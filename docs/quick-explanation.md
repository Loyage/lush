# 快捷解释

本文说明如何在 Lush 项目页面中解释所选文字、选择调用 API、调整 Prompt 和回看历史。实现与安全边界见[工程契约](engineering/quick-explanation.md)。

## 配置

1. 在侧栏进入「快捷解释」。默认编辑设备共享配置；打开项目后可切到「本项目覆盖」，清除覆盖后继承设备默认。历史与调用始终归当前项目，无项目时只能配置。见[设备设置](device-settings.md)。
2. 选择已有「模型来源」中的 API Key 连接与物理模型 ID。支持 OpenAI 兼容 API、DeepSeek、OpenRouter 和 Z.AI；不支持 Codex OAuth 套餐或 Kimi Coding 专用协议。
3. 按需编辑 Prompt，或恢复内置默认。默认用简洁中文说明含义、原因与影响，并指出不确定性。自定义 Prompt 不覆盖固定的只读安全约束。
4. 保存。保存不调用模型，不改变开发 Worker 的来源，也不影响已经发起的解释。

没有可选来源时先去「模型来源」添加连接和密钥。已有凭证或本地配置就绪不代表联网验证成功；实际调用仍可能遇到上游拒绝、网络错误或超时。

## 使用

在项目内任意页面选中 1–8192 字的可选文字，右键点紫色「解释」。文档、消息、结果和全屏执行详情使用同一入口。输入控件与菜单自身不作为选区来源；没有选区时不会自动把整块内容送模型，超长选区会明确提示缩短。

解释在旁侧面板展示，保留原页面位置。它只发送选区与页面位置，不读取关联文件、步骤或其他项目内容，不执行命令、不创建 Worker 或分支。调用会消耗所选 API 的 token，关闭面板仅停止界面读取，不取消后台请求。

解释结果不是执行事实。资料不足或模型错误时应以原记录为准；选中文字可能含敏感内容，点击前确认允许发送到所选端点。

## 追问

解释结束后，面板下方会出现追问输入框。输入 1–8192 字的问题发送，模型会在原选区和原解释的基础上回答，并带上这条解释之前的所有追问；问答按顺序保留，可随时回看。

追问固定沿用原解释发起时的来源、模型与 Prompt 快照，不会因为设置变化而中途换模型；来源被禁用或凭证变化时明确提示，不会静默改用其它来源。每次只处理一条在途追问，完成前输入框禁用；追问与原解释共用最多 4 次并发。历史问答超出上下文上限时，最早的追问会被丢弃并在该轮标明，不会假装完整。旧式没有来源快照的解释不能追问，界面会提示重新发起解释。删除一条解释会连同它的追问一起删除。

## 历史和运行限制

「快捷解释」页面集中保存项目历史，按新到旧分页，点击记录可看完整选区、结果、当时的来源和 Prompt，以及这条解释的追问轮次。每条历史可在确认后永久删除；正在进行的解释或追问要等调用结束后才能删除，删除只移除记录，不取消调用。更改或删除来源不改写历史快照；旧式记录没有来源/Prompt 证据时显示未知。

最多同时 4 次调用，每次最多 120 秒；失败也保留历史。停止项目会中断请求，重启不会自动重放未知副作用。未选项目的全局工作台不能发起解释，先打开项目。

更新此功能涉及 daemon 和 Host 两端。合入并部署后由用户在安全空闲时更新/重启项目后台及 Host；不要只刷新旧 Host 页面。当前运行进程是否匹配代码可用 `bun run doctor` 与 `bun run lush host status` 分别检查。
