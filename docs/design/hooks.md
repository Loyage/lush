# Worker Hooks：把预约变成可理解的自动动作

本章指导 Worker 自动动作及项目 daemon 内置自动动作的设计。用户决定 #197：受控动作、独立项目自动化页面与 Worker 挂载区、首个满足创建条件的安全边界发射，并分阶段实施。实现契约见[Hooks 工程接缝](../engineering/hooks.md)。

W162／决定 #402 将自动选择和未来新指令结束流程默认值提升为设备唯一策略；开启自动选择处理已有问题，child 流程、实际挂载与项目 Shell 授权不变。以[用户工作台](user-workspace.md)和[工程契约](../engineering/user-workspace.md)为准，优先于下文历史项目默认／daemon 开关范围。

## 用户目标

用户可以在 Worker 允许的生命周期节点提前安排动作，清楚知道挂在哪里、什么时候执行、是否会启动 Agent，以及执行成败。预约不是另一套调度系统，而是一次性 Hook 的产品包装；自动合并则是持续 Hook。

## 原则

- **明确挂载作用域。** Worker 规则挂在 Worker 上，项目模板只复用配置、不代表已经挂载。用户明确授权的 daemon 自动选择是项目内置 Hook，不继承为 Worker 规则、不共享到 Host 或设备，不引入新业务实体。
- **触发、授权、执行分开。** 节点出现只产生候选；条件匹配后仍须经过原有权限、冻结、Git 和生命周期准入。Hook 不能绕过安全门。
- **一轮返回不等于工作完成。** Agent 正常返回可能在等子 Worker、用户或消息。自动合并的实际触发点必须是交付安全点，显示为“Agent 完成工作后”。
- **整体解冻不等于某项合并结束。** 最后一项冻结原因释放才是解冻；预约发射还须重新核验父身份、分支和创建门。
- **挂载不等于创建。** 预约时只保存指令、引用、父身份与运行设置；不建 Input、Worker、分支或 worktree，不固定代码基线，不启动 Agent。创建时按父分支当时的提交 fork。
- **配置与结果分开。** 自动合并是否启用不能靠本轮请求推断；一次性 Worker Hook 成功后自动删除挂载，执行结果留在审计记录，不堆积已失效授权。失败、未知与错过／不适用的挂载保留诊断，持续 Hook 与模板不删除。
- **默认值不是隐式路由。** 用户未指定运行覆盖时，预约挂载时冻结有效默认配置；显式配置保留完整运行设置。实际调用的认证与模型仍由启动时合法配置核验，不复制凭证。Pi 默认模式只能固定所选模式，执行机器 Pi 自身的默认模型、资源与认证仍在实际启动时决定，不能冒充已冻结的 Lush 运行覆盖。
- **故障可见，未知不重放。** 已确认未执行的等待项可恢复；动作已开始但副作用未知时保留现场和诊断，不能把 daemon 重启当作自动重试授权。

## 放在哪里

独立项目级「自动化」页面（保留 `#hooks` 地址，小标题「快捷指令和 Hook」）分开管理快捷指令授权、Hook 与可复用模板。Hook 名称、作用范围、授权状态和结果使用统一卡片，不将预置规则突出称为「示例」。结束后默认流程与 Worker 详情使用相同环节按钮视觉，但保留项目默认显式保存的语义；高亮不冒充执行完成。模板数量增加时可检索，模板与实际挂载分开管理。可用节点、动作与通用流程介绍放在[帮助文档](../hooks.md)，卡片仅保留帮助链接与操作所需状态、参数及必要风险提示。模板保存不启动 Agent，也不自动安装到全项目。

Worker 详情的 Hooks 区默认只保留一行最高自动环节按钮，点击即保存，归档授权仍确认清理范围。高亮表示已保存授权，不能冒充执行结果。通用节点与自动链介绍集中在帮助文档，不在每个 Worker 重复展开。按需展开「管理」后，按节点查看自动合并、预约发射和用户规则的名称、启用状态、一次性/持续、等待与锁定原因、参数和执行记录；未启用的内置自动合并仍可找到，失败和未知结果不因折叠而隐藏。

Worker 图不复制完整编辑器，只提供同源简要入口。即时“合并”保留在交付区，不与持续开关混为一谈。按钮有统一 Hook 标识与帮助；安排或可能唤醒 Agent 的动作另用 `agent-call` 紫色样式和 `agentHelp()`，禁用项使用外层帮助宿主。

## 合并—验收的串行级别

W169／用户决定 #418 统一验收与归档：验收表示不再有异议，同时安全回收 worktree/ref，保留完整运行历史。当前 Worker 只有“关闭／自动到合并／自动到验收”三个最高环节；两个内置 Hook 按交付就绪、已集成推进，验收内部包含资源回收。旧 archive 等价 accept，用户明确授权旧自动验收直接采用新语义。具体契约见[统一验收](../engineering/worker-acceptance.md)与[自动链工程接缝](../engineering/completion-hooks.md)。

自动验收代替用户确认，不额外调用 Agent 评审，也不证明业务质量；运行退出、消息、待决、后代、共享使用者与 Git 交付安全门仍需通过。脏工作区阻止验收，回收失败保留事实和诊断，不冒充完成。child 流程仍整体只读，默认自动合并、直接父 Agent 检查后验收并回收资源，不继承父级授权。

请求冻结或执行中不能改变当前链；允许的显式提高只补办后续步骤。自动到合并只提醒待验收；自动到验收成功静默，无独立待归档环节。失败、未知结果与待决仍可见，重启不重放未知副作用。

## 项目新指令的结束后默认流程

用户决定 #325（W137）：项目自动化页面提供启用开关与默认最高环节（合并／验收，验收含归档回收），默认关闭，关闭仍保留环节。仅当前项目、仅之后实际创建的新指令 Worker 复制这份授权；不改已有 Worker，不从父继承，不改变 child 锁定自动合并及父 Agent 验收，不适用于管理 Worker。预约发射按真正创建时的流程默认，不混淆运行配置挂载快照。验收授权先说明资源回收范围，自动验收仍不是质量保证；旧归档值兼容等价验收。

## 项目 daemon 自动选择

用户决定 #267：休息期间可显式开启自动答复，避免 Worker 一直等待人工选择。规则固定为单选第一项，多选和文字问答交由 Agent 自行判断；开启同时处理已有待答问题。默认关闭，按项目持久保存，独立于 Worker 自动链。自动答复必须标明 Lush 来源，不伪装成用户决定；页面启用前说明可能恢复多个调用、产生费用。既有「已知」仍只标已读，不能借此启用自动答复。工程边界见[daemon 自动选择](../engineering/daemon-auto-select.md)。

## 可自定义的范围

普通自动动作组合目录中的请求合并、创建独立 Worker、纯告知、追加消息；定时节点另允许显式重试失败与继续暂停。用户决定 #319 追加**显式授权的通用命令动作**；W151 / 决定 #363 将它拆为快捷指令与 Hook：用户先在当前项目快捷指令目录注册 Shell 命令并授权具体版本，Hook 只引用该版本并负责触发，不再保存可执行 Shell 正文、不代管命令业务语义。快捷指令也可由用户选择 Worker 手动执行，仍过同一安全门。命令以项目 daemon 用户权限在所挂载 Worker 工作目录运行，不是沙箱；必须就地说明风险，不能伪装成 Agent 调用或只读模板。按节点限制可用动作，合并和创建各自使用指定安全点；消息只能发给当前 Worker 或直接父子；首期追加消息动作只允许一次性，防止正常返回→追加消息→新调用的无限付费循环。异常结束不默认重试 Agent。

规则支持一次性/持续、启停及显式 Worker 状态/集成状态条件。模板实例挂载时复制参数，之后修改模板不悄悄修改运行中的实例。派生子 Worker 的流程 Hook 整体锁定，用户自定义规则不能借删除、停用或最高级别设置绕过；其他受控自定义规则不受此只读限制影响。

## 快捷指令与版本授权（W151 / 决定 #363）

授权目录负责“允许做什么”，Hook 负责“何时做”，手动执行负责“这次在哪里做”；不能以创建模板或触发节点出现代替 Shell 授权。编辑指令递增版本并撤权，旧 Hook 不自动升级到新正文；用户重新授权新版本并明确更新引用后才能继续。撤权、删除、版本变化必须阻止未开始执行，已开始的副作用不承诺撤回，未知结果不重放。

旧内联 Shell 配置保留定义与历史但停止直接执行；用户显式导入为未授权快捷指令、确认正文，再授权并启用引用。注册、授权和挂载是不同操作，不能隐式承接旧启用字段。工程契约见[快捷指令与 Hook](../engineering/shortcut-commands.md)。任意 Shell 仍以 daemon 用户权限运行，授权目录不是操作系统隔离，不能据此承诺命令只访问当前项目。

## 可学习的 main 推送示例（W133 / 用户决定 #319）

自动化页面提供默认关闭的持续示例：先默认注册并授权内置 `git push` 快捷指令，再以版本引用挂载到 main Worker 成功收到一次合并节点，用户可直接启用 Hook。W151 追加要求将已有未修改默认示例一次性导入并授权；不恢复用户已撤权、编辑或删除的指令，不重放旧触发。该例外仅限内置默认指令，其他 Shell 仍须显式授权。用户在项目页面或 main 的 Hooks 管理区启停的是同一挂载，不是两个独立授权。示例可编辑、复制，复制默认停用；模板与已挂载实例继续分离，改变模板不影响正在运行的规则。首次初始化提供示例，删除后不得反复安装。

remote、跟踪分支、网络与认证都由用户自己的 Git 配置或命令决定；Hook 不猜 remote、不改 Git 配置、不调用 Agent 帮推送。执行失败不撤销已经成功的合并，未知副作用不自动重放。命令开始前仍复核生命周期与分支门禁；连续合并要保留各次触发，不能用“正在执行”静默吞掉后一项。任意命令可访问该系统用户的资源，去除调用凭证不是操作系统隔离。

## 定时提交（用户决定 #266）

定时节点把用户授权的动作在指定时间**提交**给当前项目 runtime，不保证 Agent 在该时刻开始：并发槽、安全冻结和实际调用收尾仍可能延迟。用户可选显式时区的一次性日期或每日固定时刻；不把服务器本地时区当用户的半夜。

项目 daemon 停止期间错过的未提交时刻跳过，不启动后台、不唤醒设备、不在恢复时补跑。已经持久提交但尚未开始的项仍等待首个安全点；重复日期不堆积多份待执行项。未知副作用始终不重放。每日消息／创建是明确的时间周期授权，不能顺带放开生命周期返回→追加消息的递归循环。

到点可创建 Worker、追加消息、重试失败 Worker 或继续已暂停 Worker。后两者是用户预先授权的受控动作，保留原工作区与历史，不恢复取消、验收或归档。失败 Worker 仅可窄挂定时自重试，不借此开放其他终态行为。额度更新时间只是一份时间安排，不是额度已恢复的证据；来源由用户显式配置，不隐式换付费账号。界面分别说明下一提交时间、已提交待执行、实际结果与不适用／错过。

## 时间信号与管理型 Agent（用户决定 #270）

时间信号供用户把“额度更新时间已到”等项目内事件绑定到管理指令；同一信号可绑定多项指令。时间到点不等于额度已恢复，不隐式查询或切换账号。默认开发输入框仍提交开发任务；管理指令的创建与绑定只放自动化页面，保存时不调用 Agent。

管理型 Worker 不是开发 Worker：使用独立提示词、专属非 Git 工作目录和仅管理工具，首版仅可查询当前项目、开始／继续 paused 的开发 Worker和重试 failed 的开发 Worker。用户可授权管理当前项目任意目标，但不能借此取消、合并、验收、归档、删除或修改账号／服务；普通开发 Agent 权限不变。

信号绑定可一次性／持续，默认一次性；持续复用同一管理 Worker而不并发调用。忙时只留一项，未开始项可恢复，未知副作用不重放。管理 Agent 提交的受阻操作由 runtime 持久等待安全点，不要求模型循环等待或反复付费重发。权限、时间、持久化与模块分区见[时间信号与管理契约](../engineering/hook-signals-management.md)。

## 订阅刷新时间快捷填入

时间信号编辑器可只读模型来源的结构化缓存，让用户明确选择账号与额度窗口，复制 `reset_at` 到一次性日期，保留用户时区。选择不是账号绑定，不持续跟踪后续刷新，不从窗口时长猜下一次日期。缓存观测时间可见，未知／失败／过期不得冒充可用；失败不回退旧成功值。填入不联网、不调用 Agent、不改变来源或管理权限；用户仍可手工修改时间。

## 公平与失败保护

预约发射在首个可创建安全点执行，不等待整个合并队列清空。每项合并释放父执行位后，已挂载的创建规则有机会按挂载顺序准入；创建之后在独立分支运行，不占父合并执行位。仍有其它冻结、同步或未知落地现场时继续等待。

多标签编辑用版本校验；请求失败保留正文、引用和运行设置。创建成功但客户端未收到响应不能重复创建；已挂载规则不得被同一个触发重复执行。用户取消等待项仅撤销未来动作，不删除已经创建的 Worker 或撤回已发出的合并请求。

## 反例

- 把每次 Agent 返回都当成工作完成，提前合并半成品。
- 将交付请求、Hook 启用状态、Worker 验收压成一个状态。
- main 冻结时静默改投其它父 Worker，或先创建空壳 Worker 并宣称尚未创建。
- 挂载时保存了模型，发射却悄悄使用后来改变的项目默认。
- 以“Hook”为理由自动重试未知副作用或获得永久 Agent token。
- 模板保存时启动 Agent，或隐藏延迟调用的 token 代价。

## 验收问题

用户能否看清触发点和等待条件？两种内置 Hook 是否采用同一挂载读面？冻结期间能否编辑完整预约参数并在安全点创建一次？失败、重复提交、重启及未知副作用是否保住现场？模板是否与挂载分离？消息与调用是否有明确权限和递归边界？旧合并协议和历史记录是否保持原义？
