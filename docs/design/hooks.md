# Worker Hooks：把预约变成可理解的自动动作

本章指导 Worker 自动动作及项目 daemon 内置自动动作的设计。用户决定 #197：受控动作、独立项目自动化页面与 Worker 挂载区、首个满足创建条件的安全边界发射，并分阶段实施。实现契约见[Hooks 工程接缝](../engineering/hooks.md)。

自动选择保持设备唯一策略；Worker 自动化未来挂载及启用默认为项目独立设置。child 的锁定合并／验收流程与实际挂载作用域不变，旧设备完工默认不自动导入或参与新建。

## 用户目标

用户可以在 Worker 允许的生命周期节点提前安排动作，清楚知道挂在哪里、什么时候执行、是否会启动 Agent，以及执行成败。预约不是另一套调度系统，而是一次性 Hook 的产品包装；自动合并则是持续 Hook。

W228／D534：快捷指令也是可理解、可复用的项目能力目录。每条定义说明作用、适用场景及可选标签、示例与风险，支持 Shell 和启动独立 Worker 的提示词；通过列表搜索选择单条，再查看详情或编辑，不铺开所有正文。W241／D566 将指令管理改为独立列表→详情／编辑子页面，删除所有用户手动运行入口，指令仅供 Hook 自动执行；旧配置与历史不迁移。SQLite 保存权威定义、版本与安全历史，Skill 风格 Markdown 只作导出表达。本轮不自动注入项目 Skill 或扩大开发 Agent 权限；未来让 Agent 发现或调用仍须独立明确权限与可信边界。

## 原则

- **先注册，再挂载。** 项目自动化目录是能力边界，不只是导航。所有内置、自定义及受保护系统功能先登记；UI、CLI 和管家都不得直接给 Worker 安装未登记的规则。注册保存定义，不等于挂载或执行；系统功能登记不解除原有只读限制，设备级自动选择仍归全局。
- **授权固定版本。** 挂载明确引用注册功能及版本，包括实际执行的命令定义；修改功能或快捷指令产生新版本，已有挂载仅经显式升级采用，不能静默改变已授权行为。挂载仍决定目标与工作目录，不形成跨项目授权。
- **能力说明不是执行授权。** 描述与适用场景帮助用户或未来 Agent 判断用途，不能因描述推荐就执行。提示词创建成功只表示已提交独立 Worker，不代表 Agent 已完成目标；一次性创建熔断不能因切换指令类型而解除。
- **触发、授权、执行分开。** 节点出现只产生候选；条件匹配后仍须经过原有权限、冻结、Git 和生命周期准入。Hook 不能绕过安全门。
- **统一语言，不混淆来源与目标。** 来源规则决定是否交付及自动验收，目标处理策略决定如何处理已授权交付。两者使用同一受控工具目录、持久操作与结果展示；普通串行和归并是目标工具的策略，不是两条争抢成果的 Hook。开启目标归并不提高来源授权；归并关闭仍处理合法交付。
- **提交不等于完成。** 请求工具提交成功不证明代码合入或验收。异步结果必须关联本轮真实操作与精确收据；无代码结果交付也不应说成产生了合并提交。复杂归并算法与资源回收仍由 runtime 引擎保障，不开放任意 DAG 或 Shell 编排来代替安全协议。
- **一轮返回不等于工作完成。** Agent 正常返回可能在等子 Worker、用户或消息。自动合并的实际触发点必须是交付安全点，显示为“Agent 完成工作后”。
- **中断完成不等于请求接受，也不等于整个项目可重启。** Worker 信号确认本次调用真实退出；项目批次信号另复核所有在途操作。W216／D508 首版仅放行维护期间纯告知，不借节点突破 Agent／命令准入；全局只汇总固定来源范围，重启仍需用户显式触发并重核安全门，见[中断完成契约](../engineering/interrupt-completion.md)。
- **整体解冻不等于某项合并结束。** 最后一项冻结原因释放才是解冻；预约发射还须重新核验父身份、分支和创建门。
- **挂载不等于创建。** 预约时只保存指令、引用、父身份与运行设置；不建 Input、Worker、分支或 worktree，不固定代码基线，不启动 Agent。创建时按父分支当时的提交 fork。
- **配置与结果分开。** 自动合并是否启用不能靠本轮请求推断；一次性 Worker Hook 成功后自动删除挂载，执行结果留在审计记录，不堆积已失效授权。失败、未知与错过／不适用的挂载保留诊断，持续 Hook 与模板不删除。
- **默认值不是隐式路由。** 用户未指定运行覆盖时，预约挂载时冻结有效默认配置；显式配置保留完整运行设置。实际调用的认证与模型仍由启动时合法配置核验，不复制凭证。Pi 默认模式只能固定所选模式，执行机器 Pi 自身的默认模型、资源与认证仍在实际启动时决定，不能冒充已冻结的 Lush 运行覆盖。
- **故障可见，未知不重放。** 已确认未执行的等待项可恢复；动作已开始但副作用未知时保留现场和诊断，不能把 daemon 重启当作自动重试授权。

## 放在哪里

W315／D676：项目自动化 `#hooks` 改为统一注册目录，不再仅显示三个写死的内置入口。默认展示名称、用途、内置／自定义／系统来源及真实挂载数量；具体目标、定义与执行记录在单项详情按需查看，异常不得隐藏。复用显式搜索与单项导航，窄屏单列；注册不默认挂到 main。常用流程是找功能、选 Worker、确认挂载；内置完工、推送与告知保留原设置和权限，系统保护不因目录统一而解除。条件发射仍在输入／草稿管理，关联受保护系统功能；[一次性整合](merge-convergence.md)仍是显式操作，不变成持续策略。设备功能不搬进项目目录。

已有未登记规则通过显式升级补登记并关联原挂载，保留身份、启停、执行历史及去重证据，不重放或扩大授权。读取不执行迁移。D678：管家先完成注册，再独立请求具体 Worker、触发点和固定版本挂载；两步默认自动执行，用户可逐项收紧为确认或禁用。不保留注册并直接挂载的捷径。

W263／D611 删除的独立 Valet 设置和指令与 Hook 工具页面不恢复；D676 将功能注册与版本管理归入项目自动化目录，而不是恢复独立工具页或允许 Worker 内联定义规则。已有 API／CLI 也必须遵守注册硬边界，配置、授权与历史按显式升级兼容。日常开发 Worker 与持久 Valet 分别进入「工作列表」「管家列表」，共用有界列表、真实编号和类型化详情，不另建一套 Agent 信息或执行阅读器，也不以绑定快照冒充完整工作历史。W279／D635：Valet 详情可停止、停用授权及经精确预检确认删除，不提供开发动作；当前项目仅一个管家事项占运行位，排队、待用户确认、在途操作与退出收尾均须收口后才释放，未触发的信号绑定不占位。W302／D659、D660 将「CLI 接口」归入全局工作台：命令学习不依赖项目，管家权限统一为同设备用户所有项目共享，而非项目覆盖。保持先搜索学习、进入单条用途与风险后就地配置，不默认平铺权限；静态说明可缓存，实时权限按需读取，审核上限不能冒充实际授权。W316／D677：未配置时内建默认即生效，全部已支持的受控接口默认开放，旧设备和项目限制退出授权、原数据仅留历史；用户可逐项收紧，也可让管家申请修改，权限修改始终须真实用户审核。无需项目在线，浏览和保存不调用 Agent；未开始请求重检、已开始不强停、失败不重放，精确边界见[全局管家权限](../engineering/hook-signals-management.md#设备全局管家权限)。Worker 侧显示注册来源和固定版本，只能选择已登记版本挂载、升级及按原权限启停；定义变更回到注册目录，不接受内联改写。注册不启动 Agent、不安装，修改不改变已有实例；未知结果不重放。新指令默认按项目独立保存，具体 Worker 授权在对应详情管理，默认设置不能冒充实际执行事实。完整操作入口见[帮助文档](../hooks.md#页面入口)。

W270／D622：Worker 详情的「自动化」只显示实际挂载功能的标题及开关／最高环节，简介在标题悬停帮助中展示，原理与高级参数按需展开。挂载就是显示，未挂载不展示该功能；项目默认挂载范围只影响未来实际创建，不回写或隐藏已有授权。旧显示原则仅 API 兼容，不再决定展示。完工与告知初始全适用范围挂载，child 完工始终挂载且锁定；push 只按 main 的真实 identity hook 存在判定；持续归并挂载及未来默认已退休，历史配置和在途仍按[实施契约](../engineering/merge-convergence-implementation.md)保留。同 Worker 刷新保留显式展开和在途编辑，失败、未知及必要诊断不得因折叠隐藏。最高环节点击保存，验收仍确认资源回收；高亮不是执行成功。实际挂载、规则和执行记录在 Worker 中按需查看，归并边界见[归并实施契约](../engineering/merge-convergence-implementation.md)。

工作树的更多操作菜单直接展开同源「自动链」最高环节按钮，方便就地调整处理策略；不复制完整 Hook 编辑器，child、冻结及版本门禁与详情保持一致。旧服务缺少自动链读面时保留只读 Hooks 详情入口，main/owner 的自定义挂载仍从详情管理。普通单项“合并”及一次性“整合全部”复用工作树与 Worker 详情，不新增交付管理页，也不与持续开关混为一谈。按钮有统一 Hook 标识与帮助；安排或可能唤醒 Agent 的动作另用 `agent-call` 紫色样式和 `agentHelp()`，禁用项使用外层帮助宿主。

## 合并—验收的串行级别

W169／用户决定 #418 统一验收与归档：验收表示不再有异议，同时安全回收 worktree/ref，保留完整运行历史。当前 Worker 只有“关闭／自动到合并／自动到验收”三个最高环节；两个内置 Hook 按交付就绪、已集成推进，验收内部包含资源回收。旧 archive 等价 accept，用户明确授权旧自动验收直接采用新语义。具体契约见[统一验收](../engineering/worker-acceptance.md)与[自动链工程接缝](../engineering/completion-hooks.md)。

自动验收代替用户确认，不额外调用 Agent 评审，也不证明业务质量；运行退出、消息、待决、后代、共享使用者与 Git 交付安全门仍需通过。脏工作区阻止验收，回收失败保留事实和诊断，不冒充完成。child 流程仍整体只读，默认自动合并、直接父 Agent 检查成果但不因本轮交付就验收回收；保留现场供同一个 child 接收追加需求，尽量随父级安全批量验收，不连带验收独立指令，不继承父级授权。

请求冻结或执行中不能改变当前链；允许的显式提高只补办后续步骤。自动到合并只提醒待验收；自动到验收成功静默，无独立待归档环节。失败、未知结果与待决仍可见，重启不重放未知副作用。

## 新指令的结束后默认流程

项目默认只复制给之后实际创建的新用户指令，不改已有 Worker、不从父继承、不改变 child 锁定合并及父 Agent 检查责任，不适用于管理 Worker。关闭保留所选环节，验收包含归档回收，旧归档值等价验收，自动验收不是质量保证。待验收告知是独立开关：新用户指令默认开启、child 默认关闭，均可在自己的自动化修改；真实进入待验收才告知，不把一轮静息冒充交付，关闭不隐藏异常或删除历史。字段、去重与旧设备兼容见[项目默认接口](../reference/rpc/hooks.md#新指令默认流程)。

## 项目 daemon 自动选择

用户决定 #267：休息期间可显式开启自动答复，避免 Worker 一直等待人工选择。规则固定为单选第一项，多选和文字问答交由 Agent 自行判断；开启同时处理已有待答问题。默认关闭，按项目持久保存，独立于 Worker 自动链。自动答复必须标明 Lush 来源，不伪装成用户决定；页面启用前说明可能恢复多个调用、产生费用。既有「已知」仍只标已读，不能借此启用自动答复。工程边界见[daemon 自动选择](../engineering/daemon-auto-select.md)。

## 可自定义的范围

普通自动动作组合目录中的请求合并、创建独立 Worker、纯告知、追加消息；定时节点另允许显式重试失败与继续暂停。通用命令动作拆为快捷指令与 Hook：用户在当前项目目录注册 Shell 命令，Hook 只引用指令身份并负责触发，不保存可执行 Shell 正文、不代管命令业务语义。不再提供 Web、CLI 或公开 API 的手动执行入口。命令以项目 daemon 用户权限在所挂载 Worker 工作目录运行，不是沙箱；必须就地说明风险，不能伪装成 Agent 调用或只读模板。按节点限制可用动作，合并和创建各自使用指定安全点；消息只能发给当前 Worker 或直接父子；首期追加消息动作只允许一次性，防止正常返回→追加消息→新调用的无限付费循环。异常结束不默认重试 Agent。

规则支持一次性/持续、启停及显式 Worker 状态/集成状态条件。完整规则先登记，实例引用明确版本；注册时校验定义、挂载时再校验目标适用性和权限，不从脱敏摘要重建私有运行覆盖。派生子 Worker 的流程 Hook 整体锁定，用户自定义规则不能借删除、停用或最高级别设置绕过；其他受控自定义规则仍按原权限管理。

## 快捷指令与固定授权版本

快捷指令负责“做什么”，Hook 负责“何时做”，挂载 Worker 决定执行目录或父身份；旧 default_worker_id 仅兼容历史配置，不参与路由。D676 将原有跟随最新定义改为固定授权版本：登记功能冻结所引用的快捷指令版本，已有挂载继续使用已授权定义，修改命令后须登记新功能版本并显式升级挂载。编辑不自动停用或改变旧授权；删除和类型失配仍须遵守执行安全门，异步编辑不能混用正文与收据。已开始的副作用不承诺撤回，未知结果不重放。功能注册、挂载授权、自动链级别、管家逐项权限和精确确认机制与执行准入彼此独立。

旧内联 Shell 保留定义与历史但停止直接执行；用户显式导入、检查正文，再启用引用。旧未授权／已撤权字段不再阻塞，已停用规则不自动启用，历史不改写也不重放。工程契约见[快捷指令与 Hook](../engineering/shortcut-commands.md)。任意 Shell 仍以 daemon 用户权限运行，指令目录不是操作系统隔离，不能据此承诺命令只访问当前项目。

## 可学习的 main 推送示例（W133 / 用户决定 #319）

自动化页面提供默认关闭的持续示例：注册内置 `git push` 快捷指令，以身份引用挂载到 main Worker 成功收到一次合并节点，用户可直接启用 Hook。旧配置导入及停用保留以[快捷指令兼容契约](../engineering/shortcut-commands.md#旧配置与-git-push)为准。用户在项目页面或 main 的自动化管理区启停的是同一挂载，不是两个独立开关。示例的定义修改产生新注册版本，复制默认停用；版本与实例分离，已有挂载不随定义或命令更新而改变。首次初始化提供示例，删除后不得反复安装。

remote、跟踪分支、网络与认证都由用户自己的 Git 配置或命令决定；Hook 不猜 remote、不改 Git 配置、不调用 Agent 帮推送。执行失败不撤销已经成功的合并，未知副作用不自动重放。命令开始前仍复核生命周期与分支门禁；连续合并要保留各次触发，不能用“正在执行”静默吞掉后一项。任意命令可访问该系统用户的资源，去除调用凭证不是操作系统隔离。

## 定时提交（用户决定 #266）

定时节点把用户授权的动作在指定时间**提交**给当前项目 runtime，不保证 Agent 在该时刻开始：依赖、安全冻结和实际调用收尾仍可能延迟。用户可选显式时区的一次性日期或每日固定时刻；不把服务器本地时区当用户的半夜。

项目 daemon 停止期间错过的未提交时刻跳过，不启动后台、不唤醒设备、不在恢复时补跑。已经持久提交但尚未开始的项仍等待首个安全点；重复日期不堆积多份待执行项。未知副作用始终不重放。每日消息／创建是明确的时间周期授权，不能顺带放开生命周期返回→追加消息的递归循环。

到点可创建 Worker、追加消息、重试失败 Worker 或继续已暂停 Worker。后两者是用户预先授权的受控动作，保留原工作区与历史，不恢复取消、验收或归档。失败 Worker 仅可窄挂定时自重试，不借此开放其他终态行为。额度更新时间只是一份时间安排，不是额度已恢复的证据；来源由用户显式配置，不隐式换付费账号。界面分别说明下一提交时间、已提交待执行、实际结果与不适用／错过。

## 时间信号与管理型 Agent（用户决定 #270）

时间信号供用户把“额度更新时间已到”等项目内事件绑定到管理指令；同一信号可绑定多项指令。时间到点不等于额度已恢复，不隐式查询或切换账号。默认输入仍用于开发；保存信号绑定的 API／CLI 操作不调用 Agent，主输入框显式「管理 Lush」提交则即时新建 Valet。W263／D611 已删除独立 Valet 设置的 Web 入口，已有信号绑定不迁移或重放。

Valet 不是开发 Worker：独立提示词、专属非 Git 目录、可信管理工具，不加载开发上下文、不提供任意文件／Shell 工具。Worker 自身与直接父子事务、项目管理分别由 `lushw`、`lush` 表达；Valet 通过独立审核的项目管理能力受控跨开发树协作，不继承 invocation 绑定的 `context.*`，也不获得自己的开发分支或改变普通 Worker 的亲缘约束。已支持的受控接口默认开放（写操作 automatic），用户可逐项收紧；管家修改权限始终须真实用户精确确认，不把静态能力目录当作当前权限。设备操作须显式请求，私有凭证、交互认证与跨项目能力不开放，普通开发 Agent 权限不变。

信号绑定可一次性／持续，默认一次性；持续复用同一 Valet 而不并发调用。W323／D686：正常结束且安全收口后，用户可向同一 Valet 追加，明确授权新一轮，不重放旧操作；项目执行位忙碌时拒绝追加并保留输入，失败、取消与未知副作用不能借追加恢复。自身决策问题的答复只恢复同一 occurrence，不创建新的管理输入。忙时只留一项，未开始项可恢复，未知副作用不重放。管理 Agent 提交的受阻操作由 runtime 持久等待安全点，不要求模型循环等待或反复付费重发。权限、时间与持久化见[时间信号与管理契约](../engineering/hook-signals-management.md)。

## 订阅刷新时间快捷填入

历史时间信号编辑器的辅助实现可只读模型来源的结构化缓存（Web 设置入口已退休），让用户明确选择账号与额度窗口，复制 `reset_at` 到一次性日期，保留用户时区。选择不是账号绑定，不持续跟踪后续刷新，不从窗口时长猜下一次日期。缓存观测时间可见，未知／失败／过期不得冒充可用；失败不回退旧成功值。填入不联网、不调用 Agent、不改变来源或管理权限；用户仍可手工修改时间。

## 条件信号与安全准入

条件发射是一次性输入授权，不等同于历史父解冻创建 Hook。多个条件必须全部满足：工作安全收尾、本轮成果真正进入 main、目标树彻底静息。条件附属 Hook 只提供可核验信号，不能直接冒充创建或绕过父 runtime 准入；暂停、失败、待开始和未交付开发都阻塞静息，已合并且无新工作的待验收状态不阻塞。无代码安全成果不要求虚构合并，取消但脏的工作仍阻塞。

静息等待只约束开始时；独占开发从准入到本轮安全交付暂缓其它开发，仍允许自身后代、管理、查询及交付，不提高合并／验收授权。撤销尚未执行的意图与释放独占是不同动作，未知 dispatch 不能重放。实现边界见[条件发射](../engineering/conditional-emission.md)。

## 公平与失败保护

历史解冻创建预约在首个可创建安全点执行，不等待整个合并队列清空。每项合并释放父执行位后，已挂载的创建规则有机会按挂载顺序准入；创建之后在独立分支运行，不占父合并执行位。仍有其它冻结、同步或未知落地现场时继续等待。

多标签编辑用版本校验；请求失败保留正文、引用和运行设置。创建成功但客户端未收到响应不能重复创建；已挂载规则不得被同一个触发重复执行。用户取消等待项仅撤销未来动作，不删除已经创建的 Worker 或撤回已发出的合并请求。

## 反例

- 把每次 Agent 返回都当成工作完成，提前合并半成品。
- 将交付请求、Hook 启用状态、Worker 验收压成一个状态。
- main 冻结时静默改投其它父 Worker，或先创建空壳 Worker 并宣称尚未创建。
- 挂载时保存了模型，发射却悄悄使用后来改变的项目默认。
- 以“Hook”为理由自动重试未知副作用或获得永久 Agent token。
- 注册时直接挂载或启动 Agent，或隐藏延迟调用的 token 代价。
- 列表补上了自定义功能，但 CLI／管家仍能绕过注册安装内联规则。
- 挂载标着旧版本，执行时却使用最新命令正文。

## 验收问题

用户能否看清触发点和等待条件？两种内置 Hook 是否采用同一挂载读面？冻结期间能否编辑完整预约参数并在安全点创建一次？失败、重复提交、重启及未知副作用是否保住现场？是否先登记再挂载，且所有入口使用同一硬边界？定义更新是否保留已授权版本？旧规则显式升级是否保住身份与去重历史？消息与调用是否有明确权限和递归边界？旧合并协议和历史记录是否保持原义？
