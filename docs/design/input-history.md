# 历史输入与缓冲区：先记下想法，再决定执行

本章面向修改输入框、暂存与历史检索的开发者。用户需要低成本保留突发想法、反复修改，并在合适的时候明确交给 Lush；也需要找回曾经发出的原始命令。操作说明见[历史输入与暂存](../input-history.md)，接口边界见[核心 API 收敛](../engineering/core-api.md)。

## 原则

- **记录不等于执行。** 暂存只保存项目内的正文、引用和父 Worker 身份，不创建工作区，不调用 Agent，不自动排队。关闭浏览器后仍能找回。
- **一条想法，一次明确授权。** 发射是可靠挂载需求，不保证立即创建 Worker。条件信号、父空闲与安全准入由 runtime 承担；新建实际成功后才产生原始 Input，追加只产生消息收据，不伪造 O 编号。完整契约见[条件发射](../engineering/conditional-emission.md)。
- **先接住人的需求，内部等待由软件承担。** Worker 冻结只限制 Agent 执行与 Git 写入，不应让用户无法表达。合法追加输入须先可靠保存，由 Worker 代管，等待当前交付收口、整体解冻与 Agent 实际退出后再投递；不能把「已保存」说成「Agent 已收到」。暂存输入不得打断固定提交的修复，也不得被自动验收、归档吞掉。
- **原话与后续工作分开。** 暂存可编辑、删除；已发出的原始输入不可改写。后续要求走 Worker 追加消息，而不是把历史原话改成新的指令。
- **历史必须可查全。** 搜索针对项目全部原始 Input 与未提交 Draft，不局限于首页快照或已经加载的记录。旧流程输入、关联 Worker 已不存在的输入也不能无声消失；缺失状态明确显示未知。例外只有用户经资源预检和最终确认执行 Worker 彻底删除：无剩余使用者的原始输入与已发射草稿随所选子树一起清除，不把此操作冒充普通归档或历史筛选。
- **归属不能随浏览器或 Git 切换漂移。** 暂存时保存父 Worker 身份，发射前可显式更改；代码基线在实际创建时固定，不在保存想法时锁死。父Worker失效要保留草稿、提示重选，不能静默改投 main 或当前分支。

## 状态是事实的投影

暂存不属于 Worker 生命周期。发射先展示等待条件、排队准入、正在投递或未知结果等持久事实；实际创建后才展示对应 Worker 的状态。多个条件全部满足且核验本轮成果，不能把调用返回或旧轮合并误作完成。静息等待和持续独占分开表达，独占不是自动合并授权。

合并是另一个维度。「待验收」和「已合并」可以同时成立；「已完成」也可能没有代码合并。不要把Worker生命周期、代码交付与归档压成一个互斥状态，不为历史页再维护一套可漂移的Worker状态机。追加开发后不得把上一轮落地当成本轮已经交付。

历史页按新建、追加与管理三种模式检索：原始 Input、未发射或已挂载的草稿、经统一输入流程发出的追加草稿、来源可证明的普通用户追加消息，以及主输入框提交的管理需求。消息与管理需求保留独立来源，不伪装成 Input、不造 O 编号；定时信号和系统消息不收录，旧缺少可信用户来源的消息保留在 Worker 中，不猜测归类。已发送追加草稿与其真实 Message 去重。默认三种模式全选、全部状态，非文本筛选即时生效但不应用未提交关键词；同页详情往返保留筛选。追加与管理详情只读并可定位来源，Worker 状态不证明单条消息已处理。

Worker 对话中的人类输入显示当前软件登录账号名（不是模型来源账号），头像使用用户名第一个 Unicode 字符簇；Worker 使用机器人头像，其他系统／Worker 通信独立归类，不冒充用户。账号通过根 Host 会话接口一次读取，只留当前 UI 会话内存；加载失败或无账号明确显示名称未知，不编造姓名，不将名称作为 HTML。原始目标只按真实 `task.input_id` 显示 `O<Input ID>`，没有 Input 不造 O；明确用户追加输入只显示持久 `append_number`（如 `A198-1`），来自 Event 或关联 Message。历史缺号回退消息 `#ID`（消息身份也缺失则标未知），不从事件、分页或显示顺序猜编号。渐进读取名称／编号不得覆盖别页或丢失当前阅读状态。

## 交互与失败保护

- 新建与追加统一为桌面 Enter 暂存、Ctrl/⌘+Enter 与 Ctrl/⌘+Shift+Enter 直接发射；手机／触屏回车及 Shift+Enter 换行，可见按钮承担提交。所有页面默认新建，默认父 main；明确点击「追加输入」才切换到指定目标，隐藏父选择但保留暂存能力。条件发射只在草稿详情提供低调入口，用户主动点击后才展开具体设置；默认收起，收起保留设置，已有条件须以简要标注和发射按钮文案明确提示。引用附件不支持时拒绝而保留原文，不静默丢附件。
- 输入区域统一项目色，只在文本框用实线／加号表示新建、虚线／回复箭头表示追加；追加目标编号和标题常驻。冻结允许可靠挂载并说明延迟，不合法目标禁用并说明，不能悄悄改投。切换保留文字，导航退出追加模式；挂载确认后且没有在途新编辑才恢复默认模式。输入法确认不触发提交。
- 挂载 ACK 后留在原页，不打开不存在的 Worker。草稿详情保持只读收据，直到实际获得 Input 才可转到原文；独占意愿必须仍可定位与释放。追加不转成 O 原文。保存比较正文、去向、引用、条件和独占；运行参数仅发射时写入。Ctrl/⌘+S、撤销／重做与按钮共用编辑、版本和单飞保护，普通 Enter 换行，不新增草稿发射快捷键。
- 「管理 Lush」是显式的第三种去向，不是开发 Agent 换一个 Prompt。其独立提示词、无 Git 目录和可信工具不加载开发上下文；普通 Agent 不扩权。管理权限分级，危险请求精确预检后由真实用户确认；能力发现不能冒充执行授权。详见[管理型 Worker](../engineering/hook-signals-management.md)。
- 提供可见按钮，不要求触屏用户记快捷键。W189／决定 #451：主输入与历史暂存正文均有撤销／重做，和组合快捷键共用本页文字编辑历史；主输入按钮默认隐藏、展开「更多」后显示，新建与追加模式都可展开，收起不影响快捷键或编辑历史；不回退引用、设置、服务器版本或已发送请求。主输入成功清空才释放本条历史，失败与在途编辑保留。手机聚焦按实际可视区域避让软键盘，优先确保正文可见，按钮允许换行，不挤成小字。凡现在或稍后会调用 Agent 的授权动作都必须带调用代价标识；参见[按钮帮助](ui-guidance.md)。
- 重复按键与点击不能创建多个 Worker。多标签编辑必须检测版本冲突，不以最后一次请求偷偷覆盖前一次保存。
- 请求失败保留原文与引用；请求在途时新打的字、新加的引用不得被旧请求的成功回调清掉。服务端确认成功后立即释放本条输入，不把列表刷新或详情加载算进提交锁；后台更新失败不冒充提交失败，也不诱导重复提交。
- 页面切换、搜索或刷新使旧响应失效，旧响应不能把用户拉回旧页面。后台读状态不覆盖正在编辑的想法。
- 引用是附件，不混入正文；保存快照与来源定位沿用[上下文引用](references.md)边界。

## 取舍与反例

完整历史可能很长，因此服务端检索、分页返回预览，按需读取原文。分页不是删历史，预览截断必须可见。显式刷新优先于频繁重画编辑中的页面。

以下做法违背目标：

- 暂存时就创建 Worker 或调用 Agent，把想法库变成不受控队列。
- 恢复旧批量 planner 提交流程，让一条暂存绕过当前指令协议。
- 只搜索首页最近Worker，却宣称能查全部历史。
- 父 Worker 不可用时自动选择另一个归属。
- 把「已合并」当作验收完成，或悄悄改写已发出的原话。

## 验收问题

1. 用户能否只记录、不执行，并在重开页面后继续编辑？
2. 全部原始输入是否可搜索，未知关联是否如实保留？
3. 暂存发射是否沿用当前指令的安全、身份与 Git 准入？
4. 重复提交、多标签冲突、失败与迟到响应是否保住用户文字？
5. 状态是否允许「已合并但待验收」，且不误报后续轮次？
