# 历史输入与缓冲区：先记下想法，再决定执行

本章面向修改输入框、暂存与历史检索的开发者。用户需要低成本保留突发想法、反复修改，并在合适的时候明确交给 Lush；也需要找回曾经发出的原始命令。操作说明见[历史输入与暂存](../input-history.md)，接口边界见[核心 API 收敛](../engineering/core-api.md)。

## 原则

- **记录不等于执行。** 暂存只保存项目内的正文、引用和父 Worker 身份，不创建工作区，不调用 Agent，不自动排队。关闭浏览器后仍能找回。
- **一条想法，一次明确发射。** 发射当前选定的暂存条目，不顺便提交其它想法；提交成功后通过同一个原始 Input 追溯 Worker，不在历史里重复显示已提交草稿。
- **先接住人的需求，内部等待由软件承担。** Worker 冻结只限制 Agent 执行与 Git 写入，不应让用户无法表达。合法追加输入须先可靠保存，由 Worker 代管，等待当前交付收口、整体解冻与 Agent 实际退出后再投递；不能把「已保存」说成「Agent 已收到」。暂存输入不得打断固定提交的修复，也不得被自动验收、归档吞掉。
- **原话与后续工作分开。** 暂存可编辑、删除；已发出的原始输入不可改写。后续要求走 Worker 追加消息，而不是把历史原话改成新的指令。
- **历史必须可查全。** 搜索针对项目全部原始 Input 与未提交 Draft，不局限于首页快照或已经加载的记录。旧流程输入、关联 Worker 已不存在的输入也不能无声消失；缺失状态明确显示未知。例外只有用户经资源预检和最终确认执行 Worker 彻底删除：无剩余使用者的原始输入与已发射草稿随所选子树一起清除，不把此操作冒充普通归档或历史筛选。
- **归属不能随浏览器或 Git 切换漂移。** 暂存时保存父 Worker 身份，发射前可显式更改；代码基线在发射时固定，不在保存想法时锁死。父Worker失效要保留草稿、提示重选，不能静默改投 main 或当前分支。

## 状态是事实的投影

暂存不属于Worker生命周期。发射后，输入展示对应 Worker 的当前状态：已创建/待开始、排队中、执行中、等待中、待处理、暂停、待验收、完成、失败或取消。

合并是另一个维度。「待验收」和「已合并」可以同时成立；「已完成」也可能没有代码合并。不要把Worker生命周期、代码交付与归档压成一个互斥状态，不为历史页再维护一套可漂移的Worker状态机。追加开发后不得把上一轮落地当成本轮已经交付。

历史页只收录创建Worker的原始输入和未发射的想法，不把 Worker 内的每条追加消息伪装成独立Worker；追加过程仍在 Worker 中查看。

## 交互与失败保护

- 新 Worker 输入模式：Enter 暂存、Shift+Enter 换行；Ctrl/⌘+Enter 与 Ctrl/⌘+Shift+Enter 保留创建与立即执行的差别。所有页面（包括 Worker 详情）默认新建独立 Worker，默认父为 main，显式父选择不随页面变化。只有点击详情「向该 Worker 追加输入」才进入追加模式：Enter 追加给指定 Worker、Shift+Enter 换行，隐藏暂存；影子文字明确目标及回车行为；项目配色继续表征所属项目，两种输入模式用形态而非不同颜色区分：整个输入区域统一染上项目色，不再为表单或目标条加外框；只在输入框本身用扎实的实线边框与加号表示默认新建，用虚线边框与回复箭头表示临时追加，聚焦时仍保留对应线型，不叠加第二圈描边；追加目标编号和标题常驻加粗独立成行，浅色／深色与窄屏均可辨认；冻结时仍可追加并说明延迟投递，终态等不可追加时禁用并说明，不静默改投。提供「回到新建 Worker」按钮；空白且无引用时按 Esc 也返回默认模式，切换保留文字与引用，页面导航退出追加模式。追加被服务端确认保存后自动返回新建，不等待 Agent 实际处理；失败或请求期间编辑过正文／引用、显式切换过目标时保留当前输入去向，不让迟到确认改变未发送内容的目标。中文输入法确认候选不能误触暂存或发送。
- 发射后留在当前页面，不自动打开新 Worker 或预约父 Worker；仅创建成功而待开始时，通过纯告知提供主动查看入口，不替用户开始调用。
- 提供可见按钮，不要求触屏用户记快捷键。只有真正启动 Agent 的动作才带调用代价标识；参见[按钮帮助](ui-guidance.md)。
- 重复按键与点击不能创建多个 Worker。多标签编辑必须检测版本冲突，不以最后一次请求偷偷覆盖前一次保存。
- 请求失败保留原文与引用；请求在途时新打的字、新加的引用不得被旧请求的成功回调清掉。服务端确认成功后立即释放本条输入，不把列表刷新或详情加载算进提交锁；后台更新失败不冒充提交失败，也不诱导重复提交。
- 页面切换、搜索或刷新使旧响应失效，旧响应不能把用户拉回旧页面。后台读状态不覆盖正在编辑的想法。
- 引用是附件，不混入正文；保存快照与来源定位沿用[上下文引用](references.md)边界。

## 取舍与反例

完整历史可能很长，因此服务端检索、分页返回预览，按需读取原文。分页不是删历史，预览截断必须可见。显式刷新优先于频繁重画编辑中的页面。

以下做法违背目标：

- 暂存时就创建 Worker 或调用 Agent，把想法库变成不受控队列。
- 恢复旧批量 planner 提交流程，让一条暂存绕过当前指令协议。
- 只搜索首页最近Worker，却宣称能查全部历史。
- 父 Worker 不可用时自动选择另一个归属。
- 把「已合并」当作验收完成，或悄悄改写已发出的原话。

## 验收问题

1. 用户能否只记录、不执行，并在重开页面后继续编辑？
2. 全部原始输入是否可搜索，未知关联是否如实保留？
3. 暂存发射是否沿用当前指令的安全、身份与 Git 准入？
4. 重复提交、多标签冲突、失败与迟到响应是否保住用户文字？
5. 状态是否允许「已合并但待验收」，且不误报后续轮次？
