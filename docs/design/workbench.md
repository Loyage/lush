# 工作台与开发环境

本章指导纯 Web 工作台与 Host 的边界。工程接口见[工作台接入契约](../engineering/workbench.md)。

## 用户目标

打开 Lush 即进入工作台，不需要先选择项目。项目管理、界面设置和帮助在无项目或离线时仍可用。每个项目使用独立浏览器标签，不覆盖已有输入；关闭页面不停止后台开发。

## 原则

- 保留薄 Host 与每项目独立 lushd。Host 只负责登记、鉴权、路由和转发，不持有 Worker 事实、不做跨项目调度。
- 每次项目请求带固定 `/p/<project-id>/` 身份，不存在服务端全局可变的“当前项目”。
- 项目目录、Git、Agent、凭证与 `.lush/` 留在运行后台的机器，不复制到浏览器或其它服务器。
- Lush 仅提供 Web UI，不提供桌面壳、SSH 连接管理、远端安装或跨 Host 代理。
- 远程开发由用户在服务器运行 Lush，再自行配置 SSH 端口转发、IP/端口或域名；Lush 不读取 SSH 配置、不持有隧道。
- Host 允许 HTTP，但明文密码、会话和项目内容存在被窃取或篡改的风险，应明确警告而不是阻拦。推荐 HTTPS 或用户自建 SSH 隧道；认证和同源保护不能代替传输加密。

## 操作所有权

关闭视图只关闭视图，移除项目记录只删除入口。停止项目后台必须是独立明确操作，检查活动调用与 Git 工作，不强杀、不取消 Worker 冒充安全停止。停止 Host 不等于停止 daemon；列表和旧页轮询不能偷偷启动已停止后台。

## 验收

空项目和离线状态下主体是否可用？另开项目是否保留原标签输入？路径是否明确属于 Host 所在机器？请求与偏好是否按项目隔离？关闭、移除与停止的后果是否如实说明？HTTP 风险是否明确而不妨碍用户选择？
