# 工作台与开发环境

本章记录已确认的启动与远程开发方向，指导 Web、Electron 和 Host 的改造。工程边界见[工作台接入契约](../engineering/workbench.md)。设计目标不代表所有平台已经验收。

## 用户目标与已确认选择

打开 Lush 即进入软件主体，而不是先理解本地、SSH、Host、daemon 后才获得界面。项目开发、项目入口和环境连接在主体管理；没有项目、连接失败时仍能访问项目管理、设置与帮助。

- 每个项目默认独立窗口，Web 对应独立标签页，不覆盖已有窗口的输入。
- Web 发起的 SSH 由 Web 服务所在机器、该服务用户执行，不是访问者电脑。
- 关闭窗口或断开 SSH 不停止后台开发。停止项目后台必须是独立、明确且安全准入的操作。

## 原则

- 工作台先于项目启动。没有项目是正常空态，不是阻塞应用的错误或强制弹窗。
- 环境是项目实际所在的机器/用户上下文；SSH 和 HTTPS 是接入方式，不是业务项目类型。
- 每次请求带固定环境与项目身份，不存在服务器全局可变的“当前项目”。不同环境相同路径、相同项目 ID 不得共享偏好或错误地串写。
- 保留薄 Host 与每项目独立 lushd。Host 管理登记、鉴权、连接与后台入口，不持有 Worker 事实、不做跨项目调度。
- 项目数据、Git、Agent 和模型凭证留在目标环境；不迁移 `.lush/`，不把本地认证复制到远端。
- 客户端可信界面与远端执行能力逐步解耦；禁止为了合并界面而赋予远端网页本机 SSH IPC。
- 登录边界仍然存在。“直接进入主体”不意味着绕过公网认证。

## 操作与所有权

关闭项目视图只关闭视图；断开环境只停止自有隧道；移除记录只删除入口。停止项目后台需检查活动调用与 Git 工作，不强杀、不取消 Worker 冒充安全停止。停止 Host 不等于停止 daemon；只有 HTTPS 的通道被停止后不能自行恢复，必须有独立管理通道。

Web 的 SSH 能力相当于服务用户的远程执行权限。公网入口必须由部署者显式限定允许使用的 SSH 别名，不因登录可用就开放任意远端。预检、安装确认必须绑定会话、目标及一次性计划；取消/过期不能复用授权。不得关闭主机校验、记录私钥或转发浏览器凭证到远端。

## 取舍与反例

保留项目 daemon 是为了长任务、故障隔离与断线续跑；不能为了少一个进程把全部项目合并为全局调度器。统一体验不等于浏览器拥有桌面的权限；Windows 本地执行后端是独立范围。

不接受：首屏连接方式大表单、未选项目使主体 inert、断线关闭整个软件、将服务器目录称为访问者本机、列表轮询偷偷启动项目、断开隧道同时停止 Worker、通过一个含糊开关混淆连接与服务。

## 验收问题

- 空项目和离线状态下主体、项目管理、界面设置、帮助是否可用？
- 打开另一个项目是否保留原窗口和未发送输入？
- SSH 执行位置、项目路径归属和后台状态是否明确？
- 项目/API/偏好身份是否同时包含环境与项目？
- 安装授权、浏览器认证、SSH 隧道是否按身份隔离？
- 断开、关闭、移除、停止是否具有不同且如实说明的后果？
