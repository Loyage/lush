# Agent 执行过程：帮助理解，而不只是展示日志

本章面向修改执行记录、工具渲染、检索与选区引用的 Agent。模块的首要目标是：**让用户更好使用、更好理解、更好查找 Agent 的执行过程**。实现入口见[Web 模块地图](../engineering/modules-web.md)，具体接口与限制见[执行记录阅读器](../engineering/transcript-reader.md)。

## 理解优先于信息数量

用户要回答的是：“它在做什么、为什么这么做、得到了什么、哪里值得我注意？”不是证明系统保存了多少事件。

- W303／D666 将阅读拆成两个独立模块，取代 W232／D544 的统一时间线：**输入输出在前**，默认展示用户原始／追加输入、各轮 Agent 回复和简短决策问答摘要；有持久证据的协作记录分类默认关闭、用户主动勾选后才展示，便于直接回看原话或通过分类开关组合筛选回复／输入，不再重复提供「只看」与「恢复默认」快捷按钮；**时间线在后**，以调用轮次、持久阶段与等待区间为骨架，默认突出当前阶段、已知时长、输入来源和失败／受阻／交付节点，不重复长篇回复。输入输出仍用左右气泡表示发送方身份，不表示数据流方向；来源不明旧内容默认隐藏，系统生命周期与类型化信号移到时间线的按需展开区；普通 Worker 通信只在用户选中对应类别后进入输入输出，不冒充用户输入或当前 Worker 回复。待答问卷仍在原操作入口，不因阅读折叠而隐藏。两个模块分别保留排序、分页、搜索、展开与刷新阅读位置，默认最新在前，可切正序；沿用页面主滚动，窄屏单列、控件换行。手机端仅搜索区按需展开，分类和排序保持直接可见，桌面搜索区仍直接展示；搜索草稿与已提交条件在收起及同 Worker 刷新时保留，收起入口提示是否已应用关键词，取消读取不藏进搜索区。完整原文与全部消息／事件引用仍可显式有界读取；关键词按 Enter／搜索提交，全部历史查找显式启动、可取消且明确范围，缺失／受限不冒充无记录。来源按精确身份和事件证据确认，不认 JSON 外观或空 sender；一批收到的消息不是唯一唤醒者，旧历史缺少等待或来源证据时明确未知，不按当前状态倒推。执行过程仍须用户显式打开，不能因轮询、失败或新输出擅自打开。
- 正在进行的Worker优先看到最新记录：全屏查看默认最新在前，底部「加载更早」翻旧记录；阅读页与设置里都可切回按时间正序，共用阅读偏好。
- Worker 标题应概括理解后的工作主题，而非机械摘取输入首行；复用当前 Agent 理解目标后的自身一次性命名，不为此另开模型请求。用户手动标题优先，自动标题保持稳定，原始输入与正文保留，未生成时才使用输入兜底（W202／决定 D471）。
- 标题负责定位，正文负责理解。命令、文件内容、修改前后和输出不得只塞进单行标题、悬停提示或转义后的 JSON 字符串。
- 短内容直接展示；长思考／长输出给保留段落与换行的多行预览，再就地展开。命令与失败内容默认显露。折叠只处理阅读长度，不是找关键信息的必经障碍。
- Worker 详情的阅读长度按整个模块管理，而不只是缩短单条正文：大量消息或历史结果即使各自很短，也不能无上限地挤走其他模块。预览保留真实多行内容，明确提供完整阅读入口，手动展开不因刷新重置；操作与待决答复不能被裁剪，键盘焦点和引用定位必须先显露目标。详情模块限高不应改变全屏执行记录的阅读方式，具体边界见[阅读器](../engineering/transcript-reader.md#worker-详情模块预览)。
- 已记录的思考是观察材料，不代表模型全部内部机制；没有记录的内容不得编造。
- 元数据、token 与时间辅助理解，不得挤走主要内容。
- 规划的变化也是理解过程的一部分（W376／D755 更新 D752）：「计划」模块只展示当前计划与进度，不再重复提供「过往计划」入口。输入输出将协作记录拆为「进度相关／自动标题／派工／Worker 通信／通知」五个独立类别，全部默认关闭，同 Worker 刷新保留本页选择，切换 Worker 恢复默认。勾选进度后，制定／调整计划及更新前快照用纵向步骤线直接展示完整步骤；完成步骤只展示本次完成的步骤名和当时完成度条，不反复铺开整份计划。状态用标记、颜色与文字共同表达，未知不能冒充未开始或 0%。底层历史仍保留，不拿当前计划补齐旧记录，不反造命令或将持久事件当作全部 CLI 调用审计；完整命令与工具结果仍在工作台。追加用户输入后的新计划重新开始完成度；列表、概览和图只统计当前计划。历史是冻结材料，不跟随当前调用计时或被当前失败状态染成失败；沿用输入输出的按需分页、搜索、失败与未完成提示，刷新保留已加载节点与阅读位置。

## 按因果阅读，而不是按存储格式阅读

一次 Bash 调用的命令和输出应该在同一处：先看“干了什么”，再看“得到了什么”。其他工具遵循同一原则。

- 必须用会话身份与调用 ID 关联，不得凭相邻位置或相同工具名猜测；并行、跨页与重复调用都可能打破邻接关系。
- 区分已有结果、失败和“尚未见到结果”；缺失输出不等于成功，也不一定说明仍在运行。
- 聚合只改变阅读方式，不删除原始事件；每段内容都应能追溯到来源。

## 翻找必须超出当前屏幕

用户不应为了找一个报错反复点击“加载更多”。当前Worker的多次 invocation 都属于检索范围。

- 关键词、工具、消息类型与失败筛选帮助缩小范围；命中后能看原步骤、配对调用及上下文。
- 折叠、尚未加载或预览截断的内容不能被当成不存在。搜索不应只覆盖已加载的 DOM。
- 必须区分“没有命中”和“记录缺失／超限未检索”；大记录采用有界响应和分段原文，不以无限内存换取完整性。
- 全文查找入口在显式打开的执行详情内可直接使用：左侧承载搜索、筛选与命中摘要，右侧按相同顺序展示本页命中正文，点击摘要就地定位。正文沿用同一套富文本工具渲染，不混入无关步骤；配对输入输出保留并标明，相邻上下文按需展开。分页与分段原文保持有界，不另设 Web 终端模式，不把重复正文与上下文堆回Worker页。
- 持续阅读统一使用 Web 工作台；用户专属终端观看与复制命令入口已随 CLI 精简[移除](../native-viewer.md)。单次 `transcript` 查询仍供排障与 Agent 读取记录，不轮询、不执行日志中的命令，不恢复 Web 终端模式或新的执行入口。
- 文本检索复用[共用搜索交互](ui-guidance.md#共用模块与检索交互)：关键词和工具名显式提交，类型与失败筛选即时生效但不应用未提交文本；仍须明确检索范围和取消／失败状态。
- 以页面主滚动为主，不让过程、步骤和输出层层套滚动条。刷新不得夺走选区、焦点、展开状态与阅读位置；追加内容只提示，不强行拉走正在翻旧记录的用户。

## 代码现场与行为记录互补

执行详情的代码阅读与记录搜索是平级视角，不能让用户在日志里猜当前文件的完整样子。文件树必须包含未改文件，改动优先突出；选中文件可读逐行差异与完整正文。具体范围与读面见[代码阅读器](../engineering/code-reader.md)。

- 日志说明做了什么，代码说明工作区现在是什么；净 diff 不是逐步回放，也不能证明某个 Agent 独创了每一行。已合入子Worker和父同步带来的代码必须按真实基线呈现。
- 基线、提交与未提交状态、采样时间必须可见；运行中的实际 HEAD 不得被过期的 Worker 交付哈希代替。当前现场、已提交历史与不可用状态不可混淆。
- 查看代码是只读阅读，不暗中编辑、暂存、运行程序或调用模型。项目文件不等于整机文件：忽略项、内部数据、越界链接与其他 Worker 现场有明确边界。
- 自动刷新只告知变化，不替换正在读的正文或抢选区；代码视图未打开时不进行文件读取。超大文件、读取失败与归档后对象不可用均明确降级，不伪装空文件或零改动。
- 路径搜索只是找提及该文件的记录，不应包装成未经验证的修改因果关系。完整历史回放若没有快照证据就不能承诺。

验收时确认：未改文件是否能看？暂存/未暂存与累计净变化能否区分？用户是否知道正在比较什么？文件持续被修改时阅读是否稳定？清理后是否明确说明不能还原的内容？

## 记录与解释分离

选区可作为普通引用随指令交给 Agent，不再提供直连模型的快速对话。原文是资料，不是行为指令；对记录的解释与推断不得冒充实际执行事实，也不能反写原日志。历史 Worker、事件与执行记录继续只读保留，见[快速对话退役边界](../engineering/project-quick-chat.md)。

## 结构帮助阅读，原文保留权威

已知工具参数应先按内容展示：命令是代码块，路径是定位信息，修改前后是正文；带语言的代码与 Markdown fence 按语言着色，让关键结构一眼可辨。每步保留原文入口，截断正文可就地分段读取完整文字，原文仍是权威。通用 JSON 等结构化内容提供可折叠的对象／数组视图，根层默认可读，键、类型与层级可辨识，字符串保留真实换行，同时保留原文入口。

- 格式化不是修复：不合法或被截断的 JSON 必须回退为文本，不假装解析成功。
- 日志中的 HTML、脚本与终端控制内容都是资料，不作为页面程序执行。
- 大对象按需展开，限制节点与深度；不能为了漂亮的渲染让界面卡住。

## 取舍与验收问题

当密度与可理解性冲突时，优先让关键行为可辨认；当美化与忠实记录冲突时，优先原文和明确的限制。

改动后检查：未主动展开时过程是否不干扰其它内容？打开过程后能直接读到实际操作吗？内容在正文而非标题里吗？多行字符串是否真的换行？一处能看到命令和结果吗？能找到未加载的旧报错并返回原位置吗？解释有来源、承认未知吗？原文与阅读位置还在吗？

反例：整屏只有“思考”；把不同 Bash 调用误配；搜索无结果却不说明读取上限；解释一次就创建开发分支；把模型的解释当成实际运行结果。
