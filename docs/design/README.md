# 模块设计理念

这里回答“模块为什么存在、遇到取舍应该朝哪个方向设计”，供修改模块的 Agent 和维护者按改动范围在读实现前阅读。长期职责与跨模块边界从[模块地图](../engineering/modules.md)定位，精确接口与实现细节以源码和测试为准。

## 阅读与维护

- [用户工作台](user-workspace.md)：W162／决定 #402，设备唯一设置、全局收件箱与自动化、项目独立工作页；优先于旧项目设置覆盖描述。
- [工作台与开发环境](workbench.md)：主体先于项目启动，区分环境、接入方式、项目与后台生命周期。
- [设备共享设置](device-settings.md)：同设备用户配置一次，只保留 Worker 显式运行参数；旧配置迁移显式确认，项目事实与历史隔离。
- [Agent 执行过程](agent-process.md)：让用户更好使用、更好理解、更好查找 Agent 的执行过程。
- [上下文引用与定位](references.md)：把用户当下所见（选区、语义节点）低成本带进下一条指令，并定位来源。
- [按钮帮助与 Agent 触发标识](ui-guidance.md)：让按钮含义与“会调用 Agent”的代价一眼可见。
- [Agent 配置与模型来源](agent-model-settings.md)：分离设备默认工作方式与调用资源，保留单 Worker 的明确来源选择。
- [Agent 能力模块](agent-capabilities.md)：W217／D509，必需核心与可选工作能力分离，薄 Skill 入口、按需 CLI 指南及设备全局启停。
- [账号资源连接器](account-resources.md)：区分账号、端点、现金/Key预算/套餐窗口，托管凭证且显式选择，不把查询失败当耗尽。
- [Worker Hooks](hooks.md)：统一触发节点、挂载配置、预约发射与受控自定义动作。
- [归并合并方案](merge-convergence.md)：W205／D482，固定成果并行归并、单批受检发布与独立 Worker 体验；目标自动化挂载默认关闭，新交付由Agent自主验证；实际能力与旧在途兼容见工程接缝。
- [通知与告知](notices.md)：按客户端、类别与渠道控制打扰，逐条已知但不替用户做决定。
- [历史输入与缓冲区](input-history.md)：先持久记录想法、显式发射，并准确检索原始指令与Worker状态。
- 仅为新的长期主题或重要理念变化新增／修订文档，简短写清用户目标、设计原则与关键取舍；反例和验收问题按需补充，不为模板扩写，也不记录每次选择。
- 设计理念是长期方向，不是已实现功能清单。仅关键契约与限制需要工程文档，普通实现由代码和测试表达，并链接到必要入口。
- 修改模块前必须读对应理念；当实现便利与理念冲突时，先解释冲突，不得悄悄降低目标。用户尚未表达的其他模块偏好，不应由 Agent 擅自编造。

新增主题更新本索引；仅职责边界或必读要求变化时更新模块地图或 `AGENTS.md`，不要求每次理念修订同步多处。维护分级与时机见[文档写作约定](../contributing/documentation.md#维护分级与时机)。
