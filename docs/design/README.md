# 模块设计理念

这里回答“模块为什么存在、遇到取舍应该朝哪个方向设计”，供修改模块的 Agent 和维护者在读实现前阅读。文件职责与接口仍以[模块地图](../engineering/modules.md)为准。

## 阅读与维护

- [工作台与开发环境](workbench.md)：主体先于项目启动，区分环境、接入方式、项目与后台生命周期。
- [设备共享设置](device-settings.md)：同设备用户配置一次，项目与 Worker 按需覆盖；迁移显式确认，项目事实与历史隔离。
- [Agent 执行过程](agent-process.md)：让用户更好使用、更好理解、更好查找 Agent 的执行过程。
- [上下文引用与定位](references.md)：把用户当下所见（选区、语义节点）低成本带进下一步，并就地获得只读解释。
- [按钮帮助与 Agent 触发标识](ui-guidance.md)：让按钮含义与“会调用 Agent”的代价一眼可见。
- [Agent 配置与模型来源](agent-model-settings.md)：分离工作方式和调用资源，支持项目默认与单 Worker 的明确来源选择。
- [账号资源连接器](account-resources.md)：区分账号、端点、现金/Key预算/套餐窗口，托管凭证且显式选择，不把查询失败当耗尽。
- [Worker Hooks](hooks.md)：统一触发节点、挂载配置、预约发射与受控自定义动作。
- [通知与告知](notices.md)：按客户端、类别与渠道控制打扰，逐条已知但不替用户做决定。
- [历史输入与缓冲区](input-history.md)：先持久记录想法、显式发射，并准确检索原始指令与Worker状态。
- 新增模块理念时，写清用户目标、设计原则、取舍、反例和验收问题；不要用当前控件布局代替设计目标。
- 设计理念是长期方向，不是已实现功能清单。具体能力与限制另记在工程文档，并链接到实现入口。
- 修改模块前必须读对应理念；当实现便利与理念冲突时，先解释冲突，不得悄悄降低目标。用户尚未表达的其他模块偏好，不应由 Agent 擅自编造。

新增主题后，必须同步本索引、模块地图和必要的 `AGENTS.md` 阅读指引，确保理念能被正在修改代码的 Agent 发现。
