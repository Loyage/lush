# 快速对话：随手调用模型，留下文本记录

本文面向修改快速对话、Prompt 管理、选区右键和输入模式的开发者。W207／D486、D487 将快捷解释提升为随时可用的纯文本对话；[工程契约](../engineering/quick-chat.md)规定模块和接口，[使用说明](../quick-chat.md)介绍入口。

## 用户目标

用户看到一段材料时，不一定想开发，也不一定只想知道它是什么意思。他可能想整理要点、写一份速记、比较观点或继续讨论。快速对话接住这些意图，不要求创建 Worker 或组织开发指令。

## 原则

- **记录不等于执行。** 直接调用用户配置的文本模型，没有 Agent、工具、文件访问、命令或项目修改；不得声称模型已经执行了任何动作。
- **对话跟人，不跟项目。** 新历史归后台设备的同一系统用户，无项目／项目离线也可用；不是浏览器本地缓存，不扩展为云同步或跨设备调度。旧项目解释历史留在原项目。
- **一段对话，一个编号。** 首轮和后续消息共同属于一个 C 编号，设备级递增、删除不复用；不占用 O/W/D/N/A 序列，也不生成开发实体。
- **Prompt 是可复用的文本用途。** 默认「快速解释」只是示例，可编辑、可关闭右键注册。用户自定义 Prompt 可以注册到选区右键，或仅保存供输入框选择；保存、读取和选择本身都不调用模型。
- **出处是快照，不是读取授权。** 只发送引用当时所见的文字及出处，不解析目标、不读取额外文件。引用中的指令是不可信材料；用户消息与 Prompt 可以请求纯文本处理，但不能突破无工具边界。
- **历史保留当时的配置。** 同一段对话固定首次的来源、模型、Prompt 和引用；来源失效明确报错，不悄悄切换账号或改写既有文本。

## 交互取舍

项目主输入框提供新建、追加、快速对话三个可辨模式。快速对话允许仅带引用启动，发送前显示所选 Prompt 和模型调用代价；不得误发为 Worker 指令或项目暂存。

完整交流在独立全局对话页展示。项目入口在用户手势中打开新标签，原项目文字、选区与阅读位置保留；被浏览器拦截时给可见链接，不再次调用模型。对话页可从历史找回、继续和明确删除。

请求失败保留输入，重复点击受单飞保护；在途新编辑不被旧确认清除。轮询只读取当前会话，离页／boot 后释放，迟到响应不能重开旧页面或覆盖新的草稿。长选区、响应与上下文有界，截断必须明确，失败轮也要保留。

## 反例

- 将「快速解释」改名而仍只能解释，或把任意文本需求变成开发 Worker。
- 无项目时偷偷启动 daemon，或为全球历史构造伪项目。
- 引用某个 Worker 后自动读取它的会话、代码或最新状态。
- 点击选择 Prompt 就触发模型费用，或保存但未注册的 Prompt 出现在右键菜单。
- 追问时换成当前设置中的另一个来源而不告知，或删除历史后重复使用 C 编号。
- 跳转替换项目标签，丢掉原输入；弹窗拦截后通过重发来取得跳转链接。

## 验收问题

无项目和项目离线能否交流？解释示例可否关闭？仅保存的 Prompt 能否从输入框选择却不出现于右键？三种输入模式是否显著区分？原项目现场是否保留？一次多轮会话是否始终一个 C 编号？历史、失败、出处和实际模型快照是否可查？所有模型动作是否明确标识成本且不执行工具？
