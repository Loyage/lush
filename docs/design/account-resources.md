# 账号资源：看清连接，明确代价

本章说明账号资源连接器的用户目标与安全取舍。实现字段、Provider/Runtime/Web 边界见[账号资源连接器](../engineering/agent-connections.md)；旧查询兼容边界见[额度查询与历史](../engineering/agent-usage.md)。

## 用户目标

用户要知道自己连了哪些账号、哪份余额或套餐正在被使用、观测何时更新、失败如何恢复。一个模型名不能说明实际使用的是官方套餐、付费 API，还是第三方代理，也不能标识哪个账号。

连接必须把服务商、端点、认证来源和模型范围放在一起理解。同一服务商的不同账号是不同连接；多个模型可以共享同一资源窗口。不把连接升级为整机调度实体；历史、实际消费者和运行事实仍归所选项目 daemon。设备共享连接由同一后台机器的系统用户管理，无项目 Host 只提供窄配置管理，不汇总跨项目运行事实；见[设备共享设置](device-settings.md)。

## 原则

- **结构化事实优先。** 余额、Key 预算、套餐比例各自有类型和作用域，显示单位与重置时间；不得从格式化插件文本反解析数据。
- **认证状态、观测状态、运行能力分开。** 保存了密钥不代表已验证登录；查询失败不代表余额为零；取得账户数据不代表某模型请求必然成功。429 不能一律称为套餐耗尽。
- **只读查看与联网刷新分开。** 进入连接页读本地配置与缓存；手动刷新明确告知联网。用户决定 #186 允许页面在保存 / 登录成功后自动查询该连接，必须在操作前明确说明，且保存成功与刷新失败分开表达；不把底层保存 RPC 改成隐式联网。后台采样默认关闭，启用后关页仍采样，停机留空、不补伪造历史。
- **利用已有请求而不是新增模型探测。** 支持的正常响应头可以提供被动反馈；通用 RPM/TPM 不能冒充订阅额度。被动反馈缺失并不证明资源没有限制。
- **账号身份与历史隔离。** 更新凭证、端点或查询来源不能把旧观测附到新账号；旧历史可以保留，必须标明来源/账号段与时间。所有数值只代表采样时刻，不把差额归因为 Lush 的独占消耗。
- **选择必须明确。** Pi 的 Lush／机器默认双模式以[配置契约](../engineering/agent-configuration-v2.md#profile-模式)为准，不把用户明确选择机器配置误称为认证失败回退。Worker 来源／模型窄更新保留其他完整覆盖，下次摘要不能冒充当前实际绑定；保存只影响后续 invocation，不热切换、不自动降级或换付费账号／后端。API Key 与登录归设备连接，执行后端只引用支持的认证，不能把统一保存误称为所有 Agent 都能使用。受信调用前策略默认关闭、明确 Worker 覆盖优先，失败／未知／旧余额不作为零参与付费切换；见[模型选择](../engineering/managed-model-selection.md)与[页面理念](agent-model-settings.md)。

## 凭证托管的取舍

用户选择私有文件而不是系统钥匙串：技术配置属于后台机器同一系统用户的设备根，旧项目凭证不参与活跃覆盖或来源并集，只作为显式迁移来源。目录 0700、文件 0600、原子写入，不进入仓库、不返回秘密或密钥前缀、不自动复制外部客户端认证。它支持无人值守，但不是静态加密保险箱；同一系统用户及同权限 Agent／扩展仍可能读取，不把私有权限说成 OS 沙箱。迁移与旧文件退役以[设备契约](../engineering/device-settings.md#显式迁移连接与迁移分区)为准。

秘密只从明确的录入/登录操作产生。UI 不回显、不持久保存在浏览器；请求/回调的秘密不进入事件或错误。权限无法验证的平台应拒绝托管，不静默退回不安全存储。

端点改变必须重新核对凭证授权，不能把官方密钥自动转发到新代理。外部源码按固定版本审查、保留许可；不能直接加载带 UI、自动登录或付费探测的整套插件。

OAuth refresh token 会轮换。Lush 托管的刷新必须协调，不能让多个 Worker 的临时认证目录或不同项目 daemon 各自刷新同一令牌；刷新锁归凭证实际存储根。显式迁移先备份和记录，再发布共享并退役源端，中断源认证 fail-closed，不能留下两份活跃 refresh 副本。临时运行只复制 access token；长调用中 token 过期可能失败，下一次 invocation 再由 Lush 刷新。这是安全边界，不应包装成无损持续登录。

## 出站网络与认证分开

出站代理是设备技术设置，作用于账号登录／刷新／查询及项目实际 Agent 调用，不是模型端点或项目配置覆盖。请求发生在执行环境，浏览器能联网不代表后台可用，远端 127.0.0.1 不是访问者电脑。

继承、明确直连和指定代理必须可辨认；失败不得偷偷直连或换账号。设备策略形成请求／invocation 快照，在途登录链保持同一策略，后续请求才使用新值；Lush 环境与 Worker 显式 env 的顺序见[网络契约](../engineering/outbound-network.md#请求和执行路径)。代理认证只写不回显，TLS 验证及凭证目的地授权不能降低。

## 反例

- 每个模型旁显示一个“余额”，却未说明共享账号或端点。
- 失败填零、凭证存在显示“已登录”、把 RPM 剩余量称为套餐余额。
- 为确认能否调用而悄悄发一个“便宜”的模型请求。
- 对所有百分比直接排序，假定 80% 周额度一定比 60% 月额度更充裕。
- 将重置倒计时归零直接解释为额度已恢复，或把不同币种余额加成一个总金额。
- 批量停用时不说明涉及哪些连接，或全量保存时丢失原有默认模型 / 思考深度。
- 新账号显示旧账号成功缓存，或者删除连接时删除外部凭证和全部历史。
- 用户只同意管理账号，就自动从订阅切到付费 API。

## 验收问题

用户能否辨认同服务商多账号和实际端点？现金/Key预算/订阅窗口是否分开？失败、未知、过期旧值和来源时间是否明确？密钥更新后是否正确切分历史？连接页查看是否不额外联网？后台关闭、请求取消、配置更换和 OAuth 刷新的竞态是否安全？实际消费者是否来自运行时绑定而不是模型名猜测？不支持的平台和真实登录尚未验证的路径是否如实说明？
