# 用户工作台：配置跟人，工作归项目

本文固定 W162 与用户决定 #402、#408、#411 的整体重组方向；实现接缝见[用户工作台契约](../engineering/user-workspace.md)。它优先于既有“设备默认 → 项目覆盖”以及项目级自动选择／新指令默认流程的描述。尚未完成的能力不得仅凭本设计宣称已实现。

## 用户目标

用户只配置一次自己的偏好、Agent、模型资源与快捷解释。无论当前查看哪个项目，都能知道其他项目需要自己处理的事项；全局设置不挤占项目工作页，不覆盖已有输入。

## 两种空间

- 用户工作台由 Host 提供：项目入口、全局收件箱、设备设置、全局自动化与帮助。不需要某个项目 daemon 在线。
- 项目工作页使用固定 `/p/<project-id>/` 身份：Worker、输入、代码、执行记录、项目自动化和项目事项筛选。独立标签，关闭页面不停止开发。
- W171／决定 #421：全局空间是项目空间的上级。项目侧栏只保留项目内部页面，不显示全局页面按钮或顶部全局收件箱摘要；左上角品牌图标在独立标签打开全局工作台，保留原项目现场。设备自动选择的持续授权状态提示仍保留，不混同收件箱计数。
- 打开设备页面或另一个项目保留原项目标签的输入、选区与阅读位置；读取不启动已停止后台。

## 全局后台总览（W171／决定 #421）

根 `#projects` 为「后台总览」：只涵盖此 Host 已登记且有权访问的项目，不扫描整机未登记后台。显示在线／未运行或不可达、已确认 PID、执行数和待决／合并情况；仅显式刷新，不因读取启动后台。不可达不等于证明进程已停止。

后台总览不提供“处理消息”按钮；收件箱独立存在，点击具体消息在新标签进入来源项目「待我处理」中的原记录，沿用原 Notice 的答复／已读协议。告知使用蓝色，与需要用户答复的琥珀色问答区分；导航本身不提交答案或标为已读。总览可直接发新指令，固定来源项目与 main 父 Worker，创建独立指令 Worker，不追加到某个开发 Worker。只有「创建并开始」启动 Agent，创建成功不等于已执行；离线禁止发送，须显式启动或刷新确认。发送失败保留原文，不自动重试；刷新不丢草稿，迟到 ACK 不清除新输入。总览输入只保留当前页面会话，不冒充项目持久暂存。

## 设置归属

设备指后台机器的同一系统用户，不是浏览器机器、操作系统所有用户或云账号。不引入跨设备同步、Host 调度或全局 `LUSH_HOME`。

- 设备唯一技术配置：运行参数、Agent 默认与角色配置、来源和凭证、网络、环境设置、Pi 基础配置／资源库、快捷解释 profile，以及外观、阅读、排序和提醒偏好。没有项目可选覆盖。
- #411 协调既有 W160 项目外观：深浅主题设备唯一，项目旧 `theme` 留存但不参与显示，不自动导入设备主题；项目名称、标签标题、侧栏辨识色及已有颜色保持。配色是项目身份元数据，不是技术设置覆盖，在项目工作页之外的用户工作台管理。
- Worker 的完整显式运行设置保留，包括模型、来源及高级参数；child 继承现有规则。这是任务参数，不是项目默认设置。
- #408 将“本机补充” Markdown 归设备：`agent init --local` 与后续读取都只使用设备私有目录，旧项目私有补充不再活跃，也不因缺设备文件回退。旧内容只在显式预检、冲突检查与用户确认后导入；原文件保留，仓库专属指令不能未经确认传播到所有项目。
- 项目保留 AGENTS.md、可提交 `.lush-agent/` 等代码库约定、Worker／Input／历史／Git／会话、解释结果和实际调用记录。
- 输入草稿、具体节点折叠、当前过滤、滚动与焦点是工作状态，不通过设备偏好同步。
- 外观等及时同步；技术配置在后续调用读取，当前调用快照不热切换。并发参数仍是每项目上限，不冒称整机总预算。
- 浏览器 localStorage 只缓存设备偏好，后端是权威来源；浏览器通知权限属于客户端能力，设备开关不能替其它浏览器授予权限。

## 设备自动化

用户决定 #402：保留单 Worker 运行设置；开启自动选择也处理积压问题；新指令默认结束流程统一到设备层。

- 全局自动选择只有一份持续用户授权，各项目 daemon 执行，Host 和浏览器不是运行依赖。默认关闭，不沿用旧项目开关隐式扩大授权。
- 开启处理已有及新到未答问题；不启动停止的项目，后台恢复后在原安全门内处理。单选第一项，多选／文字问题交 Agent 判断，答案明确标为 Lush 自动选择。
- 关闭撤销未来答复，不撤回已提交答案或调用。答复提交与全局开关写入使用同一设备锁排序，不允许缓存中的旧授权越过关闭。
- 新指令默认流程为设备级 enabled 与最高环节。仅实际创建的新指令复制授权，不修改已有 Worker，不改变 child 的只读流程和父 Agent 验收。
- Shell 指令授权、推送、项目目标／引用、时间信号、管理指令和实际 Hook 挂载继续属于项目／Worker；不能借“全局模板”复制仓库授权。
- 启用及可能恢复调用的操作标明 Agent 代价；全局关闭入口不是 Agent 调用。

## 全局收件箱

Notice 在来源项目保存权威记录，Host 汇总已登记且本会话有权访问的项目。不同项目的整数 Notice／Worker ID 不可混同。

- 按需人工决定、未读告知、异常和自动选择历史组织；每条带项目、显式 Worker 编号与来源。
- 回答、忽略和已读转发给来源 daemon，继续原事务、校验和唤醒路径；看过或已知不能替用户答复。
- 持久缓存只是派生视图，可断线补齐；离线显示最后确认时间，不能从缓存执行动作或声称当前状态已确认。
- 单项目不可达不阻塞其它项目；移除／失去权限的来源不再返回缓存内容。未登记目录不扫描，停止 daemon 不因聚合读取重启。
- 系统通知只提醒新到事项，多标签去重，不补发历史；关闭所有浏览器后不承诺 Web 后台推送。

## 安全迁移与反例

旧项目设置和凭证不自动删除、覆盖或导入。显式预检检查冲突、稳定来源身份、路径及私有权限，确认导入后再退役源端；配置收敛后旧文件仅作为迁移来源／历史，不继续形成活跃项目覆盖。缺少设备来源时明确提示迁移／配置，不能偷偷使用旧凭证。

反例：只隐藏作用域按钮但仍读项目覆盖；批量打开现有项目开关却称全局授权；把本地 Notice ID 当全局身份；离线标已读成功；打开收件箱启动停用后台；读取设置启动伪项目；全局归档默认改写已有 Worker。

## 验收

无项目／当前项目离线能否配置？两个项目是否读取同一设备值？Worker 显式参数是否完整保留？在 A 页能否处理 B 问题且不改 A？关闭全局自动选择是否阻止未开始的答复？新默认是否只影响未来指令？离线、迁移冲突、迟到响应、重启与多标签是否保留真实状态和用户草稿？
