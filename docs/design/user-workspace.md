# 用户工作台：配置跟人，工作归项目

本文固定 W162 与用户决定 #402、#408、#411 的整体重组方向；实现接缝见[用户工作台契约](../engineering/user-workspace.md)。技术设置不提供“设备默认 → 项目覆盖”；自动选择设备唯一，Worker 自动化默认值按项目独立管理。尚未完成的能力不得仅凭本设计宣称已实现。

## 用户目标

用户只配置一次自己的偏好、Agent 与模型资源。无论当前查看哪个项目，都能知道其他项目需要自己处理的事项；全局设置不挤占项目工作页，不覆盖已有输入。

## 两种空间

- 用户工作台由 Host 提供：项目入口、全局收件箱、设备设置、全局自动化、CLI 接口与帮助。不需要某个项目 daemon 在线。CLI 学习和设备用户所有项目共享的管家权限均在全局页；内建默认授权、旧限制退出及执行边界见[管家权限契约](../engineering/hook-signals-management.md#设备全局管家权限)。
- 项目工作页使用固定 `/p/<project-id>/` 身份：Worker、输入、代码、执行记录、项目自动化和项目事项筛选。独立标签，关闭页面不停止开发。
- W171／决定 #421：全局空间是项目空间的上级。项目侧栏只保留项目内部页面，不显示全局页面按钮或顶部全局收件箱摘要；左上角品牌图标在独立标签打开全局工作台，保留原项目现场。设备自动选择的持续授权状态提示仍保留，不混同收件箱计数。
- 打开设备页面或另一个项目保留原项目标签的输入、选区与阅读位置；读取不启动已停止后台。

## 全局卡片面板（W234／D552）

`#projects` 是用户可定制的监控面板，不用大标题、英文眉题和介绍占据信息空间。全局设置选择项目与账户，每卡选择当前关心的信息和常用导航；配置、位置和尺寸都由 Host 设备保存、跨浏览器共享。设置应贴着所设置的面板，通过弹窗编辑，不挤占或移动卡片，而不是藏在项目管理。此决定取代 W199／决定 #467、#468 的只读瀑布流、浏览器独立顺序与管理页账户选择；精确接口见[总览面板契约](../engineering/dashboard-panel.md)。

W234／D552：恢复原项目聚合卡片、统一额度窗口和项目辨识色外观，取代 D547 的五类独立卡片组织与 TailAdmin 重设计，但不恢复 W212／D505 的内容自然撑高。卡片尺寸是固定占位，加载、错误、长标题与新消息不推移邻居。列表用固定槽位加翻页，详情在弹窗，不建嵌套滚动窗；小尺寸优先保留消息等即时信息，其余已选内容仍可从详情访问。响应式显示与旧小尺寸的安全投影不自动改写共享布局。移除重复说明和无必要留白，而不是隐藏异常。

W253／D587：统一「编辑模式」取代仅编辑布局。进入后每卡设置常显，可从卡片库添加已登记来源、移出卡片、选择内容与导航，并拖动缩放；仍保留每项目一张卡和统一额度窗口，不自由拆分或重复同来源。所有修改先进入一份页面草稿，支持撤销／重做，整页「保存更改」才发布设备共享配置，「取消编辑」恢复全部已确认设置，离开前提醒未保存修改。卡片弹窗的应用不单独写入；移出总览不删除来源。拖动与缩放按响应式网格吸附、避免重叠，支持键盘替代，窄屏不覆盖共享桌面坐标。普通查看保持紧凑；项目辨识色只读复用、不初始化，内部状态指标仍沿用项目概览对应语义色。

每个项目在一张卡片中聚合所选状态、消息、Worker 和项目入口。消息按待答／告知各一行显示数量与最新内容，点击定位来源项目原记录，可在那里回答；「已知」只清除当前显示的 informational Notice，不答复或忽略问题。离线、未知总数和截断不冒称没有消息。常用导航可选择，展开入口或详情不能改变卡片占位。目录登记、后台启停、手动中断／继续、项目行重启、独立界面重启、配色编辑和新建 Worker 仍在独立 `#project-management`；W312／D674 将一键安全重启迁至总览独立「快捷操作」卡，项目管理不重复提供。维护确认、安全准入与 Agent 代价不变。旧独立卡片配置按来源只读聚合，保留来源、内容和导航选择，不因查看面板偷偷迁移文件。

所选账户统一放在一张额度窗口，内部账户以固定行分页、不独立拖动或缩放。每来源最多并排两项指标，以窗口简称、已用百分比、额度条和重置倒计时为主，观测年龄贴近账户名；现金／Key 预算仍明确类型与单位，不反复显示缺失的剩余量与解释性文字。其余指标及所选详情、来源和历史放独立弹窗；失败、未知、已删除来源不藏掉，现金、Key 预算和套餐不可混加。进入面板不查询服务商、不启动离线项目；内部单项刷新显式查询该账户，「刷新全部」查询已摆放账户并重读项目状态与消息，不扩展到未摆放账户、不调用模型。精简应移除重复解释，而不是省掉异常与来源可信度。

## 历史后台总览（W171／决定 #421）

根 `#projects` 为「后台总览」：只涵盖此 Host 已登记且有权访问的项目，不扫描整机未登记后台。显示在线／未运行或不可达、已确认 PID、执行数和待决／合并情况；仅显式刷新，不因读取启动后台。不可达不等于证明进程已停止。

后台总览不提供“处理消息”按钮；收件箱独立存在，点击具体消息在新标签进入来源项目「待我处理」中的原记录，沿用原 Notice 的答复／已读协议。告知使用蓝色，与需要用户答复的琥珀色问答区分；导航本身不提交答案或标为已读。总览可直接发新指令，固定来源项目与 main 父 Worker，创建独立指令 Worker，不追加到某个开发 Worker。只有「创建并开始」启动 Agent，创建成功不等于已执行；离线禁止发送，须显式启动或刷新确认。发送失败保留原文，不自动重试；刷新不丢草稿，迟到 ACK 不清除新输入。总览输入只保留当前页面会话，不冒充项目持久暂存。

W176／决定 #434：服务重启也集中在这里。项目后台在各自项目行独立安全重启，界面服务与「全部重启」独立放在总览最底部，与顶部「刷新项目状态」分开；全部重启指此 Host 已登记的所有在线项目后台＋当前界面服务，而非单项目或整机所有后台。确认前列清范围，逐项安全重启，任一忙碌／失败停止后续步骤并报告部分完成；不启动离线项目、不扫描未登记项目、不强杀、不自动重试。界面重启影响连接它的所有页面，需提示保存未发送输入与可能重新登录。

W183：同一底部区域提供「全部中断」「全部继续」，范围仅此 Host 已登记且当前已确认在线的项目，不包含界面服务。操作前只读重核并确认固定项目范围，沿各项目维护接口逐项提交，失败停止后续并报告部分结果；不启动离线项目、不自动重试或撤销成功请求。中断只请求安全收尾，不承诺已经可重启；继续带 Agent 代价，只解除项目维护门并按原恢复规则调度。手动模式下三个步骤仍由用户分别触发。W249／D579 将主入口浓缩为「一键安全重启」，一次确认自动完成安全中断、后台重启与本次工作恢复，最后重启界面；保留原有维护暂停，故障立即停止，三个批量入口收进手动维护展开区。W312／D674 将一键入口迁到默认显示的独立快捷操作卡，其他维护留在项目管理；该卡参与统一编辑、移动／缩放、移除／卡片库加回、撤销／重做和整页保存／取消，设备共享选择并非浏览器临时开关。D681 将按钮扩展为可自选库，默认显示一键安全重启和全局自动选择，也可勾选全部中断、全部继续、全部重启或全不选；选择和保存卡片不执行动作或修改策略。自动选择状态区分已确认开启／关闭／未知，开启需持续授权确认，关闭不调用 Agent；它与全局自动化页和 banner 共用设备策略状态。窄屏纵排，容纳不了的已选操作仍可在原地详情执行，完整进度／失败结果也放详情；缩放或信息刷新不切断流程，离页或移除停止后续步骤，已发请求不承诺撤销。浏览器只复用项目接口，不成为跨项目后台调度器，执行和恢复边界见[一键安全重启契约](../engineering/project-maintenance.md#一键安全重启w249d579)。W216／D508 增加本次固定范围的完成提醒：Worker 真实退出与项目全部安全屏障是两层事实，Host 只派生来源状态，失败／撤销／未知／不可达不冒充完成。维护期间仅纯告知放行，来源通知可留存，关闭页面不承诺后台推送，见[中断完成契约](../engineering/interrupt-completion.md)。

## 设置归属

设备指后台机器的同一系统用户，不是浏览器机器、操作系统所有用户或云账号。不引入跨设备同步、Host 调度或全局 `LUSH_HOME`。

- 设备唯一技术配置：运行参数、Agent 默认与角色配置、来源和凭证、网络、环境设置、Pi 基础配置／资源库，以及外观、阅读、排序和提醒偏好。没有项目可选覆盖。
- #411 协调既有 W160 项目外观：深浅主题设备唯一，项目旧 `theme` 留存但不参与显示，不自动导入设备主题；项目名称、标签标题、侧栏辨识色及已有颜色保持。配色是项目身份元数据，不是技术设置覆盖，在项目工作页之外的用户工作台管理。
- Worker 的完整显式运行设置保留，包括模型、来源及高级参数；child 继承现有规则。这是任务参数，不是项目默认设置。
- #408 将“本机补充” Markdown 归设备：`agent prompt init --local` 与后续读取都只使用设备私有目录，旧项目私有补充不再活跃，也不因缺设备文件回退。旧内容只在显式预检、冲突检查与用户确认后导入；原文件保留，仓库专属指令不能未经确认传播到所有项目。
- 项目保留 AGENTS.md、可提交 `.lush-agent/` 等代码库约定、Worker／Input／历史／Git／会话和项目实际调用记录。已删除的快速对话专用历史、Prompt 库和模型配置按[退役契约](../engineering/project-quick-chat.md)安全清理，不影响正常开发记录和 Agent 模型来源。
- 输入草稿、具体节点折叠、当前过滤、滚动与焦点是工作状态，不通过设备偏好同步。
- 外观等及时同步；技术配置在后续调用读取，当前调用快照不热切换。W210／D492 移除 Worker 并发槽与配额，不设置项目或设备并发上限；依赖、冻结及真实退出等安全准入保持。
- 浏览器 localStorage 只缓存设备偏好，后端是权威来源；浏览器通知权限属于客户端能力，设备开关不能替其它浏览器授予权限。

## 设备自动化

保留单 Worker 运行设置；设备自动选择开启时也处理积压问题。Worker 自动化默认与显示原则属于项目设置，不是设备技术配置覆盖。

- 全局自动选择只有一份持续用户授权，各项目 daemon 执行，Host 和浏览器不是运行依赖。默认关闭，不沿用旧项目开关隐式扩大授权。
- 开启处理已有及新到未答问题；不启动停止的项目，后台恢复后在原安全门内处理。单选第一项，多选／文字问题交 Agent 判断，答案明确标为 Lush 自动选择。
- 关闭撤销未来答复，不撤回已提交答案或调用。答复提交与全局开关写入使用同一设备锁排序，不允许缓存中的旧授权越过关闭。
- 新指令默认流程由项目自动化设置，设备旧值只保留历史，不参与新建。仅实际创建的新指令复制项目授权，不修改已有 Worker 或 child 只读流程；具体策略与展示原则见[Worker Hooks](hooks.md)，父级验收边界见[统一验收](../engineering/worker-acceptance.md)。
- 快捷指令定义、推送、项目目标／引用、时间信号、管理指令和实际 Hook 挂载继续属于项目／Worker；快捷指令不再预授权，不能借“全局模板”扩大项目自动化作用域。
- 启用及可能恢复调用的操作标明 Agent 代价；全局关闭入口不是 Agent 调用。

## 全局收件箱

Notice 在来源项目保存权威记录，Host 汇总已登记且本会话有权访问的项目。不同项目的整数 Notice／Worker ID 不可混同。

- 按需人工决定、未读告知、异常和自动选择历史组织；每条带项目、显式 Worker 编号与来源。
- 回答、忽略和已读转发给来源 daemon，继续原事务、校验和唤醒路径；看过或已知不能替用户答复。
- 持久缓存只是派生视图，可断线补齐；离线显示最后确认时间，不能从缓存执行动作或声称当前状态已确认。
- 单项目不可达不阻塞其它项目；移除／失去权限的来源不再返回缓存内容。未登记目录不扫描，停止 daemon 不因聚合读取重启。
- 系统通知只提醒新到事项，多标签去重，不补发历史；W391 的显式 Web Push 订阅允许关闭页面后提醒，设备总开关不代替客户端授权。后台提醒仍仅派生来源 Notice，不运行跨项目任务；送达与手机安装限制见[远程 Host 部署](../deployment/remote-host.md#手机-pwa-与后台提醒)。

## 安全迁移与反例

旧项目设置和凭证不自动删除、覆盖或导入。显式预检检查冲突、稳定来源身份、路径及私有权限，确认导入后再退役源端；配置收敛后旧文件仅作为迁移来源／历史，不继续形成活跃项目覆盖。缺少设备来源时明确提示迁移／配置，不能偷偷使用旧凭证。

反例：只隐藏作用域按钮但仍读项目覆盖；批量打开现有项目开关却称全局授权；把本地 Notice ID 当全局身份；离线标已读成功；打开收件箱启动停用后台；读取设置启动伪项目；全局归档默认改写已有 Worker。

## 验收

无项目／当前项目离线能否配置？两个项目是否读取同一设备值？Worker 显式参数是否完整保留？在 A 页能否处理 B 问题且不改 A？关闭全局自动选择是否阻止未开始的答复？新默认是否只影响未来指令？离线、迁移冲突、迟到响应、重启与多标签是否保留真实状态和用户草稿？
