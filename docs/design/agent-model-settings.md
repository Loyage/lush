# Agent 配置与模型和来源：把工作方式和调用资源分开

本章回答如何区分“Agent 怎样工作”和“用哪个账号／模型”。技术设置设备唯一，项目历史／消费者隔离；旧配置仅显式迁移，见[用户工作台](user-workspace.md)。Worker 可覆盖默认并冻结继承给 child，Lush／Pi 默认双模式与认证边界见[配置契约](../engineering/agent-configuration-v2.md)，不自动切账号或回退认证。

## 用户目标

用户能分别回答「Agent 如何工作」与「模型从哪个端点、哪个账号调用」，并可低成本调整设备默认和单 Worker 的下一次调用。模型名不能代表来源；同一模型在不同来源中的账号、价格、协议与额度可能不同。

用户决定 W392／D770：关系为 Worker → Agent 执行后端 → 已注册模型（唯一名称 + 来源 + 具体模型）。登记仅是设备配置索引，选择时复制来源与具体模型值，不成为运行时动态别名。来源是设备技术配置，不新增核心业务实体或 Host 跨项目调度。运行时继续通过托管端点与凭证准备调用，不因页面拆分引入新的模型代理网关。

## 两个页面

### Agent 配置

顶部显示设备默认的后端、来源与具体模型摘要，明确下一次调用生效。按「模型与运行」「工作方式」「高级与诊断」分区，保留未保存输入。Lush Pi 选择已注册模型，下方只读显示来源与具体模型；不再要求先选来源再填物理模型。不将其他账号的 CLI 模型混入托管来源模式。

- 模型与运行：后端、已注册模型、独立思考深度。设备默认、Worker、新建指令、Hook／自动化以及 Valet／管理员实际共用同一选择器。Prompt、资源、预算与环境变量按需展开。仅 Codex CLI 保留本机目录候选与名称输入，沿用自身认证；Pi 默认配置模式不受登记影响。
- 工作方式：追加 Prompt、Skills、扩展。替换内置 Prompt 为高级操作，保留风险警告及确认。
- 高级配置保留 Agent 环境变量；诊断仅按需检查执行机器上的 Pi、Codex 软件安装与版本，不读取任何 Pi/Codex 配置或认证、不调用账号接口。软件可用不代表认证有效或模型可调用，安装路径可以是全局目录，不应误称为独立 Pi 运行环境。Prompt、扩展/Skills 安装与启用仍属于工作配置，不属于软件诊断。
- 仅对确实可配置的角色提供覆盖，不新增虚构 Agent 实体或预设角色。

### 模型和来源

W392／D770：导航标题为「模型和来源」，默认打开「模型」页签；「来源」页签复用原连接、登录与额度管理。旧 `#model-sources` 保留为页面入口，`#model-source-<id>` 继续打开来源页签并定位该来源；`#model-sources-connections` 可直达来源页签。

W396／D774：保留默认模型页签，第三页签「运行诊断」默认展示近 24 小时分析总览，不要求先选择对象；顶栏提供时间、来源、具体模型与已登记项目筛选。输入／输出 token、速度、响应数与估算 USD 后，默认可见流量趋势、来源＋具体模型速度比较及额度观测变化；现在的额度缓存、明细和计算口径按需展开。覆盖缺失、离线、旧值及截断始终说明，不把未知补零。模型／来源行可带固定绑定直达，历史不用登记名称过滤。总览卡仍是原固定几何的简版，增加完整分析链接；不新增主侧栏入口。窄屏筛选／指标换行、图表单列与明细卡片，普通页面复用共享折叠模块。使用方式和精确口径见[运行诊断](../engineering/runtime-diagnostics.md)。

模型列表显示唯一名称、来源、具体模型与编辑／删除，最多 50 条。空列表引导先添加来源并登录（API 来源配置密钥），再显式注册，不自动导入旧来源模型。注册按「一个已配置来源 → 多选其本地范围／缓存目录的模型 → 逐项唯一命名 → 保存」进行，默认建议物理模型名；冲突就地显示，批量逐项报告成功与失败，再次保存只处理尚未成功项。无候选时引导补充来源范围或显式刷新目录，不偷偷联网探测。编辑默认只突出名称，来源／具体模型折入高级区域。注册和登记编辑不改来源。

用户选择即冻结当时显示的具体绑定。列表重读、迟到响应、登记改名／改绑定／删除均不替换它；只有显式重新选择才采用新版。登记与固定绑定不一致要明示。旧 profile 仍是 `connection_id + model`，没有精确匹配登记时显示「未注册当前配置」，可原样保存或去登记页显式注册，不猜选第一项。思考深度不随模型选择更改，不再提供把来源默认模型／思考深度一起填入运行表单的动作。

窄屏模型行上下排列名称、来源与物理模型，常用操作可见、无横向滚动；页签、注册和选择均支持键盘与双主题。来源页签离开时沿用登录／秘密清理，不将秘密留在浏览器。

#### 模型来源

用户决定 #249：默认总览改为等高精简摘要，保留名称、服务商 / 启停、本地凭证状态、默认模型、余额 / 套餐摘要与缓存观测时间；每行最多两项资源，套餐已用比例保留直观进度条，现金仍显金额；更多指标明确引导到详情。摘要不显示冗余的「观测成功」，但失败、未知和部分可用仍明确提示；缓存相对时间紧邻刷新按钮。完整端点、模型范围、默认思考深度、原始读数、重置倒计时和实际使用者只在用户点击该来源「详情」后查看。不设置全局「详情模式」开关；窄屏同样等高，长文本有界显示，完整文字在单来源详情保留。详情在所选来源下方向下展开，再次点击或返回可收起，不使用弹出侧栏；编辑、登录等操作面板保持按需打开。余额、剩余量和用量百分比加粗显示。来源列表先于说明、筛选、添加与批量操作显示，每行也先展示信息、后展示操作按钮，进入页面即可看到核心数据。

追加排版反馈：摘要行改为紧凑信息区与最右侧操作列；上次刷新时间在刷新按钮上方，详情按钮在刷新下方，编辑入口仅放在单来源详情。订阅窗口标题用结构化时长简写（如 `5h` / `7d`），不重复“主要 / 次要套餐窗口”，摘要同时显示距离额度重置还有多久（本地按分钟更新）；绝对日期与时间仅留在详情折叠区，到期标为待刷新，未知时长不按窗口位置猜测。原始指标名与完整口径保留在详情折叠区。窄屏仍保留右侧操作列，不把按钮另放一整行。

用户决定 #186：采用全宽多连接总览与侧边编辑面板，替代原双栏单连接阅读模式（总览的信息密度与只读详情展开方式以上述 #249 及追加反馈为准）；不把已存凭证说成联网验证可用。提供醒目的添加入口，每行直接刷新，编辑从详情进入；窄屏用可读卡片和独立面板，不要求横向拖动表格。

多连接管理支持本地搜索、筛选、勾选及批量刷新、启用 / 停用。批量配置修改先说明具体连接范围并确认，逐项反馈成败；不得因单项失败把整批说成成功，不批量覆盖模型、密钥或端点，不提供批量删除。统计只汇总连接数量与状态，不混加不同货币或套餐比例。

详情分「连接与模型」「余额与额度」「使用情况」。添加、编辑、登录按需展开。额度、历史与采样设置跟来源走，不另建额度管理页面。现金余额、Key 预算、订阅窗口分开，保留失败、未知、旧值、时间和观测出处。套餐额度用进度条突出已用比例和窗口（如 5 小时 / 7 天）与重置时间，其余口径、适用范围和原始读数收进折叠详情；现金余额仍显金额，不用无总数的进度条。

模型编辑必须就地说明填写物理模型 ID，例如 `gpt-6.1-sol`，并预览完整调用名 `openai-codex/gpt-6.1-sol`。默认模型可从已填列表选择；不能把包含斜杠的合法物理 ID（如 `vendor/chat`）机械裁掉前缀。切换来源或编辑模式不得静默覆盖未保存草稿；取消时必须清空秘密，不能把密钥保存在浏览器。

用户决定 #176 的来源范围保留：Codex 候选模型由用户在「来源」页签填写。已填写列表完整出现在注册面板，不能因自动目录不完整而隐藏；未填写且无缓存候选时就地引导去来源页编辑。配置范围不等于联网验证账号权限，具体操作与目录边界见[模型目录](../engineering/agent-model-catalog.md)。

详情仍可为每个来源保存默认模型与默认思考深度，兼容既有来源配置；它们不是自动路由。W392 的运行设置改用已注册模型，取代 #247 的主动切换来源填默认流程，不再自动填入或修改思考深度。详情还可逐来源勾选「额度刷新提醒」：开启后页面在缓存观测的重置时间到达时标出该额度，同一 `reset_at` 只提醒一次，刷新发现重置时间变化则按新时间重新计时。

进入页面只读本地配置与缓存。用户决定 #186：保存连接或完成登录后，页面自动刷新支持查询且已启用、有凭证的该连接；保存前必须说明联网行为，配置保存成功与额度刷新失败必须分别反馈，不因查询失败谎称保存失败。刷新中保留清晰的就地状态，旧值标明观测时间；换账号不得挂上旧账号数据。此联动不改变底层保存 RPC 的本地写入边界，不启动模型探测；采样默认关闭。

额度窗口的主显示回答“还有多久重置”，并以「上次刷新」相对时长说明当前数值多久前取得；绝对时间和观测口径保留在详情。倒计时与刷新提醒仅是本地时间计算，期限已到只能提示待刷新，不能假称额度已恢复或伪造新观测。刷新提醒沿用系统通知总开关，首次载入与刷新不补发关闭页面期间积压的提醒，也不新增 daemon 后台调度。计时显示不得留下离页后继续运行的采样或登录检查。删除不清除旧观测或外部客户端凭证，不能改变运行中调用的来源。

## 切换来源

设备默认从 Agent 配置页调整；用户决定 #357 将 Worker 详情合并为单一「调整运行设置」入口，常用的配置模式、后端、来源、模型与思考深度优先展示，Prompt、资源、预算与环境变量折入高级设置。面板读取已有 Worker 配置，未修改项保留，不得用角色默认悄悄覆盖它们；读取失败不回退默认表单。「加载默认参数」是明确丢弃表单改动、恢复设备／角色默认的操作。底层仍复用既有用户专属配置接口和准入规则；不为了可见入口放宽运行状态或权限。

当前调用实际来源与下一次配置应分别说明；没有后端证据时标明未知，不从模型名或默认配置猜测当前绑定。界面按用户自己命名的连接名称展示来源，不把内部连接 ID 当作可读名称；连接列表缺失或来源已删除时才回退连接 ID 并标明未知。保存不自动继续/重试，下一次 invocation 生效，当前请求不热切换。Worker 显式覆盖优先于设备／角色默认；清除覆盖的操作必须明确标注影响。

运行表单不再单独切来源；用户显式选择已注册模型才复制其来源与具体模型，不改变执行后端、思考深度或其他编辑。打开表单、读取／刷新登记以及迟到响应不替换当前绑定。登记是否存在不作为旧配置的新增保存约束，实际来源／模型仍受既有后端校验；额度失败、未知、过期缓存均不能当作零触发路由。

## 兼容与能力边界

Lush Pi 使用设备独立配置与每次私有快照，不复制机器默认 Pi 的凭证／设置／Prompt，未绑定时不自动回退；用户明确选择 Pi 默认模式才使用机器配置。独立目录不是 OS 沙箱，项目 AGENTS.md 和显式选择资源仍保留，旧历史不删除。

Pi 支持 Lush 托管连接；Codex CLI 仍沿用自身认证，托管 Codex OAuth 可供 Pi 使用不等于 Codex CLI 支持绑定。原账号观测历史保留在模型来源的只读存档，不迁移、不合并到托管连接；软件诊断不得读取或改写任何账号认证。独立配置与调用快照中只放本次需要的认证，OAuth refresh token 留在 Lush 连接管理器，避免并发调用各自刷新。

同一决定同时批准来源/模型窄更新：后台读取现有完整 Worker 覆盖（无覆盖时取有效角色默认），只更新来源和模型，原子保存并沿用状态、冻结与用户权限准入。详情仅返回无秘密的后续选择摘要，不公开 Prompt、环境变量或完整 retry_profile。

自定义端点仍仅支持现有 HTTPS OpenAI Chat Completions 适配，模型目录仅表示配置范围，不保证联网可用。来源密钥只写不回显。出站代理影响登录、查询与后续 Agent 调用，应归设备系统网络设置，而不是模型来源的端点字段。

## 验收问题

能否独立找到 Agent 配置与模型和来源？模型页签是否默认显示，注册面板是否只显示所选来源的模型？逐项保存能否重试失败项而不重复成功项？重读／登记变更是否保留固定绑定与未保存草稿，旧配置是否不被自动导入？思考深度是否始终独立？额度是否仍区分失败 / 未知 / 旧值 / 时间？看得出当前使用与下次配置的区别吗？打开页面是否不额外联网查询账号？Worker 只换来源或模型时是否保留折叠高级设置中的其他覆盖？窄屏、键盘与双主题是否能用？诊断失败是否仍可编辑配置？旧凭证与历史是否没有被迁移或删除？不支持的后端是否如实禁用并解释？

`bun run check:model-choice` 用隔离 HTTP fixture 与 Firefox 检查共用表单的已注册模型选择、冻结绑定、注册保存与 320–1440px 双主题／键盘操作；`check:device-settings` 与 `check:agent-layout` 覆盖设备路由和页面集成。不连接用户项目后台或调用真实模型。

接口与分工见[模块地图](../engineering/modules.md)，连接安全边界见[账号资源理念](account-resources.md)，运行时兼容见[共享模型选择](../engineering/managed-model-selection.md)。
