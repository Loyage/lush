# Agent 配置与模型来源：把工作方式和调用资源分开

用户决定 #157：当前项目统一管理账号/API、扩展和 Skills；Worker 默认使用 Lush 配置，也可显式选择执行机器的 Pi 默认配置。用户创建时可编辑运行设置，子 Worker 自动继承。新双模式契约见[项目 Agent 配置与双模式运行](../engineering/agent-configuration-v2.md)，其模式规则优先于下文 #154 的旧“所有 Pi 调用均托管”限制；Lush 模式仍严格隔离凭证，不自动回退或切换账号。

用户决定 #255：Agent 配置的高级诊断仅负责安装好的 Pi、Codex 软件本身，检查命令、安装路径、版本及可用性，不诊断账号或凭证、不查询余额。旧余额历史在模型来源页按需作为只读存档展示，不与正式连接曲线合并；旧查询及后台采样停用，原配置、凭证和历史记录保留不删除。

用户决定 #152：将原「Agent 管理」拆为「Agent 配置」与「模型来源」两个独立页面，并按既有后端能力实施；不在此次页面改造中新增 Codex CLI 托管绑定或自动路由。

## 用户目标

用户能分别回答「Agent 如何工作」与「模型从哪个端点、哪个账号调用」，并可低成本调整项目默认和单 Worker 的下一次调用。模型名不能代表来源；同一模型在不同来源中的账号、价格、协议与额度可能不同。

关系为：Worker → Agent 执行后端 → 模型来源（服务商、端点、账号）→ 物理模型。来源是项目技术配置，不新增 Host 全局账号池或核心业务实体。运行时继续通过托管端点与凭证准备调用，不因页面拆分引入新的模型代理网关。

## 两个页面

### Agent 配置

顶部显示项目默认的后端、来源与模型摘要，明确下一次调用生效。按「模型与运行」「工作方式」「高级与诊断」分区，保留未保存输入。先选择执行后端，再选择来源，最后选匹配模型，不将其他账号的 CLI 模型混入托管来源模式。

- 模型与运行：后端、模型来源、模型、思考深度、软预算。
- 工作方式：追加 Prompt、Skills、扩展。替换内置 Prompt 为高级操作，保留风险警告及确认。
- 高级配置保留 Agent 环境变量；诊断仅按需检查执行机器上的 Pi、Codex 软件安装与版本，不读取任何 Pi/Codex 配置或认证、不调用账号接口。软件可用不代表认证有效或模型可调用，安装路径可以是全局目录，不应误称为独立 Pi 运行环境。Prompt、扩展/Skills 安装与启用仍属于工作配置，不属于软件诊断。
- 仅对确实可配置的角色提供覆盖，不新增虚构 Agent 实体或预设角色。

### 模型来源

用户决定 #249：默认总览改为等高精简摘要，保留名称、服务商 / 启停、本地凭证状态、默认模型、余额 / 套餐摘要与缓存观测时间；每行最多两项资源，套餐已用比例保留直观进度条，现金仍显金额；更多指标明确引导到详情。摘要不显示冗余的「观测成功」，但失败、未知和部分可用仍明确提示；缓存相对时间紧邻刷新按钮。完整端点、模型范围、默认思考深度、原始读数、重置倒计时和实际使用者只在用户点击该来源「详情」后查看。不设置全局「详情模式」开关；窄屏同样等高，长文本有界显示，完整文字在单来源详情保留。详情在所选来源下方向下展开，再次点击或返回可收起，不使用弹出侧栏；编辑、登录等操作面板保持按需打开。余额、剩余量和用量百分比加粗显示。来源列表先于说明、筛选、添加与批量操作显示，每行也先展示信息、后展示操作按钮，进入页面即可看到核心数据。

追加排版反馈：摘要行改为紧凑信息区与最右侧操作列；上次刷新时间在刷新按钮上方，详情按钮在刷新下方，编辑入口仅放在单来源详情。订阅窗口标题用结构化时长简写（如 `5h` / `7d`），不重复“主要 / 次要套餐窗口”，摘要同时显示距离额度重置还有多久（本地按分钟更新）；绝对日期与时间仅留在详情折叠区，到期标为待刷新，未知时长不按窗口位置猜测。原始指标名与完整口径保留在详情折叠区。窄屏仍保留右侧操作列，不把按钮另放一整行。

用户决定 #186：采用全宽多连接总览与侧边编辑面板，替代原双栏单连接阅读模式（总览的信息密度与只读详情展开方式以上述 #249 及追加反馈为准）；不把已存凭证说成联网验证可用。提供醒目的添加入口，每行直接刷新，编辑从详情进入；窄屏用可读卡片和独立面板，不要求横向拖动表格。

多连接管理支持本地搜索、筛选、勾选及批量刷新、启用 / 停用。批量配置修改先说明具体连接范围并确认，逐项反馈成败；不得因单项失败把整批说成成功，不批量覆盖模型、密钥或端点，不提供批量删除。统计只汇总连接数量与状态，不混加不同货币或套餐比例。

详情分「连接与模型」「余额与额度」「使用情况」。添加、编辑、登录按需展开。额度、历史与采样设置跟来源走，不另建额度管理页面。现金余额、Key 预算、订阅窗口分开，保留失败、未知、旧值、时间和观测出处。套餐额度用进度条突出已用比例和窗口（如 5 小时 / 7 天）与重置时间，其余口径、适用范围和原始读数收进折叠详情；现金余额仍显金额，不用无总数的进度条。

模型编辑必须就地说明填写物理模型 ID，例如 `gpt-6.1-sol`，并预览完整调用名 `openai-codex/gpt-6.1-sol`。默认模型可从已填列表选择；不能把包含斜杠的合法物理 ID（如 `vendor/chat`）机械裁掉前缀。切换来源或编辑模式不得静默覆盖未保存草稿；取消时必须清空秘密，不能把密钥保存在浏览器。

用户决定 #176：Codex 候选模型由用户在「模型来源」页填写。已填写列表应完整出现在 Worker 运行设置里，不能因自动目录不完整而隐藏；未填写且无缓存候选时就地引导去来源页编辑。配置范围不等于联网验证账号权限，具体操作与目录边界见[模型目录](../engineering/agent-model-catalog.md)。

详情可为每个来源保存默认模型与默认思考深度。它们不是自动路由：用户决定 #247 允许已有 Worker 的运行设置在主动切换来源时自动填入默认模型，思考深度不变；项目/角色配置与新建指令运行设置仍只提供一键填入。填入后仍可改，保存才生效，不启动调用。详情还可逐来源勾选「额度刷新提醒」：开启后页面在缓存观测的重置时间到达时标出该额度，同一 `reset_at` 只提醒一次，刷新发现重置时间变化则按新时间重新计时。

进入页面只读本地配置与缓存。用户决定 #186：保存连接或完成登录后，页面自动刷新支持查询且已启用、有凭证的该连接；保存前必须说明联网行为，配置保存成功与额度刷新失败必须分别反馈，不因查询失败谎称保存失败。刷新中保留清晰的就地状态，旧值标明观测时间；换账号不得挂上旧账号数据。此联动不改变底层保存 RPC 的本地写入边界，不启动模型探测；采样默认关闭。

额度窗口的主显示回答“还有多久重置”，并以「上次刷新」相对时长说明当前数值多久前取得；绝对时间和观测口径保留在详情。倒计时与刷新提醒仅是本地时间计算，期限已到只能提示待刷新，不能假称额度已恢复或伪造新观测。刷新提醒沿用系统通知总开关，首次载入与刷新不补发关闭页面期间积压的提醒，也不新增 daemon 后台调度。计时显示不得留下离页后继续运行的采样或登录检查。删除不清除旧观测或外部客户端凭证，不能改变运行中调用的来源。

## 切换来源

项目默认从 Agent 配置页调整；Worker 详情提供轻量来源与模型入口，完整 Profile 编辑继续保留。轻量操作必须保留已有 Worker 覆盖中的 Prompt、资源、预算与环境变量，不得用角色默认悄悄覆盖它们。底层仍复用既有用户专属配置接口和准入规则；不为了可见入口放宽运行状态或权限。

当前调用实际来源与下一次配置应分别说明；没有后端证据时标明未知，不从模型名或项目默认猜测当前绑定。界面按用户自己命名的连接名称展示来源，不把内部连接 ID 当作可读名称；连接列表缺失或来源已删除时才回退连接 ID 并标明未知。保存不自动继续/重试，下一次 invocation 生效，当前请求不热切换。Worker 显式覆盖优先于角色/项目默认；清除覆盖的操作必须明确标注影响。

来源选择不自动更改付费账号或执行后端。用户决定 #247：已有 Worker 的轻量来源入口与完整运行设置（含失败重试）在用户主动切换到已读取的来源时，自动填入该来源的默认模型，保留思考深度及其他编辑；无默认模型时保留原模型并就地提示选择匹配模型，不猜选第一个模型。打开表单、读取/刷新连接、重置与迟到目录响应均不触发自动填入；项目/角色配置与新建指令运行设置不改变原有手动行为。旧模型不匹配时仍阻止保存。额度失败、未知、过期缓存均不能当作零触发路由。

## 兼容与能力边界

用户决定 #154：所有 Pi 调用都使用 Lush 项目独立配置及每次调用快照，不读取/复制用户默认 Pi 的凭证、设置或全局 Prompt。未绑定来源的后续 Pi 调用明确失败并提示选择来源，不自动回退外部认证；不删除旧配置和会话。独立目录不等于操作系统沙箱。项目 AGENTS.md 等开发约定仍可加载；用户显式选择的扩展/Skills 路径可以保留，但不自动发现/加载用户默认资源。

Pi 支持 Lush 托管连接；Codex CLI 仍沿用自身认证，托管 Codex OAuth 可供 Pi 使用不等于 Codex CLI 支持绑定。原账号观测历史保留在模型来源的只读存档，不迁移、不合并到托管连接；软件诊断不得读取或改写任何账号认证。独立配置与调用快照中只放本次需要的认证，OAuth refresh token 留在 Lush 连接管理器，避免并发调用各自刷新。

同一决定同时批准来源/模型窄更新：后台读取现有完整 Worker 覆盖（无覆盖时取有效角色默认），只更新来源和模型，原子保存并沿用状态、冻结与用户权限准入。详情仅返回无秘密的后续选择摘要，不公开 Prompt、环境变量或完整 retry_profile。

自定义端点仍仅支持现有 HTTPS OpenAI Chat Completions 适配，模型目录仅表示配置范围，不保证联网可用。来源密钥只写不回显。项目出站代理影响登录、查询与后续 Agent 调用，应归项目系统网络设置，而不是模型来源的端点字段。

## 验收问题

能否独立找到两页？选择来源是否只显示其模型？额度是否用进度条突出已用比例与窗口、仍保留失败 / 未知 / 旧值 / 时间？默认模型是否仅在已有 Worker 主动切换来源时自动填入，未设默认时保留并提示，其他入口与读取操作仍保护模型草稿？思考深度是否不随换源自动改写？看得出当前使用与下次配置的区别吗？打开页面是否不额外联网查询账号？Worker 的轻量操作是否保留其他覆盖？窄屏、键盘与双主题是否能用？诊断失败是否仍可编辑配置？旧凭证与历史是否没有被迁移或删除？不支持的后端是否如实禁用并解释？
