# 按钮帮助与 Agent 触发标识：让含义与代价一眼可见

本章面向修改 Web 按钮文案、图标、样式与交互的 Agent，回答“什么按钮必须解释、解释怎么写、怎样让人一眼看出它要调用 Agent”。实现入口是 `src/ui/web/assets/help.js` 与按钮原语 `src/ui/web/assets/dom.js`、`src/ui/web/assets/dialog.js`；模块职责与导出见 [Web 前端模块](../engineering/modules-web.md)。

## 用户目标

用户不应该靠猜来使用界面。看到一个图标、一个箭头或一个流程动作时，他需要马上知道它会做什么；看到一个会调用 Agent 的按钮时，他还需要在点之前就知道这会启动一次真实调用、要等较久、并消耗 token。

帮助提示要把这两件事就地讲清楚，而不是把说明埋进文档、塞进原生 `title` 的一行小字，或依赖用户已经记住了上一次点击的结果。

## 什么时候必须给按钮帮助

只要按钮的含义不能由可见文字自解释，就必须带 `data-help` 文案。至少包括：

- 只剩图标的按钮，以及窄屏 / 移动端被折叠成图标、箭头或省略号者。
- 破坏性或不可逆操作（删除、归档、丢弃、强制停止等）。
- 会改变流程状态的按钮，例如审批、驳回、合并、冻结、重试。
- 会调用 Agent 的按钮，另见下一节。
- 同一处有多个相似按钮、用户容易点错时（如一批「打开结果 / 接受 / 要求修改」）。

帮助文案是一句完整的说明，写“会做什么、有什么后果”，不重复按钮上的可见文字，也不只是把 `aria-label` 换个说法。

## 哪些按钮不加

可见文字已经完整表达动作的按钮不加 `data-help`，否则每个按钮都弹提示，反而让用户忽略真正需要解释的那些。返回、保存、退出、关闭、刷新、查看详情和带明确名称的普通页面导航这类自解释按钮保持干净。模型来源的刷新只是更新额度，不调用 Agent / 模型，不重复用浮层说明；联网范围与失败口径留在页面就地说明中。禁用原因仍可由外层宿主解释。

判断标准是“用户是否可能猜错或猜不出来”，不是“按钮重不重要”。

## 普通页面导航入口

W283／D637：帮助文档、使用帮助、管理模型来源、查看全部与返回等独立 UI 导航，统一使用 `nav-link` 轻量导航按钮：主题绿色文字、淡底、细边框与小圆角；悬停加深淡绿色，不显示下划线，键盘聚焦保留清晰轮廓。前进显示方向箭头，新标签打开显示右上箭头；它们不调用 Agent，不使用紫色。保留原生链接的打开方式、修饰键与来源项目身份。

窄屏允许完整文字换行，触控入口至少 44px，不把常用入口藏进新菜单。侧栏、整行列表、整卡导航及页内标签保持原有布局层级，不套成重复的小按钮；W／D／N／O 等自动引用与 Markdown 正文链接保持原样。此规则只统一导航呈现，不改变默认内容、高级功能展开或操作步骤。

## 具体 Worker / Order 的简介提示

指向具体 Worker / 原始 Order 的超链接，以及打开其详情、Hooks 或更多操作的按钮，延迟提示优先显示该对象的简介，而不是“打开详情”之类按钮含义。Worker 使用明确编号、展示标题（用户 `display_title` → Agent `auto_title` → 目标兜底）、目标摘要与已知状态；Order 使用真实 O 编号与原始指令摘要。摘要有界裁剪，以省略号明示，不调用 Agent 或模型生成简介。

已加载目标可直接用于提示；只有编号的链接在持续悬停、键盘聚焦或长按达阈值后，才通过既有只读 API 按链接来源项目加载。短暂掠过、普通点击及页面渲染不预取。离开、导航、换目标或旧节点卸载后，迟到响应不能重开提示或覆盖新目标；读取失败明示不可用，下次停留可重试。跨项目链接必须保持来源身份，不回落到当前项目。

这个规则不替换合并、发射、删除、追加输入等实际操作的帮助：操作后果、禁用原因与 Agent 调用费用仍按原约定展示。Notice 本身的导航与已读说明也保持独立。

## Agent 触发按钮的固定标识

会调用 Agent 的按钮必须**同时**满足两条：

- 带 `agent-call` 类，由它获得统一、醒目的紫色样式，让用户扫一眼就能认出这类按钮。
- 带由 `agentHelp()` 生成的 `data-help`，把“会调用 Agent、需要较长时间、会消耗 token”的代价说明统一交给这个函数。

不得手写 Agent 代价说明，也不得只写一半（只有紫色样式没有提示，或只有提示没有 `agent-call`）。这样代价口径只有一处权威，改文案时不会漏掉某个按钮。`help.js` 另导出 `AGENT_NOTE` 作为这段代价说明的唯一来源，`agentHelp()` 在它之上补充具体动作。

不得以紫色按钮标识为由恢复已删除的快速对话或右键直连模型动作。当前模型调用均沿正常 Agent 入口标识与授权。

## 多轮交付的代价与状态分离

已合并 Worker 的「验收」「继续开发（恢复待验收）」「同步父分支」都不自动调用 Agent，不应染成 Agent 紫色。「追加输入」与独立的「Agent 解决同步冲突」才是 Agent 入口。同步发生冲突必须先呈现固定提交诊断，不能悄悄替用户选择付费解冲突。

W169／用户决定 #418：验收表示对 Worker 工作不再有异议，**验收即归档并回收开发资源**。成功交付只提供一个「验收」动作；按钮帮助讲清分支子树的 worktree/ref 删除范围、脏现场阻止和完整运行历史保留，不提供“仅验收”，也不额外发第二次归档请求。资源回收失败不能宣称统一验收成功，显示诊断并保留显式续办入口；刷新失败不得重发成功请求。失败、取消和历史特殊分支的独立操作称「清理资源」，明确确认丢弃范围，不伪装为成果验收。详情/Worker 图共用动作实现。协议见[统一验收](../engineering/worker-acceptance.md)与[持续迭代](../engineering/task-iteration.md)。

## 共用模块与检索交互

W224／D525：常规页面复用 Worker 详情的模块设计，而不是各自复制限高、折叠与标题规则。阅读模块只有明显过高时才显示预览，展开后仍使用页面主滚动；标题与收起入口在所属模块范围内吸顶。表单、当前待答问卷和流程操作不得自动裁切，只能显式折叠，必要异常摘要留在正文之外。隐藏正文不销毁节点、草稿或选区；键盘焦点与引用定位必须先显露目标，同页刷新保留选择，离页释放观察与监听。代码／执行阅读器、Git／Worker 图和可拖动总览保留专用布局，不机械套用普通模块预览。Worker 详情[版本迭代](../engineering/version-history.md)按 W281／D641 确认的紧凑图布局显式接入共享超高预览与吸顶标题，仍保留真实图边、按需读取及独立生命周期，不复制折叠实现。

列表页与模块内文本搜索共用标签、输入框、搜索／清空入口和范围提示。按 Enter 或「搜索」提交文本；中文输入法确认候选不得提交。非文本筛选即时生效，但不能偷偷应用尚未提交的关键词。清空立即恢复无关键词结果，保留其他筛选。明确区分全库检索与已加载内容过滤；零命中、仍有未读分页、失败与未完成不能混为“没有记录”。统一展示不扩大后端检索范围，也不改变答复、已读或 Agent 调用权限。

## 视图工具的统一设计

W365／D739、W366／D740：排序与展开／收起统一可变线条图标和状态语义，不机械统一各场景外形。独立工具按钮贴合现有普通次级按钮的字号、字重、配色及圆角；模块标题与正文内折叠采用无常驻边框的紧凑轻量入口，不强制套用工具栏高度。工作树节点只用小箭头，不显示「展开／收起」文字，不画成大块按钮；键盘名称、展开状态及帮助完整保留。窄屏或触屏入口至少 44px，节点扩大热区而非图标，所在行容纳热区、不覆盖相邻内容；工具栏空间不足换行而不是隐藏文字或新增菜单。排序只留一个按钮，文字显示当前「最新在前／最早在前」，帮助说明下一动作与真实作用域。各模块原有默认顺序、设备偏好或页内状态的保存范围不变。

批量展开／收起也只留一个按钮：存在收起项（含混合状态）时先全部展开，全部展开后才全部收起；单项操作后同步，空范围禁用并解释。单项折叠文字说明点击动作，箭头跟随当前展开状态；树节点和原生 summary 保留整行点击，不机械改成小按钮。保留已读节点、选区、草稿保护、引用显露以及各模块原有后续加载规则，不借统一控件自动读取未加载历史。

搜索／筛选工具栏与分页底栏复用共用组件的尺寸、间距、焦点及反馈位置，默认筛选层级和提交方式不变。窄屏搜索输入独占一行，按钮自然换行；执行阅读器的受限搜索区允许内部滚动，以保留正文阅读空间。分页、加载更早／更新、刷新、全历史查找仍是不同动作，明确保留方向与真实范围，不合并成含糊的「更多」。

W373／D746：模块标题与计数居左，排序、搜索（适用时）、展开／收起等操作放入同一个靠右的紧凑组；只有操作组分配标题栏剩余空白，不让多个按钮各自用自动边距瓜分空白。窄屏不足时操作组换行，组内继续靠右，不隐藏文字、不新增菜单。常规单行按钮、导航、搜索／筛选和分页统一以桌面最小高度 32px、上下内边距 6px 为基准，触屏／窄屏最小点击高度仍为 44px；多行可增高。正文轻量折叠、树节点箭头和整行／整卡入口保留各自布局语义，默认内容、展开状态、排序范围和操作步骤不变。

## Worker 详情的信息密度

W350／D724：标题下首位统一为「打开工作台」新标签入口，默认执行记录，代码与改动、性能分析及适用 Worker 的 CLI 交互在工作台内切换；不再在 Agent、代码模块和页尾重复三个入口。按钮区按阅读、工作、交付、页面操作排列，追加输入、运行控制、当前合并／验收及异常恢复直达；新建子 Worker、重命名、运行设置、父分支同步及距离与危险操作按功能收进「更多操作」，危险区单独标识。同 Worker 刷新保留展开，窄屏自然换行、触控至少 44px。诊断与 Hooks 表单保持就地显示，不折进菜单；分组不改变权限、Agent 标识或确认流程。

详情优先展示该 Worker 的具体事实：模型来源、当前与下次配置、阶段、进度及阻塞／失败诊断。阶段提示用一行区分待验收、仅回答无提交、待父确认和资源回收待续办，不再逐个 Worker 重复软件设计、交付流程或完整验收介绍。固定原理留在文档，动作后果留在按钮帮助；精简不能隐藏异常或改变操作权限、安全检查与调用代价标识。

## 三种输入方式都要能看到提示

帮助不能只在鼠标悬停时出现，否则触摸屏与键盘用户就看不到：

- 桌面鼠标：持续停留 1200ms 才显示，掠过不显示，移开后消失；也可按住 650ms 查看。
- 键盘：通过键盘聚焦并停留 1200ms 后显示（按钮必须可聚焦）；点击带来的焦点不触发提示。
- 触摸屏：长按 650ms 显示；短按正常执行按钮，不显示提示。

普通点击会取消待显示的提示。离开、离焦、滚动、Esc、取消手势和导航都清理计时器；长按查看帮助不执行按钮，松手后的 click 被抑制。不要让提示变成每次鼠标移入或点击的即时反馈。

提示用自定义浮层承载，浮层挂 `.help-tip` 类。`help.js` 导出 `initHelp()` 负责装配这三种输入，`hideHelp()` 负责收起，`setHelpTimers()` 暴露计时器供测试注入；入口 `index.html` 在装配时调用 `initHelp()`。

## 禁用按钮用外层宿主

被 `disabled` 的按钮不派发鼠标与触摸事件，提示会失效。此时用外层 `span.help-host` 承载 `data-help`，并由 `help-host` 负责悬停与长按；该宿主使用 `display: contents`，在布局上不占位、不改变原有排版。

`dom.js` 的 `button()` 第 4 个参数接受 `{help, agent}` 选项：`help` 非空时写入 `data-help`，`agent: true` 时加上 `agent-call` 类；Agent 代价文案由调用方经 `agentHelp()` 生成后传入 `help`。确认与输入弹窗走 `dialog.js`，其选项同样接受 `agent` 与 `confirmHelp`，让弹窗里的确认按钮沿用同一套标识与提示。

## 从 title 迁移到 data-help

旧的 `title` 写法要迁移到 `data-help`。两者同时存在会让浏览器原生提示与自定义浮层重复弹出，用户会看到两条不同步的说明。迁移时保留原意、补齐后果，不要机械照抄，也不要留下空 `title`。

## 取舍与边界

- **为什么用自定义浮层，而不是原生 `title`。** 原生提示只能悬停触发、延迟与样式不可控、在某些内嵌 webview 里根本不出现，也无法承载 Agent 代价这类需要强调的说明。自定义浮层能在持续悬停、键盘持续聚焦、长按三种输入下一致工作，并与主题、reduced-motion 和 `agent-call` 样式统一。代价是需要在关闭、滚动、导航时主动收起，`hideHelp()` 就是这条清理路径。
- **长按与右键引用菜单、文本选中的冲突。** 长按既要触发帮助，又不能抢走页面已有的右键引用入口与文本选择。约定是：在可引用区域或正在选中的文本上，帮助让位于引用菜单与选择行为；只有落在普通按钮宿主上的长按才显示提示。两者触发区域不重叠时互不影响。
- **无障碍与减动效。** 浮层通过 `aria-describedby` 关联到按钮，使读屏用户也能读到同一份说明；提示的淡入淡出遵循 `prefers-reduced-motion`，用户要求减少动效时直接显示而非动画。
- **不引入后端或新实体。** 帮助只是前端展示约定，不新增 RPC、表、Worker类型或持久化状态；文案随按钮所在模块走，不需要 daemon 参与。

## 反例

- 只有紫色 `agent-call` 样式、没有 `data-help`，用户知道“特别”却不知道代价。
- 手写“此操作会调用 Agent”而不用 `agentHelp()` / `AGENT_NOTE`，各处口径很快不一致。
- 图标按钮、删除按钮、合并按钮依赖用户自己猜。
- 只在 `title` 里写说明，移动端与键盘用户永远看不到。
- `disabled` 按钮直接挂 `data-help`，提示不出现。
- 保留 `title` 又加 `data-help`，出现两条重复提示。
- 给返回、保存这类自解释按钮也加提示，噪声淹没真正需要解释的按钮。
- 为了帮助提示新增 RPC、后端字段或业务实体。

## 验收问题

改动后检查：

- 含义不直观的按钮是否都带了 `data-help`，自解释按钮是否保持干净？
- 会调用 Agent 的按钮是否同时有 `agent-call` 与 `agentHelp()` 生成的提示？
- 鼠标持续停留、键盘持续聚焦、鼠标 / 移动端长按是否都能看到提示，掠过和普通点击是否不弹提示？
- `disabled` 按钮是否用 `.help-host` 外层承载提示？
- 是否已从 `title` 迁移，没有留下重复提示？
- 浮层是否通过 `aria-describedby` 关联按钮，并尊重 reduced-motion？
- 长按提示是否让位于右键引用菜单与文本选中？
- 是否没有为此新增任何后端接口或业务实体？
