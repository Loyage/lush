# 一次性整合：由 Worker 自主合并

本文记录 W287／D646 确认的产品方向：把多个待合并分支的集中整合作为一次显式操作，不要求用户管理独立的“交付”体系。当前实现及历史在途兼容以[工程接缝](../engineering/merge-convergence-implementation.md)为准；本文不是运行中的 daemon 已更新的证明。

## 用户目标与操作

用户在工作树选择某个真实父目标，从三个点「更多操作」中点击「归并分支」，确认本次来源与 Agent 调用后，由一个整合 Worker 负责组合、适配与验证，最终一次性进入目标分支。

- 单项合并与已经授权的自动合并保留普通合并路径；它们可能提前处理本来可用于集中整合的来源。
- main／owner／开发 Worker 均可作为目标，每次只纳入同一真实直接父目标下、触发时已就绪且可准入的来源。不能跨层绕过开发负责人的汇总，也不能将未收拢后代的父 Worker 当作就绪成果。
- 来源与提交在操作开始时固定；之后完成或继续开发的分支不自动加入本次操作。
- 没有可准入来源时只说明原因，不创建空的整合 Worker；有来源时，即使没有文本冲突也由整合 Agent 负责整体适配与验证。
- 来源 Worker 的验收仍独立。整合成功不自动验收来源，也不提高其合并或验收授权。

流程是「选择目标 → 确认固定来源 → 整合 Worker → 最终验证 → 一次性合入」，不是一项持续开启的目标策略。不再提供持续归并的挂载、启停、未来默认或独立交付导航。

## Agent 决定如何整合

固定两两归并不是产品规则。整合 Agent 根据来源增量、依赖和接口关系，自主决定顺序、分组或两两组合；紧密关联的变化可以统一适配，不为满足平衡树而反复修复同一问题。runtime 不替 Agent 预先安排一棵必经归并树。

整合 Agent 获得固定来源提交、各来源本轮增量基点、开发目标、报告与目标基线。来源报告是资料，不是测试通过或语义兼容的证明。不得只按文件不重叠认定互不影响，也不得在多轮 Squash 后把完整源历史反复纳入。

Agent 必须保留各来源的意图，检查改名、公共接口、数据模型及架构迁移；对有歧义的需求取舍通过 Notice 请求用户决定，不能静默丢弃某个成员。它自行选择方法不等于保证全局最优：Agent 调用、代码理解与最终验证都有成本，纯 Git 的无冲突组合也可能更快，不承诺固定提速或复杂度。

## 稳定身份，临时工作区

Worker 的委派关系、分支创建谱系与本次整合的输入关系是不同事实。整合不得修改来源的 `parent_id`、`target_branch`、源 ref、编号或会话，也不得把某个来源分支作为其他来源的成果仓库。

整合 Worker 使用登记的私有分支与工作区，只能修改自己的组合产物。它不直接推进目标或来源分支，不借整合取得普通委派、跨树消息或来源验收权限。临时中间结果属于本次操作，不通过重挂真实父分支表达；取消和失败不需要“恢复父关系”。

## runtime 守住的边界

系统必须保存本次操作的固定来源、增量基点、目标基线、尝试与最终落地映射，以支持后续增量、诊断和崩溃恢复。这些是合并的技术记录，不是要求用户学习的新业务实体。

- 开始时复核来源静息、消息、待决、清洁度、后代与合并权限，原子领取固定集合；不得抢走已经执行或落地未知的普通合并请求。
- 准备与测试不占目标的长期写执行位。来源侧普通输入按安全冻结规则暂存，不混进固定尝试。
- 只有整合调用真实退出、工作区干净且决定已处理后，才允许接收候选；旧 invocation 的 token 或返回不得推进新尝试。
- 目标基线变化后，保留已有整合成果，由整合 Agent 审查新增变化、适配并重新验证最终树。不得机械拼接后将旧测试当作新树的证据。
- 最终只由 runtime 受检推进目标，复核精确候选、成员映射、目标与来源 refs、检出状态及清洁度；只有精确落地收据成立才标记来源已合并。
- Git 已写入而数据库未结算时，仅按精确凭据核验恢复；落地未知必须保留诊断并阻止后续写入，不盲目重放。

## 验证与失败取舍

整合 Worker 承担最终组合的验证责任：进入 main／owner 前完成项目规定的集成与全量；进入开发父目标时完成受影响集成，最终 main／owner 的全量责任仍由顶层整合或开发负责人承担。不逐个中间结果重复全量，不把来源各自通过、无文本冲突、Agent 正常返回或安全落地说成组合验证通过。

一次性合入意味着：任一来源的冲突、失败或待决都可能阻挡本次整体完成。不得暗中把其他成员先发布到目标，又声称最终一次性合入。失败保留整合现场；取消只停止尚未落地的本次操作，不丢弃源代码，不承诺撤销已经落地的提交。重试针对精确操作和尝试，不能自动重放未知模型或 Git 副作用。

一批最终 Squash 通常不能独立撤销某个成员；来源的语义适配可能相互依赖，需要新的修复指令调整当前代码，不保证逐成员 revert 安全。

## 用户界面

工作树是高频入口。「归并分支」收纳在目标的三个点「更多操作」中，按钮帮助说明普通合并无法完成时可用归并方式整合来源；卡片不显示「已合并」标签与旧交付摘要的暂存输入计数。工作树卡片仅在合并尚未结束时显示简短的处理阶段或待处理／失败／落地待核验标记，不展示整合 Worker、来源数量或操作摘要；完整信息从当前 Worker 详情查看。原 Worker 父子连线不变，不展示技术节点、轮次或策略。确认框讲清实际纳入与排除项，以及 Agent 调用的时间与 token 成本。

整合 Worker 复用 Worker 详情展示来源列表、待决／失败、执行过程、测试结果和最终提交。固定提交、来源映射与安全诊断按需展开；不另设交付或合并管理页面。窄屏入口独占一行、来源纵向排列、长分支名换行，进度与异常不依赖横向滚动或展开高级区。

会调用 Agent 的动作使用统一紫色 `agent-call` 与 `agentHelp()`；禁用原因用帮助宿主呈现。取消、重试与已确认请求后的刷新失败必须区分，不因网络错误重复创建操作。

历史持续归并的配置、在途尝试、事件与收据保留原义，不批量迁移或改写；兼容读取不构成重新启用旧产品机制的入口。具体恢复门和实际范围见[工程接缝](../engineering/merge-convergence-implementation.md)。
