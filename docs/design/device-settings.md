# 设备设置：配置一次，项目事实隔离

技术配置在同一设备／系统用户下唯一，项目不再覆盖；Worker 可保留完整显式运行参数。用户只需配置一次，不能因切项目悄悄换账号、网络或工作方式。当前有效读取与权限见[用户工作台](../engineering/user-workspace.md#设备配置分区)，安全迁移见[设备契约](../engineering/device-settings.md)。

## 边界

“设备”指运行 Lush 的机器上的同一系统用户，不是浏览器机器、所有 OS 用户或云账号。设备根保存 Lush 技术配置；LUSH_HOME 仍为项目 .lush，不改项目绑定、不新增核心实体或跨项目调度。

- 设备共享：模型连接／凭证、最新余额／额度缓存、Agent 默认／角色配置、common／role env、本机 Markdown 补充、扩展／Skills 安装库、运行参数与出站网络。共享最新观测不包含项目历史曲线或消费者。
- 项目专属：AGENTS.md／可提交 .lush-agent 开发约定、Worker／Input／会话／Notice、Git／worktree、在途调用、实际消费者及历史归因。技术配置不从旧项目文件回退或取并集。
- Worker 显式参数优先于设备／角色默认，子 Worker 冻结继承；双模式的隔离和持续覆盖见[配置契约](../engineering/agent-configuration-v2.md)。保存只影响后续请求／调用，不改当前快照。
- 主题、阅读／提醒偏好设备唯一；项目辨识色是独立身份元数据，不是技术覆盖。旧 theme 留存不生效，具体筛选／折叠仍是项目工作状态，见[外观兼容](../engineering/user-workspace.md#项目外观兼容决定-411)。旧并发槽配置留存但不再限额。

## 安全迁移

旧项目技术文件只供用户选择已登记来源、显式预检并确认导入；打开／重启不自动迁移、不扫描其他项目。预检核验固定路径、私有权限／所有者、大小、内容及 revision，说明设备级影响；秘密不进入读 API／审计／错误，目标不同值阻止覆盖，不按名称或 provider 合并账号。

connection ID 与已有引用保留，同 ID 不同认证／端点是冲突。先私有备份与持久步骤，再发布设备值并退役对应 JSON／env／凭证源；不能留下双活 OAuth refresh 副本，未知／中断不重放，失败可诊断、重新预检续办。不改外部 Pi／Codex 凭证。

旧私有 Markdown 导入成功后原件保留但不再活跃；项目 AGENTS.md／.lush-agent 不导入设备。Markdown 留存不能套用到凭证退役协议。旧安装库与显式资源路径保持归属，相对路径归一到原项目可信绝对位置，不误解到另一个项目；安装／更新与启用分离，第三方代码不是沙箱。

## 界面

设置只编辑设备值，不提供“本项目覆盖”切换或清除活跃覆盖。无项目也可管理，Host 不为此创建伪项目或启动 daemon；项目历史／消费者／服务操作保留固定项目身份，不拼成设备运行事实。

迁移展示来源、范围、冲突与影响，经 revision 明确确认；失败保留编辑、ACK 与重读失败分开，迟到响应不得覆盖新页面或草稿。

## 反例与验收

反例：每项目复制 refresh token 各自刷新；同名不同账号合并；设备文件缺失便回退旧项目凭证；仅打开设置就迁移／启动项目；把项目历史／消费者当设备事实；修改默认值热切换正在运行的 Worker。

验收：切项目是否仍用同一设备配置？Worker 显式参数和项目约定是否保留？无项目能否管理而不启动后台？旧源是否仅显式迁移、冲突／中断可恢复？OAuth 是否协调刷新、秘密不出读 API？设备更新是否只影响后续调用？

接口与恢复协议见[工程契约](../engineering/device-settings.md)。
