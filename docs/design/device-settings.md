# 设备共享设置：配置一次，项目按需覆盖

用户在 W116 确认：系统设置、Agent 配置、模型来源与快捷解释应在同一设备的其他 Lush 项目复用；采用设备默认 → 项目覆盖 → Worker 显式覆盖。待决 #261 两题均选择推荐：当前项目作为首次导入来源；成功迁移的源项目改为继承，其他旧项目保留原覆盖，新项目直接继承。

## 边界

“设备”指运行 Lush 的机器上的同一系统用户，不是浏览器机器、操作系统所有用户或云账号。用户配置目录保存 Lush 自己的共享技术配置；`LUSH_HOME` 始终是项目 `.lush/`，不改绑定、不引入跨项目调度、账号自动路由或新的核心实体。

- 共享：模型连接与凭证、连接最新余额/额度观测（本地查看无需逐项目重新联网刷新，不包含历史曲线或消费者）、Agent 默认 profile/角色覆盖、通用环境设置、扩展/Skills 安装库、运行参数默认值、出站网络默认值、快捷解释默认来源/模型/Prompt。
- 项目专属：开发约定、Worker/指令/会话/解释历史/通知记录、Git 与工作区、在途调用、实际消费者和历史消耗归因。项目的快捷解释结果仍落该项目数据库。
- 项目主题与配色属于项目外观元数据，由 Host 保存到项目 `.lush/appearance.json`，跨浏览器一致（W160）；无项目工作台主题及其余客户端偏好仍不冒称设备持久配置。过滤/折叠偏好仍按项目隔离。
- 环境默认、设备默认、项目覆盖与 Worker 覆盖可辨认。保存设备设置影响继承它的项目后续调用；不打断当前调用。并发值是每项目默认上限，不是整机总并发预算。
- 项目配置可完整覆盖 Agent profile 文档、网络和快捷解释；运行参数按键覆盖。清除项目覆盖必须是用户动作，不能由一般读取或重启偷偷执行。

## 安全迁移

迁移由当前项目的用户显式预检、确认启动，不扫描其他项目。导入前显示范围、冲突与影响，校验私有文件、大小、所有权和路径；凭证和环境变量原文不进入读 API、审计或错误。共享配置已有不同值时阻止覆盖，账号不按显示名或服务商合并。

保留稳定 connection ID 及引用；同 ID 不同认证/端点是冲突。只有确认导入成功后，才把源项目原文件转为私有备份并清除活跃覆盖。不能留下两份可被自动刷新的 OAuth 认证；不能操作用户默认 Pi/Codex 凭证。失败保留可诊断、可继续的状态，不谎称全部完成，重复执行不重复导入或清除。

已有安装包和显式资源路径必须保持可用；共享层不能直接使用相对原项目 cwd 的路径。保留旧安装库是兼容事实，不等于所有旧包已经搬到共享目录。共享安装/更新与显式启用分开，第三方代码仍不是沙箱。

## 界面

设置页默认编辑“设备共享”，已有项目可切到“本项目覆盖”，说明当前生效来源与覆盖阻挡。无项目时共享配置管理仍可用，不为管理设置启动 daemon 或创建伪项目。历史、消费者、项目重启只在已打开项目时展示，不拼接成虚假的跨项目记录。

迁移与清除覆盖有明确确认、范围和结果；迟到读取/保存不得覆盖切换后的作用域或草稿。

## 反例与验收

反例：复制 refresh token 到每个项目各自刷新；按同名来源合并不同账号；修改设备默认时清掉全部旧项目覆盖；为了打开配置启动一个伪项目；把项目消费者/解释历史拼成“设备历史”。

验收：新项目是否无需重复配置？旧项目是否保留原行为？用户能否看出继承来源及本次保存范围？无项目能否管理共享设置？冲突和中断是否保留原文件与可恢复状态？OAuth 是否协调刷新且秘密不出读 API？修改设备默认是否只影响继承项目的后续调用？

接口与分工见[工程契约](../engineering/device-settings.md)。
