# 自动化与预约发射

Hook 是受控自动规则：**触发节点 → 条件 → 动作**。项目自动化只管理项目设置与未来 Worker 默认；实际授权与运行记录在对应 Worker 自动化查看。旧 Valet 信号／绑定设置和指令／Hook 工具的 Web 入口已退休，已有配置、授权、历史与 API／CLI 保留。设备自动选择在全局自动化配置。快捷指令注册后由 Hook 引用，已有自动化未来执行跟随最新定义，无需预先授权指令。项目实际挂载和执行记录互不共享，页面重构不改变其他自动化授权或迁移历史。

## 页面入口

- 侧栏「项目自动化」保留 `#hooks`，目录四项：成果自动合并与验收、合并后自动 git push、归并合并、待验收告知。每项有名称、功能简介、原理简介；点开只看设置，无运行记录或所有 Worker 授权列表。返回保留已提交搜索与功能草稿，旧运行记录书签转到设置，历史不删除。
- 「成果自动合并与验收」设置本项目用户新建 Worker 默认关闭／自动到合并／自动到验收；只影响真正新建的指令，不改已有 Worker 或 child 锁定流程。旧设备默认编辑退役，旧配置与已有授权保留。
- 「待验收告知」设置未来用户指令默认开启／关闭，初始开启；child 初始关闭，各 Worker 可独立更改。真实进入待验收时告知，关闭不屏蔽失败、未知或待决，不补发历史；自动验收成功保持静默。
- 「合并后自动 git push」设置 main 同一真实挂载的开关；新 Worker 不自动挂推送。挂载参数与运行事实从 main 自动化查看；引用指令只读，定义经既有 CLI／API 修改，已删除挂载不重装。
- 完工与告知的“挂载范围”可选全部适用 Worker、用户创建的 Worker（含 main）、仅 main／分支所有者、不挂载；初始为全部适用范围，只影响未来实际创建。两项仅适用于 order／child，“仅 main”不会给新开发 Worker 挂载；child 完工始终挂载且锁定。默认状态与详情采用相同短按钮：完工「关闭／合并／验收」，其余「关闭／开启」。旧显示原则仅保留 API 兼容，不再参与显示或挂载。条件发射仍在输入／草稿详情。
- 「工作列表」`#workers` 仅展示开发 Worker；「管家列表」`#valets` 仅展示持久 Valet 管理记录。两列表共用有界历史分页、即时状态筛选与提交式文本搜索，明确已读范围，不冒充全库检索；使用实际 W／V 编号，旧未编号记录显示 `#内部ID`，打开通用详情和执行阅读器；管家详情另提供停用授权、停止管家与安全预检删除，不提供开发、Git、合并、验收或连续追加对话。
- 「CLI 接口」`#cli-interfaces` 将命令学习与当前项目未来新 Valet 默认权限合在一起（旧 `#valet-settings` 跳此页）。顶部固定 `lush` 前缀，搜索只需输入后续命令、名称或介绍，也兼容粘贴完整命令；实时本地匹配，空词只列顶层目录，输入法组合期间不刷新。目录、搜索结果及子命令均按命令路径单词数升序（不计 `lush`、参数及选项），同词数保留目录顺序；紧凑排列，每条占一个列表行，依次显示命令、简介及末尾的管理 Agent 权限摘要，多 RPC 明示多项而不冒充单一授权。点进命令查看用途、真实格式、示例、风险及子命令，返回保留关键词、结果和页内权限草稿；高级参数与 RPC 按需展开。多 RPC 关联逐项设置，非管家／本地能力可学习但不可提权。统一保存完整映射及 revision，不执行 CLI、不调用 Agent，已有管家快照不变。保存失败保留草稿，未知结果不重放，多标签冲突需显式重新读取；离页有未保存提醒。无项目仍可浏览 CLI 说明，不可编辑项目权限。精确权限契约见[管家默认权限](engineering/hook-signals-management.md#当前项目管家默认权限w278d632w279d635)。
- 旧独立「Valet 设置」信号／绑定编辑已删除；旧 `#management`／`#management-history` 跳管家列表并说明入口已移除，不把绑定快照当作完整历史。
- 「指令与 Hook 工具」及 Web 定义／模板编辑入口已删除；旧 `#hook-tools`、`#hooks-commands`、`#hook-tools-history` 及旧命令详情地址跳项目自动化并说明入口已移除，不迁入功能页或 Worker 详情。推送页只读核对引用指令；已有 Worker 实例 Hook 挂载／启停／编辑、后端 API／CLI、配置、授权和历史保留。
- Worker 详情「自动化」只显示实际挂载功能的标题与状态按钮，未挂载不显示对应入口。简介与原理在标题的延迟悬停、键盘聚焦或长按帮助中查看，不使用原生 title。实例挂载／编辑、交付处理器、推送读取与执行记录统一放入默认收起的「高级与记录」，刷新保留展开与在途编辑。失败、未知与必要阻塞始终可见，包括未挂载归并的历史失败；旧服务缺少权威挂载读面时只展示已知事实与兼容诊断，不猜授权。child 合并／验收流程锁定不变，挂载告知时可独立修改；Worker 图保留同源最高环节入口。

保存模板只保存规则，不执行动作。挂载原模板会在后台复制完整定义，包括私有运行设置；后续修改或删除模板不改变已有挂载。编辑模板时，同一位置的创建动作没有重新设置参数就保留已有私有覆盖；新增或移动创建动作须明确设置参数，不能从脱敏摘要猜出 Prompt/env。

## 快捷指令：注册后由 Hook 引用

1. Web 指令定义管理入口已退休。通过既有 CLI／API 注册或编辑名称、正文、作用说明、适用场景及可选标签、示例、风险提示；具体参数见[Hooks 接口](reference/rpc/hooks.md)。保存不执行、不调用 Agent，不恢复授权／撤权或手动运行入口。
2. 核对正文与风险，再由 Hook 选择指令并启用挂载，无需额外授权指令。Shell 使用挂载 Worker 目录；提示词仅在父可创建节点使用一次性规则，以挂载 Worker 为父创建并启动独立 Worker，消耗 token，不能与 Shell 动作混合。“创建并提交成功”不等于 Agent 已完成，结果从关联 Worker 查看。
3. 既有 CLI／API 可导出 Skill 风格 Markdown；导出不安装、不注入，也不让开发 Agent 直接调用。
4. 编辑名称、元数据或正文递增版本，但不停用挂载；已有自动化未来执行跟随最新定义。版本保留在导出、历史和实际执行证据中，不是许可。删除或切换为不匹配类型仍阻止执行，不保证撤回已经开始的副作用；已开始运行不会因编辑而换用新正文。

仅快捷指令预授权被删除：自动化启停、合并／验收级别授权、管理 Agent 危险操作确认，以及项目／Git／冻结／生命周期／互斥／精确收据安全门均保留。

手动运行已删除：页面无运行模块，CLI `hooks command run/start` 与 RPC `hooks.command_run/command_start` 均不再提供。旧默认 Worker 配置与手动运行历史保留，不迁移或自动重放；Hook 不采用旧默认目标。

**Shell 快捷指令不是沙箱**：命令在挂载 Worker 的真实目录，以 daemon 所在系统用户权限执行，可访问该用户的文件与网络；不要把凭证写进命令。使用 POSIX `/bin/sh`，不支持交互输入，最长执行 60 秒，输出超过 64 KiB 停止。页面只显示安全执行状态、退出码及超时等诊断，不公开原始输出。不会调用 Agent或消耗模型 token；Git/SSH 认证应提前配置为非交互可用。

快捷指令运行历史仍持久保存 Hook 与旧手动运行的安全摘要：名称／版本、Worker、来源、开始／完成时间、状态及退出码等。独立 Web 历史页已退休，既有 CLI／API 的分页读取和历史移除接口保留；指令改名或删除不抹去历史，旧记录缺少名称时明确标为未知。网络超时／断线不代表命令失败，请只读核对记录，不盲目重跑。后台重启时未结算运行记为结果未知，不自动重放；关闭页面不停止已接受执行。历史移除只处理已确认成功／失败的公开列表，保留安全审计、不撤回副作用；待执行、执行中、结果未知不可删除。仍可见的自动化模块按需展开／收起，同页更新保留状态与编辑，折叠不隐藏异常摘要。CLI 用 `hooks command history --execution UUID` 查结果，见[接口](reference/rpc/hooks.md)。

旧版本直接保存 Shell 的模板／挂载停止直接执行，保留原定义与历史。选择「导入」后注册快捷指令，源 Hook 转为停用的身份引用；检查指令，再启用 Hook。导入不是执行，不重放旧触发。旧未授权／已撤权字段不再阻塞执行，但已停用规则不自动启用，历史不改写。

## 归并合并

已挂载归并的 Worker 在「自动化 → 归并合并」点击「开启」并确认；未挂载目标的显式挂载入口在「高级与记录」。不需要选择最终验证快捷指令。项目「项目自动化 → 归并合并」只有一份“挂载范围”和“挂载后默认状态”编辑器，使用独立归并默认 revision，不另保存显示设置。新默认为用户创建的 Worker（user）挂载且关闭：新 order 挂载关闭，新 child 不挂载。只影响未来实际创建，不回写 main 或其他已有策略，也不提高来源 Worker 合并／验收授权。

归并把同目标固定成果组合为每批一个单父Squash提交，冲突时可能启动整合Agent并产生费用。新交付由Agent负责验证，runtime不额外执行最终验证命令；落地不代表测试通过。关闭或移除不撤回已固定批次、不删除历史，移除后不自动重装；旧已经固定的命令验证流程仍保留隔离验证与精确候选证据门。详细参数、兼容与风险见[归并接口](reference/rpc/convergence.md)。

## main 收到合并后 git push

首次初始化默认注册内置 `git push` 快捷指令，再创建默认关闭的持续模板与 main 挂载；可以直接启用推送 Hook。旧项目示例导入与已停用配置保留见[兼容契约](engineering/shortcut-commands.md#旧配置与-git-push)；其他内联命令仍需显式导入。

1. 在「项目自动化 → 合并后自动 git push → 设置」核对挂载引用的指令及正文，无需授权版本。
2. 在该功能页或 main Worker 的自动化推送项启用同一个挂载。Hook 的 command 动作保存 `command_id`，不是 Shell 正文；旧 command_version 仅兼容，未来仍跟随最新定义。
3. main 每次**成功收到合并**，后台提交一次执行；不是每次 Agent 返回，也不是等待验收之后。关闭页面仍可执行，但项目后台必须运行。

可编辑触发节点与条件、复制为停用规则；模板修改不会改掉已有挂载。要改推送命令，使用既有 CLI／API 修改定义，已有挂载未来执行跟随最新定义。

`git push` 的 remote、跟踪分支和认证由用户现有 Git 配置决定；需要指定目标可注册 `git push origin main`。Hook 不自动设置 upstream，不代管凭证，不添加 force push。门禁受阻时未开始的 Hook 命令等待安全点，删除或类型不匹配仍阻止执行。失败不撤销合并；失败或未知结果停止未来执行，检查现场后再显式启用，只授权未来触发，不重放旧命令。

## daemon 自动选择

在用户工作台「全局自动化」开启「全局自动选择」（默认关闭）。开启时同时处理已有待答问题，之后由后台接收问题时触发，不依赖浏览器保持打开。

- 单选题选择第一项，即使没有推荐标签。
- 多选题和普通文字问答回复「请由 Agent 自行判断并继续。」，不是批准某个方案。
- 计划审批与纯告知不处理。已回答记录和 Worker 收件箱明确标记 Lush 来源，页面显示「Lush 自动选择」，与用户答复区分。
- 开启期间所有项目页面常驻模式提示，移动端也可见；可直接「查看自动问答」或「关闭自动选择」，不会因查看、已知或离开页面而自动关闭。离线提示只表示最近确认的状态。
- 在「待我处理 → 自动选择」分页回溯自动处理的原问题和答案；关闭后历史仍保留，不提供撤回答案或重选。
- 开启可能恢复多个 Worker、继续产生 Agent 调用费用；确认授权后保存，开关跨 daemon 重启保留，作用于使用同一设备配置的项目，不自动启动停止的后台。
- 停用只停止未来及尚未处理的自动答复，不撤回已答问题或已开始的调用。它不会自动合并、验收或归档 Worker。

CLI 开关为 `bun run lush hooks auto-select on|off --revision REV`；REV 从 `hooks list` 返回的 `daemon_hooks.revision` 获取，不是模板 revision。实现与安全边界见[daemon 自动选择契约](engineering/daemon-auto-select.md)。

## 条件发射与冻结等待

新输入的「发射」先可靠挂载需求，不保证立刻出现在工作树；父 runtime 真实空闲、安全可写时才创建并开始。冻结自动等待，不必切换另一种预约按钮。Ctrl/⌘+Enter 与 Ctrl/⌘+Shift+Enter 都直接发射；桌面 Enter 暂存，新建与追加都支持这套流程。主输入框不提供条件发射；先暂存，再到草稿详情主动展开「条件发射设置」。

「条件发射」保存当前版本与全部条件授权，给对应 Worker 挂受保护的信号 Hook：可等待工作安全收尾、本轮成果进入 main 或目标树彻底静息。多个条件全部满足后仍须通过父准入；静息只约束开始，独占还约束后续并行。详情分别提供撤销尚未执行的意图、释放已持有独占的入口；未知结果不自动重试。操作与状态解释见[历史输入与暂存](input-history.md)，精确边界见[条件发射契约](engineering/conditional-emission.md)。

历史 create_worker 解冻预约仍按原授权执行，不迁移或重放；旧 API 的显式 start:false 仅创建路径仍保留。挂载保存运行授权快照，实际工作区从创建时父 tip 建立；Pi 自主管理模式只冻结模式，外部 Pi 的资源和认证仍在真正启动时解析。

## 定时 Hook：到点提交，尽早开始

在 Worker 详情的实际挂载编辑器中选择「定时提交」，再选择（独立 Web 模板编辑入口已退休）：
- **一次性**：指定日期、时间与时区；必须是未来时间。
- **每日**：指定 HH:mm 与时区；每日提交一次。夏令时重复时刻取首次，不存在的时刻跳过当天。

时区显式保存，不能只凭浏览器或服务器的「半夜」猜测。定时 Hook 在项目 daemon 中执行，关闭浏览器仍有效；项目后台停止、设备关机或离线期间错过的时间**跳过、不补跑**，也不会自动启动项目或唤醒设备。

到点只提交非阻塞待执行动作，不保证 Agent 恰好在该时刻开始。冻结、同步或实际调用收尾等临时门禁会保留等待项，在首个安全点尽早执行；每日受阻不累计多份排队。管理区区分下一提交时间、已提交待执行和最近结果。停机前已提交但未开始的项恢复后仍可继续等待；已经开始但结果未知不自动重放。

可安排以下操作：
1. **创建 Worker**：挂在所选父 Worker（例如 main），保存指令、引用及运行参数；选 Codex 对应的托管来源／模型，实际创建时从当时父分支 tip 建独立工作区。
2. **追加输入**：挂在目标自身或其直接父子，使用目标已有运行设置；要使用某个 Codex 账号，先显式配置目标的模型来源，不隐式切换账号。
3. **重试失败 Worker**：可在失败 Worker 自身安排，也可提前安排到点后若失败则重试。仅处理 failed，沿用工作区与上下文；可明确设置下次运行参数。
4. **继续暂停 Worker**：只处理已经 paused 的 Worker，不撤销尚未生效的暂停请求，不恢复已取消／验收／归档工作。

重试／继续遇到其他状态会记录「已跳过」，不等待它未来失败。模型调用仍可能因额度、认证或网络失败；到达额度更新时间**不代表额度已经恢复**。定时授权不是自动判断额度或无限重试。

## 时间信号 → 管理型 Agent

旧独立 **Valet 时间信号／绑定编辑入口已退休**（「CLI 接口」仅编辑未来管家默认权限），不迁到项目自动化或管家详情。已有时间信号与绑定继续按原授权运行；需要管理具名信号、一次性／持续绑定时，使用既有 CLI／API，参数见[Hooks 接口](reference/rpc/hooks.md)。保存绑定不立即调用 Agent；到点后后台持久提交，在有运行槽时开始管理调用，不保证准点获得槽，daemon 必须运行。同一信号可绑定多项管理指令，默认一次性；持续是显式周期授权。

历史订阅缓存辅助实现仍保留时间与失败语义，但不代表页面入口仍存在：未知、无效、已到期时间不可用，查询失败不回退旧成功值；不绑定账号、不持续跟踪、不把时间已到当额度恢复。

Valet 使用独立提示词、专属非 Git 目录和仅管理工具，不写项目代码、不走合并交付。可安全查询、分析有界运行摘要、管理草稿与条件发射、合法追加、开始／继续或重试开发任务；危险操作须在待决问卷中由用户确认精确请求。不读取原始凭证或会话、不提供任意文件／Shell 工具、不跨项目。默认输入框仍用于开发，显式「管理 Lush」还可即时提交管理需求并新建 Valet，不要求时间信号；例如“W123 合入 main 后做 xxx”。不可用能力会指向用户界面，不把目录可见冒充执行权限。

时间信号只表示安排的时间已到，不是账号额度已恢复；目标仍用原保存的运行配置，不隐式换账号。管理调用自身也需要可用模型额度。冻结、同步或旧调用尚未退出时，管理工具提交的操作持久等待安全点；Valet 不靠轮询或反复付费调用等待。详情阅读区显示绑定、已提交信号、等待原因及最近结果；顶部可停用未来授权或请求停止管家，不编辑信号定义或重新启用绑定。停止请求成功、状态变为 cancelled 都不等于调用已退出；须等真实退出及在途操作收口，重新预检删除范围与 revision 后才可确认删除专属目录和历史，未知结果不自动重放。精确资源保护见[彻底删除](reference/rpc/maintenance.md#彻底删除-worker)。长指令与操作列表明确标注摘要／未列全；完整指令、结果、Agent 信息及执行历史从通用工作详情打开，Valet 详情不提供开发操作。新 Valet 显示持久 V 编号，旧未编号记录仍显示 #内部ID，不从内部 ID 猜号。

当前项目共用一个管家串行执行位；即时输入从持久排队起占位，未触发的未来信号绑定不占位，已有绑定触发后按 occurrence 身份公平排队。模型实际退出、待用户确认和受控操作完整收口前均保留占位，期间拒绝新建管家；冻结或停用不提前释放，精确去重重试仍返回原身份。持续绑定复用同一个 Valet，也不意味着支持向它追加管理指令的连续对话；忙时只保留一个未结算信号。停机错过的时间不补跑，已提交未开始的项可恢复；未知模型／动作副作用不自动重试，失败停止绑定并保留诊断。管理收据成功只表示对应受控操作已提交／执行，不证明目标业务或额度恢复成功；需要用户确认时仍是待决，不冒充完成。

管理调用不加载 Lush 公共／角色环境文件或 profile 环境覆盖，但保留机器运行环境、项目网络策略与所选连接的必要管道；这是工具／RPC 隔离，不是操作系统沙箱。

当前受限管理工具使用 Pi 后端，可选择 Pi 中的 Codex 模型；旧独立 Codex CLI 后端没有受限管理工具适配，不能用于管理调用。接口、隔离与恢复规则见[时间信号与管理契约](engineering/hook-signals-management.md)。

## 统一系统工具与操作结果

自动化目录统一说明三个系统工具：来源 `request_merge` 请求交付，目标 `integrate_deliveries` 处理已授权交付，`accept_worker` 按明确授权安全验收。来源结束规则和目标策略仍各自授权，不因 main 开启归并而自动合并或验收别的 Worker。

目标处理器持续启用，选择普通串行或归并；关闭／移除归并只影响之后固定的处理策略，不停止所有合法合并、不撤回已有交付。目标实际配置在 Worker 详情管理，项目页只设置未来默认；受保护的处理器不可作为普通模板编辑、复制或移除。

执行记录分开显示 Hook 请求提交与真实操作。提交、等待、执行中均不代表完成；操作完成可能是代码合入，也可能是无代码结果交付，验收完成包含资源回收。没有证据或旧服务未提供新字段时不推断成功，失败与未知不自动重放。操作完成不证明测试或业务质量；详细字段见[接口参考](reference/rpc/hooks.md#系统工具操作读面)。

## 自动合并—验收（验收即归档）

在「项目自动化 → 成果自动合并与验收」中选择用户新建 Worker 默认关闭／合并／验收，再保存。W169／决定 #418：**验收即归档**，表示对 Worker 工作不再有异议，允许安全回收分支子树的 worktree/ref，保留 Worker、会话、结果和完整运行历史；脏工作区阻止验收。初始关闭、默认环节为合并，关闭仍记住所选值，选择验收须了解资源回收范围。

这份项目默认**只影响本项目之后实际创建的新指令 Worker**，不修改已有 Worker 的配置。预约／定时创建按真正创建时的默认复制授权，随后修改默认不撤销已保存授权。用户明确允许旧自动验收直接采用新语义，旧自动归档值等价验收。child 默认自动合并、直接父 Agent 检查成果后保留供追加需求，尽量随父级安全批量验收（同时回收资源），不连带验收独立指令；流程对用户只读，不继承父授权；管理 Worker 不参加 Git 自动链。

Worker 详情以一行最高环节配置两个内置 Hook，点击即保存，验收授权说明回收范围。高亮与前置下划线表示已授权，不是执行结果；结果在「高级与记录」中查看。

| 最高级别 | 自动执行 | 下一人工环节提醒 |
|---|---|---|
| 关闭 | 无，保留手动流程 | 显式交付进入待验收且告知开启时提醒 |
| 自动到合并 | 合并 | 告知开启时提醒待验收 |
| 自动到验收 | 合并 → 验收（含归档回收） | 自动成功不告知 |

第 1 步是「本轮交付就绪」，不是每次 Agent 返回：调用实际退出、后代结算、消息和待决处理、Git 检查后，由父 Worker 队列合并。无改动成果经明确交付核验后跳过空 Squash，仍按顺序推进。

第 2 步复用安全校验并代替用户确认，**不调用质量评审 Agent，也不保证业务质量**。删除前的临时阻塞（例如调用仍在收尾、待处理输入或脏现场）保留等待，解除后在安全点重新核验；手动验收仍按原门禁拒绝。内部安全回收分支子树的 worktree/ref，不丢弃未提交文件。回收成功才完成此次统一验收；部分失败保留事实和诊断，显式续办，不自动重放未知删除。已成功落地的代码不撤销。

- 新指令默认采用项目独立策略；用户也可配置当前指令 Worker 的实际最高级别，不继承给后代。派生 child 的合并、验收、归档流程 Hook 整体只读：默认自动合并、由直接父 Agent 检查成果并保留现场，尽量随父级安全批量验收，用户不能关闭或提高级别；按钮禁用并说明原因。其他自定义 Hook 仍按原权限管理。
- 级别跨轮保留，与本轮执行收据分开；「已授权」不等于「已发请求」或「已执行」。
- 请求冻结／挂起、自动动作执行、同步或结果未知时不能改当前链。用户指令已合并待验收、已验收未归档时，可以显式提高级别补办，仍核验当前 HEAD、消息、待决、后代与现场。
- 旧自动合并开关保持原门禁；允许关闭时只撤销未来自动触发，不撤回已发请求。历史交付继续原协议。
- 自动验收成功只留审计和执行记录；其余实际进入待验收时按独立告知开关提醒，不在单纯静息时发成功告知。失败、受阻、未知和待决仍提醒，自定义通知 Hook 不受影响。
- 明确失败／未知结果不自动重试；先检查现场，可通过人工验收续办或特殊现场清理及显式恢复处理剩余步骤，不用改变级别绕过诊断。

## 可用节点与动作

表单按后台目录限制可选节点和动作，不允许任意组合。当前节点如下：

| 触发节点 | 含义 |
|---|---|
| `agent.started` | 正式开始一次调用 |
| `agent.returned` | 正常返回且实际退出，不等于工作完成 |
| `agent.failed` | 异常、超时或重启发现调用中断，不自动重试 |
| `agent.paused` / `agent.preempted` | 安全暂停／输入抢占已生效，不冒充失败 |
| `worker.interrupted` | 中断完成信号：本次用户安全中断已生效且调用真实退出，仅允许纯告知 |
| `project.interrupted` | 项目维护批次全部安全收尾，挂在 main／owner，仅允许纯告知 |
| `worker.delivery_ready` | 本轮交付就绪，退出、消息、待决和后代均收口；合并仍复核 Git |
| `worker.frozen` / `worker.unfrozen` | 整体写门冻结／最后一项冻结原因释放 |
| `worker.parent_ready` | 所挂载父 Worker 通过创建准入，可创建子 Worker |
| `worker.merge_received` | 子 Worker 代码成功合入所挂载父 Worker，每次合并独立触发 |
| `worker.awaiting` / `worker.resumed` | 出现待决／全部待决解除，不代表交付完成 |
| `delivery.requested` | 目标接收已授权交付，仅系统处理器使用；不能自定义挂载或借此提高来源权限 |
| `delivery.integrated` | 源 Worker 交付落地，与父侧收到合并不同 |
| `delivery.suspended` / `delivery.blocked` | 交付挂起释放执行位／未知现场待核验且保留执行位 |
| `worker.accepted` / `worker.cancelled` | 明确验收（含安全资源回收）／取消，保留运行历史 |
| `time.scheduled` | 按显式时区一次性或每日提交动作，不保证准点开始 |

主动暂停与抢占不是失败；「等待用户」对应待决问题，不是每条普通通知。页面只是读取这些事实，不靠轮询触发 Hook。

全局项目管理点击「全部中断」会为本次调用挂一次性完成告知。Worker 通知只证明自身安全停住；全局另汇总本次固定在线项目批次，全部完成且当前可重启才提醒。项目调用／Git／Hook 等仍忙、来源不可达或批次未知时不报成功；不会自动重启或继续。维护期间两个新节点仅执行纯告知，其它自动动作仍等待解除维护。页面关闭后不承诺后台推送，来源通知保留。可以用信号提醒切换模型／账号；自动生成交接摘要、备份等涉及额外权限的玩法暂未开放，见[工程边界](engineering/interrupt-completion.md)。

每条规则最多四个有序动作，并可限制触发时的 Worker 状态和集成状态：

- **发送通知**：创建信息通知，不调用 Agent；可一次性或持续。
- **发送消息**：只发送给当前 Worker 或直接父子；可能唤醒 Agent。生命周期规则仅一次性防递归；定时可按每日授权重复。
- **创建 Worker**：父可创建安全点的一次性预约，或定时提交；均复核创建安全门，可选择开始 Agent 或仅创建。
- **重试失败／继续暂停**：仅定时节点，显式授权，保留原工作区与上下文，不恢复取消／验收／归档。
- **请求合并**：仅本轮交付就绪，复用既有权限、冻结与交付队列。
- **执行命令**：引用快捷指令目录中的最新定义，不允许内联 Shell；一次性或持续；当前不允许 `time.scheduled`、`agent.failed`、`worker.accepted`、`worker.cancelled`、`worker.interrupted`、`project.interrupted`、`delivery.requested`，其他节点仍需实际目录与安全门通过。真实目录和用户权限见上节，命令业务语义由用户自己负责。
- **自动验收（含归档回收）**：仅内置串行流程，不允许自定义安装；使用最高自动环节统一授权，不能拆成互相矛盾的开关。

「main 收到合并后 git push」卡片只管理 main 的那一个挂载；编辑／复制通用命令模板不代表全项目启用。模板是尚未挂载的配置，不是全局作用范围，也不以模板的启用字段冒充真实挂载状态。

可能调用 Agent 的规则与按钮带紫色标记和费用说明。配置接口没有任意 RPC、跨项目或跨任意 Worker 的动作；通用命令本身不是系统沙箱，不能据此推断它无法访问别的目录。管理型 Agent 的窄操作授权另按上节核验，不开放给普通开发 Agent。

## 等待、失败与取消

等待中的挂载可停用或移除。预约草稿被占用时不能编辑、删除或重复发射；等待／明确失败状态下停用可释放草稿；仍在等待的挂载重新启用时后台重新核验版本与占用，明确失败需检查后重新授权。父 Worker 已取消或验收后仍可移除未执行的自定义挂载，释放草稿，但不能重新启用结束的 Worker。失败 Worker 的定时自重试是窄授权例外，可挂载／停用定时自重试，不开放其他终态行为。

一次性 Worker Hook 成功执行后自动删除挂载，包括预约发射；执行审计及已创建的 Worker、Input 和草稿发射关联保留。持续 Hook 和模板不删除。后台升级重启时也会清理旧版留下的成功一次性挂载；失败、未知、错过或不适用的项保留诊断。

动作已经开始时不能撤销。明确失败不会自动重试；执行结果未知（例如创建途中 daemon 重启）也不会重放。先核查已有 Worker、worktree 和执行记录；需要恢复时移除旧授权，再显式新建。未知状态仅停用不会释放草稿。移除挂载不删除已经产生的 Worker、代码或消息。

多个合并排队时，runtime 在每次真正释放父执行位后给等待的创建 Hook 一个机会，再推进下一项；正在修复分歧或未知落地仍占位时不会强行解锁。

模型摘要可读，但完整 Prompt、env、运行资源与私有 Hook JSON 不出现在 Worker/API 结果中。CLI / RPC 见 [Hooks 接口](reference/rpc/hooks.md)；维护契约见 [Hooks 工程边界](engineering/hooks.md)与[快捷指令契约](engineering/shortcut-commands.md)。
