# 自动化与预约发射

Hook 是受控自动规则：**触发节点 → 条件 → 动作**。除了 Worker 挂载规则，项目「自动化」页面还提供 daemon 内置自动选择、时间信号与管理指令。普通动作使用受控目录；Shell 命令先注册为快捷指令并授权具体版本，Hook 只能引用授权指令，管理指令仍用独立管理型 Worker 执行。项目之间的开关、模板、挂载和执行记录互不共享。

## 两个入口

- 侧栏「自动化」（`#hooks`，保留原地址，小标题「快捷指令和 Hook」）：快捷指令区管理命令与授权，Hook 区统一卡片管理「结束后自动处理流程」「main 收到合并后 git push」「自动选择」，名称与作用范围分开显示。下方管理可复用的项目模板，可按名称、触发节点或动作查找；时间信号与管理指令仍单独管理。卡片上的「使用帮助」打开本页，触发目录与流程说明不在管理页重复铺开。
- Worker 详情「Hooks」：默认一行「自动到：关闭 / 合并 / 验收 / 归档」，高亮已保存的最高自动环节；「管理」按需展开实际挂载、参数、最近执行记录和自定义规则编辑。异常状态保持简短可见，通用介绍集中在本帮助文档。Worker 图中的摘要入口跳到详情。

保存模板只保存规则，不执行动作。挂载原模板会在后台复制完整定义，包括私有运行设置；后续修改或删除模板不改变已有挂载。编辑模板时，同一位置的创建动作没有重新设置参数就保留已有私有覆盖；新增或移动创建动作须明确设置参数，不能从脱敏摘要猜出 Prompt/env。

## 快捷指令：先注册，再授权

1. 在「自动化 → 快捷指令」注册名称与 Shell 正文；保存不执行，也不授权。
2. 核对正文与风险，单独授权当前版本。Hook 编辑器只能选择指令及明确版本，不能填写 Shell。
3. 要立即执行，选择目标 Worker 后手动执行；仍核验真实工作目录、分支、冻结、同步、清理与实际调用门禁。受阻明确拒绝，不隐式排队重试。
4. 编辑名称或正文后递增版本并撤权。重新授权新版本后，还需明确更新 Hook 的引用，不能让旧 Hook 悄悄采用新命令。删除或撤权会阻止未开始的执行，不保证撤回已经开始的副作用。

**快捷指令不是沙箱**：命令在所选／挂载 Worker 的真实目录，以 daemon 所在系统用户权限执行，可访问该用户的文件与网络；不要把凭证写进命令。使用 POSIX `/bin/sh`，不支持交互输入，最长执行 60 秒，输出超过 64 KiB 停止。页面只显示安全执行状态、退出码及超时等诊断，不公开原始输出。不会调用 Agent或消耗模型 token；Git/SSH 认证应提前配置为非交互可用。

旧版本直接保存 Shell 的模板／挂载停止直接执行，保留原定义与历史。选择「导入」后注册未授权快捷指令，源 Hook 转为停用的版本引用；检查并授权指令，再启用 Hook。导入不是执行，不承接旧授权，不重放旧触发。

## main 收到合并后 git push

首次初始化默认注册并授权内置 `git push` 快捷指令，再创建默认关闭的持续模板与 main 挂载；可以直接启用推送 Hook。旧项目未修改的默认示例在启动时一次性导入并授权，已撤权、编辑或删除的配置不会恢复，旧触发不会重放。其他内联命令仍需显式导入并授权。

1. 在快捷指令区核对默认已授权的 `git push` 当前版本；如果后来修改或撤权，则须自行重新授权。
2. 在「main 收到合并后 git push」卡片或 main Worker 的「Hooks → 管理」启用同一个挂载。Hook 的 command 动作保存 `command_id` 和 `command_version`，不是 Shell 正文。
3. main 每次**成功收到合并**，后台提交一次执行；不是每次 Agent 返回，也不是等待验收之后。关闭页面仍可执行，但项目后台必须运行。

可编辑触发节点与条件、复制为停用规则；模板修改不会改掉已有挂载。要改推送命令，在快捷指令目录修改、重新授权，并明确更新 Hook 版本引用。

`git push` 的 remote、跟踪分支和认证由用户现有 Git 配置决定；需要指定目标可注册 `git push origin main`。Hook 不自动设置 upstream，不代管凭证，不添加 force push。门禁受阻时未开始的 Hook 命令等待安全点，但授权变化会阻止旧版本开始。失败不撤销合并；失败或未知结果停止未来执行，检查现场后再显式启用，只授权未来触发，不重放旧命令。

## daemon 自动选择

在当前项目「自动化 → 项目 Hooks」开启「自动选择」（默认关闭）。开启时同时处理已有待答问题，之后由后台接收问题时触发，不依赖浏览器保持打开。

- 单选题选择第一项，即使没有推荐标签。
- 多选题和普通文字问答回复「请由 Agent 自行判断并继续。」，不是批准某个方案。
- 计划审批与纯告知不处理。已回答记录和 Worker 收件箱明确标记 Lush 来源，页面显示「Lush 自动选择」，与用户答复区分。
- 开启期间所有项目页面常驻模式提示，移动端也可见；可直接「查看自动问答」或「关闭自动选择」，不会因查看、已知或离开页面而自动关闭。离线提示只表示最近确认的状态。
- 在「待我处理 → 自动选择」分页回溯自动处理的原问题和答案；关闭后历史仍保留，不提供撤回答案或重选。
- 开启可能恢复多个 Worker、继续产生 Agent 调用费用；确认授权后保存，开关跨 daemon 重启保留，仅作用于当前项目。
- 停用只停止未来及尚未处理的自动答复，不撤回已答问题或已开始的调用。它不会自动合并、验收或归档 Worker。

CLI 开关为 `bun run lush hooks auto-select on|off --revision REV`；REV 从 `hooks list` 返回的 `daemon_hooks.revision` 获取，不是模板 revision。实现与安全边界见[daemon 自动选择契约](engineering/daemon-auto-select.md)。

## main 冻结时预约发射

1. 在主输入框选择 main，填写指令和引用；展开运行设置可选择 Agent、配置模式、模型、思考强度及完整覆盖。
2. main 冻结时，「创建 Worker」变为「预约发射 Worker」。点击会保存一次性 Hook，**此时不创建 Input、Worker 或 worktree，也不调用 Agent**。
3. 所有冻结解除、父 Worker 允许创建且 Git 准入通过后的首个安全创建边界，后台从**那时的父分支已提交 tip**创建独立 Worker/worktree。默认排队开始 Agent，不承诺执行槽立即空闲。
4. Ctrl/⌘+Enter 预约「仅创建」；Ctrl/⌘+Shift+Enter 预约「创建并开始」。未冻结时，原「创建 Worker」仍默认只创建待开始 Worker。

「历史输入」中也可以对当前一条暂存预约「创建并开始」或「仅创建」，并单独设置运行参数。正文、引用、父身份与草稿版本来自保存的草稿，不接受混入另一份正文。

预约保存完整授权快照，而不是执行时重新读取浏览器或默认设置。未显式覆盖时冻结挂载时的有效项目默认；测试/mock 后端没有可配置模型，不冒充真实模型验证。Pi 自主管理模式只冻结模式，外部 Pi 的模型、资源和认证仍在真正启动时由 Pi 解析。

## 定时 Hook：到点提交，尽早开始

在项目「自动化」模板或 Worker 详情的挂载编辑器中选择「定时提交」，再选择：
- **一次性**：指定日期、时间与时区；必须是未来时间。
- **每日**：指定 HH:mm 与时区；每日提交一次。夏令时重复时刻取首次，不存在的时刻跳过当天。

时区显式保存，不能只凭浏览器或服务器的「半夜」猜测。定时 Hook 在项目 daemon 中执行，关闭浏览器仍有效；项目后台停止、设备关机或离线期间错过的时间**跳过、不补跑**，也不会自动启动项目或唤醒设备。

到点只提交非阻塞待执行动作，不保证 Agent 恰好在该时刻开始。冻结、同步或实际调用收尾等临时门禁会保留等待项，在首个安全点尽早执行；每日受阻不累计多份排队。管理区区分下一提交时间、已提交待执行和最近结果。停机前已提交但未开始的项恢复后仍可继续等待；已经开始但结果未知不自动重放。

可安排以下操作：
1. **创建 Worker**：挂在所选父 Worker（例如 main），保存指令、引用及运行参数；选 Codex 对应的托管来源／模型，实际创建时从当时父分支 tip 建独立工作区。
2. **追加输入**：挂在目标自身或其直接父子，使用目标已有运行设置；要使用某个 Codex 账号，先显式配置目标的模型来源，不隐式切换账号。
3. **重试失败 Worker**：可在失败 Worker 自身安排，也可提前安排到点后若失败则重试。仅处理 failed，沿用工作区与上下文；可明确设置下次运行参数。
4. **继续暂停 Worker**：只处理已经 paused 的 Worker，不撤销尚未生效的暂停请求，不恢复已取消／验收／归档工作。

重试／继续遇到其他状态会记录「已跳过」，不等待它未来失败。模型调用仍可能因额度、认证或网络失败；到达额度更新时间**不代表额度已经恢复**。定时授权不是自动判断额度或无限重试。

## 时间信号 → 管理型 Agent

需要用自然语言安排「额度更新时间到后开始 Wxx」时，在 **自动化页面**完成：

1. 新建时间信号，例如「Codex 额度更新时间已到」；选择一次性日期或每日时刻，明确时区。也可在「从订阅额度刷新时间填入」中选择模型来源与额度窗口，直接填入缓存的刷新时刻：改为一次性日期、保留当前时区，之后仍可手动修改。仅使用当前成功／部分成功观测中的订阅额度（账号级 quota），未知、无效或已到期的时间不可选；查询失败不回退旧成功值。没有可用时间时，先在「模型来源」刷新额度，再「重新读取订阅缓存」，或手动填写。这里仅本地读取，不联网刷新、不绑定账号、不跟踪后续变化；观测时间单独显示，时间已到不证明额度恢复。
2. 创建管理指令，写「开始 Wxx」或「如果 Wxx 已失败，帮我重试」，选择对应信号和管理 Agent 自己的模型／来源。
3. 绑定默认**一次性**；只有希望每天重复执行才选「持续」。同一信号可绑定多项管理指令。
4. 保存不立即调用 Agent。到点后后台持久提交，在有运行槽时开始管理调用；无需保持浏览器打开，但 daemon 必须运行。

管理 Agent 使用独立提示词、专属非 Git 目录和仅管理工具，不写项目代码、不走合并交付。首版可查询当前项目、开始／继续暂停的 Worker、重试失败的 Worker，目标不限父子；**不能**创建开发任务、追加输入、取消、合并、验收、归档、删除或修改账号与服务。默认开发输入框仍用于开发任务。若要定时创建／追加输入，继续使用上节的显式定时 Hook。

时间信号只表示安排的时间已到，不是账号额度已恢复；目标仍用原保存的运行配置，不隐式换账号。管理调用自身也需要可用模型额度。冻结、同步或旧调用尚未退出时，管理工具提交的操作持久等待安全点；管理 Agent 不靠轮询或反复付费调用等待。卡片显示绑定、已提交信号、等待原因及最近结果，可停用未来授权。长指令与操作列表明确标注摘要／未列全；完整指令、结果及历史从只读管理详情打开，详情不提供开发操作。

持续绑定复用同一个管理 Worker，不并发调用；忙时只保留一个未结算信号。停机错过的时间不补跑，已提交未开始的项可恢复；未知模型／动作副作用不自动重试，失败停止绑定并保留诊断。管理操作成功只表示开始／重试请求已排队，不证明目标任务或额度恢复成功。

管理调用不加载 Lush 公共／角色环境文件或 profile 环境覆盖，但保留机器运行环境、项目网络策略与所选连接的必要管道；这是工具／RPC 隔离，不是操作系统沙箱。

当前受限管理工具使用 Pi 后端，可选择 Pi 中的 Codex 模型；旧独立 Codex CLI 后端没有受限管理工具适配，不能用于管理调用。接口、隔离与恢复规则见[时间信号与管理契约](engineering/hook-signals-management.md)。

## 自动合并—验收—归档

在当前项目「自动化 → 结束后自动处理流程」中，选择是否启用，以及默认自动到合并、验收或归档，再保存。环节按钮沿用 Worker 详情的视觉：高亮最高环节、下划线标出包含的前置环节；这里是未保存的默认值选择，不是执行结果，也不像 Worker 详情点击即保存。初始关闭、默认环节为合并；关闭后仍记住所选环节，选择归档授权时会确认清理范围。

这份配置仅属于当前项目，**只影响之后实际创建的新指令 Worker**，不修改已有 Worker，也不补办已有成果。预约或定时创建以真正创建时的流程默认为准（模型／运行设置仍按原挂载快照处理）。每个新指令保存自己的授权，之后改变项目默认不会撤销它。子 Worker 保持至少自动合并、由直接父 Agent 检查确认，不从项目默认获得自动验收／归档授权；管理型 Worker 不参加 Git 自动链。

Worker 详情的 Hooks 区用一行环节按钮串行配置三个内置 Hook。点击即保存当前 Worker 的最高自动级别，不需另点保存；选择归档还需确认清理范围。高亮与前置环节下划线表示已授权范围，不代表执行完成；执行结果在「管理」中查看。

| 最高级别 | 自动执行 | 下一人工环节提醒 |
|---|---|---|
| 关闭 | 无，保留手动流程 | 原有工作收尾提醒 |
| 自动到合并 | 合并 | 待验收 |
| 自动到验收 | 合并 → 验收 | 待归档 |
| 自动到归档 | 合并 → 验收 → 归档 | 自动成功不告知 |

第 1 步是「本轮交付就绪」，不是每次 Agent 返回：调用实际退出、后代结算、消息和待决处理、Git 检查后，由父 Worker 队列合并。无改动成果经明确交付核验后跳过空 Squash，仍按顺序推进。

第 2 步只复用安全校验并代替用户确认，**不调用质量评审 Agent，也不保证业务质量**。第 3 步复用子树归档：删除分支及后代的 worktree/ref，保留 Worker、会话和历史，不丢弃未提交修改。验收或归档受阻时前面的成功事实不撤销。

- 项目初始关闭新指令自动链，用户可设置新指令默认，也可配置当前指令 Worker 的最高级别，不继承给后代。派生 child 的合并、验收、归档流程 Hook 整体只读：默认自动合并、由直接父 Agent 检查确认，用户不能关闭或提高级别；按钮禁用并说明原因。其他自定义 Hook 仍按原权限管理。
- 级别跨轮保留，与本轮执行收据分开；「已授权」不等于「已发请求」或「已执行」。
- 请求冻结／挂起、自动动作执行、同步或结果未知时不能改当前链。用户指令已合并待验收、已验收未归档时，可以显式提高级别补办，仍核验当前 HEAD、消息、待决、后代与现场。
- 旧自动合并开关保持原门禁；允许关闭时只撤销未来自动触发，不撤回已发请求。历史交付继续原协议。
- 自动成功只留审计和执行记录，不逐阶段发告知；失败、受阻、未知和待决仍提醒，自定义的通知 Hook 不受影响。
- 明确失败／未知结果不自动重试；先检查现场，可通过现有人工验收、归档及显式恢复处理剩余步骤，不用改变级别绕过诊断。

## 可用节点与动作

表单按后台目录限制可选节点和动作，不允许任意组合。当前节点如下：

| 触发节点 | 含义 |
|---|---|
| `agent.started` | 正式开始一次调用 |
| `agent.returned` | 正常返回且实际退出，不等于工作完成 |
| `agent.failed` | 异常、超时或重启发现调用中断，不自动重试 |
| `agent.paused` / `agent.preempted` | 安全暂停／输入抢占已生效，不冒充失败 |
| `worker.delivery_ready` | 本轮交付就绪，退出、消息、待决和后代均收口；合并仍复核 Git |
| `worker.frozen` / `worker.unfrozen` | 整体写门冻结／最后一项冻结原因释放 |
| `worker.parent_ready` | 所挂载父 Worker 通过创建准入，可创建子 Worker |
| `worker.merge_received` | 子 Worker 代码成功合入所挂载父 Worker，每次合并独立触发 |
| `worker.awaiting` / `worker.resumed` | 出现待决／全部待决解除，不代表交付完成 |
| `delivery.integrated` | 源 Worker 交付落地，与父侧收到合并不同 |
| `delivery.suspended` / `delivery.blocked` | 交付挂起释放执行位／未知现场待核验且保留执行位 |
| `worker.accepted` / `worker.cancelled` | 明确验收／取消，不删除历史或代码现场 |
| `time.scheduled` | 按显式时区一次性或每日提交动作，不保证准点开始 |

主动暂停与抢占不是失败；「等待用户」对应待决问题，不是每条普通通知。页面只是读取这些事实，不靠轮询触发 Hook。

每条规则最多四个有序动作，并可限制触发时的 Worker 状态和集成状态：

- **发送通知**：创建信息通知，不调用 Agent；可一次性或持续。
- **发送消息**：只发送给当前 Worker 或直接父子；可能唤醒 Agent。生命周期规则仅一次性防递归；定时可按每日授权重复。
- **创建 Worker**：父可创建安全点的一次性预约，或定时提交；均复核创建安全门，可选择开始 Agent 或仅创建。
- **重试失败／继续暂停**：仅定时节点，显式授权，保留原工作区与上下文，不恢复取消／验收／归档。
- **请求合并**：仅本轮交付就绪，复用既有权限、冻结与交付队列。
- **执行命令**：引用快捷指令目录中明确授权的具体版本，不允许内联 Shell；一次性或持续；当前不允许 `time.scheduled`、`agent.failed`、`worker.accepted`、`worker.cancelled`，其他节点仍需实际目录与安全门通过。真实目录和用户权限见上节，命令业务语义由用户自己负责。
- **自动验收／自动归档**：仅内置串行流程，不允许自定义安装；使用最高自动环节统一授权，不能拆成互相矛盾的开关。

「main 收到合并后 git push」卡片只管理 main 的那一个挂载；编辑／复制通用命令模板不代表全项目启用。模板是尚未挂载的配置，不是全局作用范围，也不以模板的启用字段冒充真实挂载状态。

可能调用 Agent 的规则与按钮带紫色标记和费用说明。配置接口没有任意 RPC、跨项目或跨任意 Worker 的动作；通用命令本身不是系统沙箱，不能据此推断它无法访问别的目录。管理型 Agent 的窄操作授权另按上节核验，不开放给普通开发 Agent。

## 等待、失败与取消

等待中的挂载可停用或移除。预约草稿被占用时不能编辑、删除或重复发射；等待／明确失败状态下停用可释放草稿；仍在等待的挂载重新启用时后台重新核验版本与占用，明确失败需检查后重新授权。父 Worker 已取消或验收后仍可移除未执行的自定义挂载，释放草稿，但不能重新启用结束的 Worker。失败 Worker 的定时自重试是窄授权例外，可挂载／停用定时自重试，不开放其他终态行为。

一次性 Worker Hook 成功执行后自动删除挂载，包括预约发射；执行审计及已创建的 Worker、Input 和草稿发射关联保留。持续 Hook 和模板不删除。后台升级重启时也会清理旧版留下的成功一次性挂载；失败、未知、错过或不适用的项保留诊断。

动作已经开始时不能撤销。明确失败不会自动重试；执行结果未知（例如创建途中 daemon 重启）也不会重放。先核查已有 Worker、worktree 和执行记录；需要恢复时移除旧授权，再显式新建。未知状态仅停用不会释放草稿。移除挂载不删除已经产生的 Worker、代码或消息。

多个合并排队时，runtime 在每次真正释放父执行位后给等待的创建 Hook 一个机会，再推进下一项；正在修复分歧或未知落地仍占位时不会强行解锁。

模型摘要可读，但完整 Prompt、env、运行资源与私有 Hook JSON 不出现在 Worker/API 结果中。CLI / RPC 见 [Hooks 接口](reference/rpc/hooks.md)；维护契约见 [Hooks 工程边界](engineering/hooks.md)与[快捷指令授权](engineering/shortcut-commands.md)。
