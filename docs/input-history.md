# 历史输入与暂存

本文面向使用 Web 或桌面的用户：把尚未决定执行的想法先保存到项目里，随后从「历史输入」找到、修改并发射；也可查找曾经发出的原始指令。

## 主输入框

| 操作 | 效果 |
|---|---|
| Enter /「暂存」 | 保存正文、引用和去向；新建与追加均不调用 Agent |
| 手机软键盘回车 / Shift+Enter | 换行；触屏客户端普通回车不暂存或发送 |
| Ctrl/⌘+Enter /「发射」或「发射追加」 | 可靠挂载当前输入，等待安全准入；不保证立即创建 Worker 或投递消息 |
| Ctrl/⌘+Shift+Enter | 与 Ctrl/⌘+Enter 相同，直接发射当前输入，不打开条件设置 |

默认挂载给 main，也可明确指定其它父 Worker；后台在父真正空闲且安全可写时才创建并开始独立 Worker。冻结、实际调用未退出或独占开发都会延迟准入，不需要反复重发。工作区使用实际创建时的父提交，不在暂存或挂载时锁死代码。

发射确认后留在当前页面，不自动跳到 Worker 详情。「已发射」只表示需求已可靠接住，不表示 Worker 已创建或 Agent 已开始。旧 API 的显式「仅创建」入口仍保留兼容，但不是新发射流程。

暂存成功后才清空本次保存的内容；失败时保留输入。输入法确认候选文字不触发暂存。

暂存是项目级持久记录，不是当前浏览器内存中的便签，也不是会自动执行的队列。切换项目后，应回到原项目查看该项目的想法。

手机端顶部常驻一行项目／页面身份与「导航菜单」，展开后以两列等高卡片跳转页面；菜单可独立滚动，跳转或按 Esc 后收起。输入框下方默认一行常用操作，不提供条件发射入口；历史输入与运行设置通过「更多」展开，桌面入口不变。

手机／触屏客户端用回车换行，点击「暂存」「发射」明确提交；连接键盘后仍可用 Ctrl/⌘ 组合快捷键。桌面普通 Enter 在新建与追加模式中都暂存。主输入的「撤销」「重做」默认隐藏，点击「更多」展开后显示（新建与追加模式均可用）；历史暂存正文旁仍直接显示这两个按钮。它们与 Ctrl/⌘+Z、Ctrl/⌘+Shift+Z、Ctrl+Y 共用本页文字编辑历史；不撤销引用、父 Worker、设置、保存或发射请求。主输入提交成功并清空后清除这条文字历史，失败或在途新编辑保留；历史暂存保存后仍可撤销文字编辑，再保存才更新服务器，不回退版本号。离开历史输入页后重开或刷新页面不保留撤销历史。

输入框聚焦时自动增高，失焦后缩回单行；窄屏按软键盘打开后的可视区域定位，尽量同时露出输入与操作区；极矮窗口优先露出正文，浏览器不提供可视区域接口时按窗口高度定位。缩放阅读时不强制滚动。长内容可在框内滚动，不会因缩回丢失。整个输入区域统一染上项目色，去掉外层框，只通过输入框本身的边框区分去向：**实线「＋ 新建独立 Worker」**显示父 Worker、独立工作区与 Enter 暂存；**虚线「↳ 继续当前 Worker」**将「追加到 Worker 编号 · 标题」作为独立的加粗目标条，显示不创建新 Worker 与 Enter 暂存。两种模式都沿用项目配色，实线表示默认输入，虚线表示临时追加；聚焦时边框加粗，仍保留原线型，不再套第二圈框。打字、收起更多选项后提示仍然可见；不可输入时保留目标、原位显示原因。浅色、深色和窄屏都不靠颜色判断输入去向。

打开 Worker 详情不会改变底部输入框的默认功能，仍用于**新建独立 Worker**。点击具体 指令/child 详情的「向该 Worker 追加输入」，或 Worker 树菜单的「追加输入」，才将底部输入框切换为追加模式，不弹窗、不立即发送：桌面 Enter 暂存追加，Ctrl/⌘+Enter、Ctrl/⌘+Shift+Enter 或「发射追加」可靠挂载；手机回车与 Shift+Enter 换行，父选择隐藏，暂存仍可用。追加被服务端确认挂载后自动回到新建模式，不等待 Agent 处理；冻结期间仍可挂载后等待。失败则保留追加目标与原文；若等待确认期间改过正文／引用或主动切换过目标，仍保留当前模式和未发送内容。下一次 Enter 按恢复后的新建模式暂存，不会继续追加。也可点击「回到新建 Worker」，或输入空白且无引用时按 Esc，可恢复默认模式；切换保留正文、引用与显式选择的父 Worker。离开当前页面也退出追加模式；树页发送后仍留在树页，不自动打开详情。暂停中的 Worker 收到消息后仍需显式「开始 / 继续」。追加目标被冻结时仍可发送：输入先可靠保存在该 Worker 的收件箱，由 Worker 暂存，不打断当前合并或解分歧；当前交付收口、整体解冻且 Agent 实际退出后再投递。界面显示暂存条数与等待原因，「已保存，等待投递」不代表 Agent 已收到。未处理输入会阻止验收、归档；如果交付卡住或 Worker 仍暂停／等待决策，输入保留，不要求用户反复重发。目标已结束、归档或不支持追加时，保留目标、禁用输入并说明原因，不静默改投 main，返回默认模式的按钮仍可用。

追加消息接口暂不支持引用附件；有引用时发送会明确拒绝并保留正文与引用，可移除引用后追加，或点击「回到新建 Worker」创建带引用的新 Worker。

## 找到与执行想法

打开工作分组的「历史输入」：

- 「新建 Worker」「追加输入」「管理 Lush」三种色块可独立勾选，勾选哪些就显示哪些模式的历史；多选取并集，全不选不显示记录。默认三种全选、Worker 状态与合并状态均为全部。
- 搜索针对本项目全库输入正文，包含原始 Input、草稿、可确认来源的用户追加消息及主输入框提交的管理输入，不限于当前页或首页最近 Worker。定时信号管理与系统消息不收录；旧缺少可信用户来源的追加消息保留在 Worker 中，不猜测归类。
- 模式与 Worker／合并状态筛选即时生效，不应用尚未提交的关键词；关键词用 Enter 或「搜索」提交。可继续加载更早记录，只找草稿时将 Worker 状态切换为「暂存」。
- 列表条目等高，只显示两行正文摘要、编号、时间及Worker/合并状态；点击整条输入进入独立详情，不再左右分栏。
- 详情的「返回历史输入」或浏览器后退会保留本次页面的搜索、筛选、已加载记录和列表位置。返回列表不会丢弃当前草稿编辑，重新打开同一条可继续编辑；切换到另一条时，会先确认是否放弃未保存修改。
- 打开暂存条目可以编辑原文、调整父 Worker、移除引用，或删除不再需要的想法。
- 「保存」在正文、去向、条件、独占选项或引用不同于已保存内容时亮起；恢复原值或保存成功后变灰。运行设置仅在发射时保存，不单独启用草稿保存按钮。
- 草稿详情支持 Ctrl/⌘+S 保存，以及已有的撤销／重做快捷键；普通 Enter 换行，不设发射快捷键。快捷键与按钮共用单次请求保护，保存失败保留编辑。
- 条件发射只在草稿详情设置：点击低调的「条件发射设置」才展开 Worker 条件、静息与独占选项；默认收起，收起不会清除设置。已配置时入口简要标注条件数量／独占，发射按钮显示「按条件发射」，避免误以为立即执行。
- 「发射」或「按条件发射」先挂载当前版本，实际新建会自动开始；追加复用目标的运行设置。新建可单独设置模型等运行参数。
- 挂载中的草稿只读，不能编辑、删除或重复发射。详情可「撤销条件发射」恢复尚未执行的草稿；已经执行或结果未知不能撤回或盲目重发。
- 实际创建成功后，可跳到真实原始 Input 与 Worker；没有 Input 时仍展示草稿及发射收据，不虚构 O 编号。独占草稿保留「释放独占」入口，释放不取消 Worker、不删除成果。追加草稿保留真实 Message/A 编号收据，不创建另一条原始 Input。

每次只发射当前选中的一条，不会把其它想法一起执行。新建成功关联原始 Input 后列表不重复显示源草稿；挂载等待和追加草稿仍可从历史输入中查找，已发送追加草稿与其 Message 不重复显示。普通用户追加消息与管理输入可在历史页查看只读原文，并跳转来源 Worker／Valet。

## 条件与管理输入

条件为**全部满足**：可添加 Worker「工作安全收尾」「本轮成果已合入 main」，或「等待目标树彻底静息」。工作收尾不是一次 Agent 返回；child 仅合入直接父 Worker也不等于已进入 main。静息等待包括暂停、失败、待开始、未合并开发工作和在途交付；已合并且无新工作、静息待验收的 Worker 不阻塞。已安全交付的无代码结果不需要虚构合并；取消但有脏现场的工作仍阻塞。

「独占开发」先等待项目静息，再暂缓其它开发创建和调用，直到本轮安全交付收口；自己的后代、管理、查询和交付仍可进行。它不是自动合并授权，失败、暂停或待决可能长期占用。详情显示可释放入口，只撤销后续独占意愿，保留成果与未知诊断。

主输入「管理 Lush」切换为当前项目的独立管理 Agent：例如分析运行记录，或将“W123 合入 main 后进行 xxx”保存为条件草稿。提交管理需求会调用 Agent，但不创建开发 Worker、Git 分支或 O 输入；可打开最近管理记录。管理模式 Enter 提交，手机回车换行；不提供开发暂存／条件按钮。仅已审核的查询、草稿、发射等能力自动执行；取消、合并、验收回收、删除、敏感设置等必须在待决问卷中由用户确认精确请求。没有任意文件／Shell 工具，不读取凭证、不跨项目；设备操作必须明确提出。运行诊断读取安全调用摘要，不读取原始提示词或工具内容。不可用能力会说明需转至用户界面。

## 编号与跳转

原始输入使用 `O190` 这样的编号；Worker 详情头部、版本历史及正文中的 O 编号可点击打开完整原文，不跳到关联 Worker，也不受历史列表当前筛选限制。暂存仍显示草稿 #编号，Worker 追加消息不另占 O 编号。

用户决定使用 `D454`，纯告知使用 `N455`（历史 plan 也用 D，未知类型保守用 N）。正文中的 W/D/N/O 编号显示蓝色下划线链接，支持键盘和新标签打开；D/N 打开原事项及问卷／答案，导航不会自动答复或标已读。全局收件箱链接保留来源项目，不把另一个项目的同号记录混在一起。代码块、已有链接和编辑区不自动转换；历史原文、引用快照及整数 ID 不改写，旧数字书签仍可使用。

## 状态如何理解

| 主状态 | 含义 |
|---|---|
| 暂存 | 尚未授权发射的想法 |
| 等待条件、已发射 | 已挂载，等待条件或安全准入；还没有新 Worker／追加消息 |
| 已追加 | 已持久投递到目标收件箱，不保证 Agent 已处理 |
| 发射失败、发射结果待核验 | 明确失败或开始后结果未知；未知不得自动重放 |
| 已创建／待开始 | 已创建 Worker，尚未调用 Agent |
| 排队中、执行中 | 等待执行槽或正在运行 |
| 等待中、待处理、已暂停 | 等待后续工作、用户决策或显式继续；不是失败 |
| 待验收 | 本轮交付后等待确认，不等于代码尚未合并 |
| 已完成 | Worker已确认收口，不保证有代码改动 |
| 失败、已取消 | 执行失败或明确放弃，原始输入仍保留 |
| 状态未知 | 历史关联 Worker 缺失或无法确认，不假定成功 |

合并状态单独显示，例如「合并中」「合并受阻」「已合并」。因此同一条输入可以同时是「待验收」与「已合并」。归档也不等于删除历史。

## 父 Worker 与并发编辑

暂存会保存当时的父 Worker；主输入框默认显式指定 main，不随项目检出分支改变。在任意页面（含 main/owner 详情）展开输入区仍可选择其它父 Worker；打开详情不会自动更改父 Worker。以后切换分支不会让暂存想法静默改投其它Worker。父Worker已结束、归档或暂时不可写时，发射可能被拒绝；草稿保留，可重选父 Worker 或处理阻塞后再试。

保存想法时不冻结代码：工作区从**实际创建时**父分支已提交的代码创建，未提交修改不随输入带入。旧版草稿没有保存父身份时，需要先明确选择并保存。

多标签页编辑同一条暂存会检查版本。冲突时不会覆盖另一处保存的内容；先复制保留自己的修改，再刷新页面读取最新版本并整理。详情不再提供单独的「重新读取详情」按钮，刷新列表仍不会覆盖本地编辑。网络失败也不应通过连续点击重复创建Worker，可刷新历史确认是否已发射。

更多执行与验收规则见[一条指令输入如何交付](task-flow.md)。
