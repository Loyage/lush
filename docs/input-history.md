# 历史输入与暂存

本文面向使用 Web 或桌面的用户：把尚未决定执行的想法先保存到项目里，随后从「历史输入」找到、修改并发射；也可查找曾经发出的原始指令。

## 主输入框

| 操作 | 效果 |
|---|---|
| Enter /「暂存」 | 保存正文、引用和父 Worker，不创建Worker、不调用 Agent |
| 手机软键盘回车 / Shift+Enter | 换行；触屏客户端普通回车不暂存或发送 |
| Ctrl/⌘+Enter /「仅创建」 | 创建「待开始」Worker，可配置 Agent 后再开始 |
| Ctrl/⌘+Shift+Enter /「发射并开始」 | 创建 Worker 并开始执行，忙碌时等待执行槽 |

main 或所选父分支冻结时，两按钮分别变为「预约仅创建」和「预约发射并开始」；Ctrl/⌘+Enter 预约仅创建，Ctrl/⌘+Shift+Enter 预约创建并开始。现在只保存指令、引用与完整运行设置，首个可创建安全点才使用当时父提交创建工作区。完整规则见 [Worker Hooks 与预约发射](hooks.md)。

创建、立即开始或预约发射后留在当前页面，不自动跳到 Worker 详情。仅创建的 Worker 真正创建成功后会发出「待开始」告知；可以从告知主动查看 Worker、配置并手动开始，也可以点「已知」留在原页，不会启动 Agent。预约尚未创建时不发待开始告知；立即开始不发此告知。提醒渠道可在「设置 → 界面」独立调整。

暂存成功后才清空本次保存的内容；失败时保留输入。输入法确认候选文字不触发暂存。

暂存是项目级持久记录，不是当前浏览器内存中的便签，也不是会自动执行的队列。切换项目后，应回到原项目查看该项目的想法。

手机／触屏客户端用回车换行，点击「暂存」「仅创建」「发射并开始」明确提交；连接键盘后仍可用 Ctrl/⌘ 组合快捷键。桌面普通 Enter 保持暂存／追加的原有行为。主输入与历史暂存正文旁均有「撤销」「重做」，与 Ctrl/⌘+Z、Ctrl/⌘+Shift+Z、Ctrl+Y 共用本页文字编辑历史；不撤销引用、父 Worker、设置、保存或发射请求。主输入提交成功并清空后清除这条文字历史，失败或在途新编辑保留；历史暂存保存后仍可撤销文字编辑，再保存才更新服务器，不回退版本号。重新读取或重开页面不保留撤销历史。

输入框聚焦时自动增高，失焦后缩回单行；窄屏按软键盘打开后的可视区域定位，尽量同时露出输入与操作区；极矮窗口优先露出正文，浏览器不提供可视区域接口时按窗口高度定位。缩放阅读时不强制滚动。长内容可在框内滚动，不会因缩回丢失。整个输入区域统一染上项目色，去掉外层框，只通过输入框本身的边框区分去向：**实线「＋ 新建独立 Worker」**显示父 Worker、独立工作区与 Enter 暂存；**虚线「↳ 继续当前 Worker」**将「追加到 Worker 编号 · 标题」作为独立的加粗目标条，显示不创建新 Worker 与 Enter 追加。两种模式都沿用项目配色，实线表示默认输入，虚线表示临时追加；聚焦时边框加粗，仍保留原线型，不再套第二圈框。打字、收起更多选项后提示仍然可见；不可输入时保留目标、原位显示原因。浅色、深色和窄屏都不靠颜色判断输入去向。

打开 Worker 详情不会改变底部输入框的默认功能，仍用于**新建独立 Worker**。点击具体 指令/child 详情的「向该 Worker 追加输入」，或 Worker 树菜单的「追加输入」，才将底部输入框切换为追加模式，不弹窗、不立即发送：桌面 Enter、底部「追加输入」按钮与 Ctrl/⌘+Enter 均向该 Worker 追加发送；手机回车与 Shift+Enter 换行；暂存与父选择隐藏。追加被服务端确认保存后自动回到新建模式，不等待 Agent 处理；冻结期间确认「已保存，等待投递」也会返回。失败则保留追加目标与原文；若等待确认期间改过正文／引用或主动切换过目标，仍保留当前模式和未发送内容。下一次 Enter 按恢复后的新建模式暂存，不会继续追加。也可点击「回到新建 Worker」，或输入空白且无引用时按 Esc，可恢复默认模式；切换保留正文、引用与显式选择的父 Worker。离开当前页面也退出追加模式；树页发送后仍留在树页，不自动打开详情。暂停中的 Worker 收到消息后仍需显式「开始 / 继续」。追加目标被冻结时仍可发送：输入先可靠保存在该 Worker 的收件箱，由 Worker 暂存，不打断当前合并或解分歧；当前交付收口、整体解冻且 Agent 实际退出后再投递。界面显示暂存条数与等待原因，「已保存，等待投递」不代表 Agent 已收到。未处理输入会阻止验收、归档；如果交付卡住或 Worker 仍暂停／等待决策，输入保留，不要求用户反复重发。目标已结束、归档或不支持追加时，保留目标、禁用输入并说明原因，不静默改投 main，返回默认模式的按钮仍可用。

追加消息接口暂不支持引用附件；有引用时发送会明确拒绝并保留正文与引用，可移除引用后追加，或点击「回到新建 Worker」创建带引用的新 Worker。

## 找到与执行想法

打开工作分组的「历史输入」：

- 搜索针对本项目全部原始输入正文与未发射的暂存内容，不限于当前页或首页最近Worker。
- 默认只显示「暂存」状态的输入；需要查看已发出的历史时，主动将Worker状态筛选切换为「全部」或目标状态。也可按合并状态筛选，并继续加载更早记录。
- 列表条目等高，只显示两行正文摘要、编号、时间及Worker/合并状态；点击整条输入进入独立详情，不再左右分栏。
- 详情的「返回历史输入」或浏览器后退会保留本次页面的搜索、筛选、已加载记录和列表位置。返回列表不会丢弃当前草稿编辑，重新打开同一条可继续编辑；切换到另一条或重新读取时，会先确认是否放弃未保存修改。
- 打开暂存条目可以编辑原文、调整父 Worker、移除引用，或删除不再需要的想法。
- 「发射并开始」创建一个独立指令 Worker 并调用 Agent；「仅创建」先创建待开始 Worker。父冻结时可显式预约这两种模式，并设置模型等完整运行参数。
- 预约占用的草稿只读，不能重复发射。详情可查看父 Hooks 或取消未执行挂载；等待／明确失败状态停用也可释放草稿，执行未知时须检查现场后移除，不重放。
- 发射后原文只读，并可跳到对应 Worker。继续修改需求请向 Worker 追加输入，不改写原始历史。

每次只发射当前选中的一条，不会把缓冲区里的其它想法一起执行。发射成功后，条目作为原始输入保留，不再重复显示一条暂存记录。Worker 内的追加消息不混在本页中，仍从对应Worker查看。

## 编号与跳转

原始输入使用 `O190` 这样的编号；Worker 详情头部、版本历史及正文中的 O 编号可点击打开完整原文，不跳到关联 Worker，也不受历史列表默认「暂存」筛选限制。暂存仍显示草稿 #编号，Worker 追加消息不另占 O 编号。

用户决定使用 `D454`，纯告知使用 `N455`（历史 plan 也用 D，未知类型保守用 N）。正文中的 W/D/N/O 编号显示蓝色下划线链接，支持键盘和新标签打开；D/N 打开原事项及问卷／答案，导航不会自动答复或标已读。全局收件箱链接保留来源项目，不把另一个项目的同号记录混在一起。代码块、已有链接和编辑区不自动转换；历史原文、引用快照及整数 ID 不改写，旧数字书签仍可使用。

## 状态如何理解

| 主状态 | 含义 |
|---|---|
| 暂存 | 尚未创建 Worker 的想法 |
| 已创建／待开始 | 已创建 Worker，尚未调用 Agent |
| 排队中、执行中 | 等待执行槽或正在运行 |
| 等待中、待处理、已暂停 | 等待后续工作、用户决策或显式继续；不是失败 |
| 待验收 | 本轮交付后等待确认，不等于代码尚未合并 |
| 已完成 | Worker已确认收口，不保证有代码改动 |
| 失败、已取消 | 执行失败或明确放弃，原始输入仍保留 |
| 状态未知 | 历史关联 Worker 缺失或无法确认，不假定成功 |

合并状态单独显示，例如「合并中」「合并受阻」「已合并」。因此同一条输入可以同时是「待验收」与「已合并」。归档也不等于删除历史。

## 父 Worker 与并发编辑

暂存会保存当时的父 Worker；主输入框默认显式指定 main，不随项目检出分支改变。在任意页面（含 main/owner 详情）展开输入区仍可选择其它父 Worker；打开详情不会自动更改父 Worker。以后切换分支不会让暂存想法静默改投其它Worker。父Worker已结束、归档或暂时不可写时，发射可能被拒绝；草稿保留，可重选父 Worker 或处理阻塞后再试。

保存想法时不冻结代码：工作区从**发射时**父分支已提交的代码创建，未提交修改不随输入带入。旧版草稿没有保存父身份时，需要先明确选择并保存。

多标签页编辑同一条暂存会检查版本。冲突时不会覆盖另一处保存的内容；先保留自己的修改，再重新读取最新版本并整理。网络失败也不应通过连续点击重复创建Worker，可刷新历史确认是否已发射。

更多执行与验收规则见[一条指令输入如何交付](task-flow.md)。
