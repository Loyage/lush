# 历史输入与草稿

本文面向使用 Web 或桌面的用户：「草稿」保存暂缓的工作与追加输入，管理去向和执行条件；「历史输入」只检索已经发送的原话及时间，不混入尚未发送的想法。

## 三种输入方式

| 模式 | 内容名称 | 去向与作用 |
|---|---|---|
| 新建工作 | 工作指令 | 基于所选父 Worker 的分支创建新 Worker，启动独立工作 |
| 追加输入 | 追加指令 | 给指定 Worker 补充要求或反馈，不创建新 Worker |
| 管理 Lush | 管理指令 | 交给当前项目管家（Valet），查询、调整和安排工作 |

三者统称「输入」。默认只显示右下角圆形入口，点击展开文字菜单，选择模式后打开输入面板。面板常显项目、模式及去向，打字或收起高级设置不会隐藏目标；正文提示只帮助组织内容。不同模式和目标分别保留编辑，切换不把原文字、引用或设置改投给另一目标，也不提交或调用 Agent。三类输入均支持当前浏览器内的自动保存；只有工作指令与追加指令支持项目草稿，管理指令暂不支持项目草稿。

「暂存」保存尚未授权执行的草稿，不创建 Worker、不投递消息、不调用 Agent。「提交」保存执行授权，不保证立即开始；「按条件提交」也是现在提交授权，然后等待条件满足及安全准入。它们不是三个不同的执行引擎，内部 Input、Message、Draft、RPC 和历史编号不因此改名。

## 主输入框

| 操作 | 效果 |
|---|---|
| Enter | 新建模式暂存草稿；追加模式直接提交追加指令 |
| 「暂存」 | 新建与追加模式保存正文、引用和去向为草稿，不调用 Agent |
| 手机软键盘回车 / Shift+Enter | 换行；触屏客户端普通回车不暂存或提交 |
| Ctrl/⌘+Enter /「提交新工作」「提交追加」「提交管理指令」 | 按当前去向提交；恢复的条件草稿显示「按条件提交」，保留原条件授权 |
| Ctrl/⌘+Shift+Enter | 与 Ctrl/⌘+Enter 相同，不打开条件设置 |

管理模式普通 Enter 换行，不提交。输入法确认候选文字也不触发暂存或提交。

新建工作默认父 Worker 为 main，也可展开「高级设置」明确选择其它父 Worker、查看或更改执行环境；更换父 Worker 打开该去向的独立编辑，不携带原内容改投。执行环境信息和按钮默认隐藏，收起保留本条选择。后台在父真正空闲且安全可写时才创建并开始独立 Worker。冻结、实际调用未退出或独占开发都会延迟准入，不需要反复重发。工作区使用实际创建时的父提交，不在暂存或提交授权时锁死代码。

提交确认后留在当前页面，不自动跳到 Worker 详情。「已提交」只表示授权已可靠保存，不表示 Worker 已创建或 Agent 已开始。旧 API 的显式「仅创建」入口仍保留兼容，但不是提交授权流程。

手动暂存（按钮或新建模式 Enter）及提交成功后才清空本次确认的内容，并清除对应的自动恢复内容；恢复草稿后的「保存暂存」更新同一条记录后也清空，下次打开不会自动加载，可主动从草稿续写。失败与请求期间新编辑的正文、引用保留。暂存是项目级持久记录，不是当前浏览器内存中的便签，也不是自动执行队列。切换项目后，应回到原项目查看草稿。

手机端顶部常驻项目／页面身份与「导航菜单」，展开后以两列等高卡片跳转页面；菜单可独立滚动，跳转或按 Esc 后收起。输入面板在底部停靠，为上方阅读区留出空间，不使用遮罩；窄屏按钮可换行，不缩小触控区域。默认突出去向、正文、暂存续写和提交；草稿页、历史输入、运行设置与编辑工具通过「高级设置」展开。触屏回车换行，使用可见按钮提交；连接键盘后仍可用 Ctrl/⌘ 组合快捷键。

点击面板右上角圆形收起按钮，或在正文按 Esc，收起面板和软键盘，自动保存文字、引用、设置与位置到当前浏览器。再次点击右下角圆形入口，从菜单选择类别后自动恢复该项目、模式和目标的上次未完成输入；不自动加载已手动暂存的内容。未完成编辑有状态点。导航也会收起并自动保存，保留原输入目标，不跟随新页面改投；没有当前 Worker 时，菜单仍可明确选择原先绑定的追加目标。自动保存可跨同一浏览器的刷新或重开，但不进入项目草稿、不跨设备；浏览器存储失败会提示，刷新前须手动暂存或复制原文。

主输入的「撤销」「重做」默认隐藏，点击「高级设置」后显示；草稿详情正文旁直接显示。它们与 Ctrl/⌘+Z、Ctrl/⌘+Shift+Z、Ctrl+Y 共用本页文字编辑历史，不撤销引用、父 Worker、设置、保存或提交请求。主输入成功消费并清空后清除这条文字历史，失败或在途新编辑保留；草稿保存后仍可撤销文字编辑，再保存才更新服务器，不回退版本号。离开草稿页后重开或刷新页面不保留撤销历史；未保存编辑离页前须确认。

选择类别后直接打开大输入框，长内容可在框内滚动，不再提供「扩大编辑」或「切换方式」按钮；改类别先收起，再从圆形入口菜单选择。窄屏按软键盘打开后的可视区域定位，优先露出目标、正文与主要操作；键盘打开且正文聚焦时临时隐藏高级展示，不丢设置。极矮窗口可收起回看再恢复，无可视区域接口时按窗口高度定位，缩放阅读时不强制滚动。输入区域沿用项目配色，不套外层框：实线「＋ 新建工作」表示默认创建，虚线「↳ 追加输入」表示临时追加；目标条常驻加粗，聚焦保留线型。浅色、深色和窄屏都不只靠颜色判断去向；不可输入时保留目标、原位显示原因。

## 就地继续暂存

空编辑器可点「继续最近暂存」，查找本项目同模式、同目标的最近可编辑草稿：新建匹配父 Worker，追加匹配目标 Worker。不只查第一页；读取失败会说明未能确认，不冒充没有草稿。「选择其他暂存」在面板内列出同去向的其它草稿及本页未完成编辑，不离开正在阅读的页面。

恢复保留原草稿身份、版本、正文、引用、去向、条件与独占设置。「保存暂存」或 Ctrl/⌘+S 更新原草稿，不重复新增；提交使用该草稿的精确保存版本。带条件的草稿显示摘要与「按条件提交」，条件仍到草稿页修改。主面板不直接改投恢复的草稿；如需换目标，到草稿页显式更改。

切换草稿会保留当前本页编辑，可从同一选择列表找回，不直接覆盖。已授权等待、结果未知、已发送或版本不完整的记录不能作为普通草稿续写；版本冲突保留本地内容，不自动覆盖服务器。管理指令没有项目级暂存续写入口。

## 给已有 Worker 追加

打开 Worker 详情不会自动选择追加，也不会把已有内容转成新工作。可以从圆形入口选择追加当前 Worker，或点击具体指令／child、工作树菜单中的「追加输入」；只有明确选择才打开该目标的独立编辑。父选择隐藏，暂存仍可用，不立即提交。

桌面 Enter、Ctrl/⌘+Enter、Ctrl/⌘+Shift+Enter 或「提交追加」可靠保存执行授权，暂存追加只使用「暂存」按钮；手机回车与 Shift+Enter 换行。服务端确认后恢复新建工作模式，不等待 Agent 处理；失败保留追加目标与原文。如果确认期间编辑了正文／引用或主动切换目标，仍保留当前模式和未提交内容。下一次 Enter 按恢复后的模式暂存，不继续追加。

「回到新建工作」恢复默认 main 去向的独立编辑，追加内容留在原目标，不带入新建。离开当前页面只收起面板，不改变追加目标；Esc 也只是收起。树页提交后仍留在树页，不自动打开详情。暂停中的 Worker 仍需显式「开始 / 继续」后处理消息。

冻结期间合法追加可以可靠入箱，但不打断当前合并或源侧修复；交付收口、整体解冻且 Agent 实际退出后再交付。界面显示「已入箱 … 条追加指令，待交付给 Agent」和等待原因，不把入箱说成 Agent 已收到。未处理输入会阻止验收和归档；卡住、暂停或等待决策时保留输入，不要求反复重发。目标已结束、归档或不支持追加时保留目标、禁用并说明，不静默改投 main。

追加指令暂不支持引用附件；添加或提交不支持的引用会明确拒绝，不静默丢弃原文与附件。需要引用时，先显式切换到新建工作的独立编辑，再添加引用，不把追加正文自动带入新建。

## 查找已发送批示

打开工作分组的「历史输入」，按实际发送时间倒序查找原文：

- 默认显示全部已发送的「新建工作」「追加输入」「管理 Lush」。三种模式独立多选，全不选不显示记录；Worker／合并状态位于默认收起的「高级筛选」。
- 全库搜索真实原始 Input、可确认用户来源的追加 Message、主输入框提交的管理指令，不限于当前页或最近 Worker。定时管理、系统通信及缺少可信来源的旧消息不收录，不猜测归类。
- 列表显示正文摘要、真实编号、指令类型、时间与独立 Worker／合并状态；点击查看只读原文及来源 Worker／Valet，不改写旧批示。
- 关键词用 Enter 或「搜索」提交；模式／状态即时筛选，但不应用尚未提交的关键词。「清空」立即清除已应用关键词，保留其它筛选。可分页加载更早记录；返回列表保留查询、分页和位置。

## 管理暂缓输入

打开独立「草稿」页，选择「工作暂存」或「追加输入暂存」；每次只显示一个分类。列表常显正文、去向、条件摘要及等待／失败／未知状态，支持该分类全库搜索与暂存状态筛选。这里不显示已成功发送的源草稿，也不暂存管理指令。

- 点击一条进入详情；「返回草稿」或浏览器后退保留查询、分页、位置及本地编辑，再打开同一条可继续。切换条目或离开有未保存编辑的页面前须确认。
- 可编辑草稿正文、父 Worker 或追加目标、条件、独占选项与引用，也可删除未提交草稿。不可用目标必须显式重选，不会改投其它 Worker。
- 「保存」在正文、去向、条件、独占或引用有变化时亮起；恢复原值或保存成功后变灰。运行设置仅在提交时写入，不单独启用保存按钮。
- 草稿详情支持 Ctrl/⌘+S 保存和正文撤销／重做；普通 Enter 换行，不设提交快捷键。快捷键和按钮共用单次请求保护，保存失败保留编辑。
- 详情默认展示正文、去向与执行条件，快捷导入和手动添加直接可见；可通过「执行条件设置」收起，收起保留设置。独占／静息高级项和运行参数按需展开，已有条件数量／独占仍有摘要，配置后动作显示「按条件提交」。
- 宽屏左侧设置条件、右侧展示已有条件卡片；窄屏按设置区、已有条件区上下排列。快捷导入和手动添加常驻，静息／独占在「高级设置」中按需展开，启用状态仍在摘要和卡片显示。可逐项移除；移除显式静息条件不会关闭独占隐含的静息要求，独占需单独关闭。
- 提交先挂载当前版本的授权，实际新建会自动开始；追加复用目标的运行设置，新建可单独设置模型等运行参数。已提交草稿只读，不能编辑、删除或重复提交。
- 「撤销提交」仅恢复尚未执行的草稿；已经执行或结果未知不能撤回或盲目重发。原有预约 Hook 的草稿仍走其受检取消入口。
- 实际创建 Input 或追加 Message 已入箱后才归入历史，源草稿不再重复列出；没有真实身份时只展示草稿及授权收据，不虚构 O／A 编号。追加已入箱不表示 Agent 已收到或处理。
- 历史原文通过明确来源的「查看提交草稿 · 条件与独占」回看收据；成功收据提供「查看已创建原文」或「查看已入箱追加原文」。独占仍有合法释放入口，释放不取消 Worker、不删除成果。

每次只提交当前一条，不把其它草稿一起执行。等待条件／准入、失败与未知结果仍在对应暂存分类；授权后只读，不能编辑、删除或重复发送。页面拆分不迁移、删除或重写既有记录。

## 条件与管理指令

条件必须全部满足：可添加 Worker「工作安全收尾」「本轮成果已合入 main」，或等待目标树彻底静息。工作收尾不是一次 Agent 返回；child 仅合入直接父 Worker 也不等于已进入 main。静息等待包括暂停、失败、待开始、未合并开发工作和在途交付；已合并且无新工作、静息待验收的 Worker 不阻塞。已安全交付的无代码结果不需要虚构合并；取消但有脏现场仍阻塞。

在草稿详情的执行条件区，可点击「等当前所有Worker开发完」：读取 main 的全部直接子开发 Worker，把尚未走完合并环节的项追加为「本轮成果已合入 main」条件，不限于运行中，不包含孙级 Worker 或 Valet。已合并的项和已安全交付的无代码成果不会导入，与是否验收无关；新一轮尚未交付的开发仍会导入。已有条件保留并去重，之后新建的 Worker 不自动加入；该按钮不提交草稿、不授权或执行合并。读取失败或导入后超过 16 项上限（含独占隐含静息）时整批不导入，原条件保留。暂停、失败或取消等尚未合并的项也可能被导入；不再继续的工作可手动移除条件。

「独占开发」先等待项目静息，再暂缓其它开发创建和调用，直到本轮安全交付收口；自己的后代、管理、查询和交付仍可进行。它不是自动合并授权，失败、暂停或待决可能长期占用。「释放独占」只撤销后续独占意愿，保留成果与未知诊断。

「管理 Lush」把管理指令交给独立管家（Valet）：例如分析运行记录，或将“W123 合入 main 后进行 xxx”保存为条件草稿。提交会调用管家，但不会直接创建开发 Worker、Git 分支或 O 输入；管家后续受控操作可能创建开发工作，操作结果单独记录。可点击「查看最近管理记录」。当前管理模式支持收起时保存到当前浏览器，不支持项目草稿、条件按钮或引用附件；普通 Enter 换行，Ctrl/⌘+Enter 或「提交管理指令」提交。

管家可通过既有草稿和条件接口查询两类暂存、调整条件并安排提交，仍沿用相同版本与准入保护，不新增跨项目调度能力。只有已审核的查询、草稿、提交等能力可自动执行；取消、合并、验收回收、删除、敏感设置等须用户在问卷中确认精确请求。管家没有任意文件／Shell 工具，不读取凭证、不跨项目，设备操作须明确提出。运行诊断读取安全调用摘要，不读取原始提示词或工具内容；不可用能力会说明需转至用户界面。

## 编号与状态

原始输入记录在界面称「原始指令」，使用 `O190` 等真实 Input 编号。Worker 头部、版本历史及正文中的 O 链接打开完整原文，不跳到关联 Worker，也不受历史列表当前筛选限制。草稿仍用 `草稿 #编号`，追加消息使用真实 A 编号，不另占 O 编号。

用户决定使用 `D454`，纯告知使用 `N455`（历史 plan 也用 D，未知类型保守用 N）。W／D／N／O 链接支持键盘及新标签；D／N 打开原事项与问卷／答案，不自动答复或标已读。全局链接保留来源项目，代码块、已有链接和编辑区不自动转换。历史原文、引用快照与整数身份不改写，旧数字书签仍可用。

| 主状态 | 含义 |
|---|---|
| 草稿 | 已暂存，尚未授权执行 |
| 已提交 · 等待条件／等待准入 | 已保存授权，尚未创建新 Worker 或投递追加消息 |
| 正在投递／已投递 | 正在执行投递或已有投递收据，不代表工作完成或 Agent 已处理 |
| 追加指令已入箱 | 已持久投递到目标收件箱，不保证 Agent 已收到或处理 |
| 提交后投递失败／投递结果待核验 | 明确投递失败或结果未知；未知不得自动重放 |
| 已创建·待开始 | 已创建 Worker，尚未调用 Agent |
| 排队中／执行中 | 等待执行槽或正在运行 |
| 等待中／待处理／已暂停 | 等待后续工作、用户决策或显式继续，不是失败 |
| 待验收 | 本轮交付后等待确认，不等于尚未合并 |
| 已完成 | Worker 已确认收口，不保证有代码改动 |
| 失败／已取消 | Worker 执行失败或明确放弃，原始指令仍保留 |
| 状态未知 | 历史关联缺失或无法确认，不假定成功 |

合并状态单独显示，例如「合并中」「合并受阻」「已合并」，可与「待验收」同时成立。归档不等于删除历史。

## 父 Worker 与并发编辑

暂存保存当时父 Worker 身份；主输入默认显式 main，不随项目检出分支或当前详情改变。在任意页面（含 main／owner 详情）都可展开输入区选择其它父 Worker。父已结束、归档或暂时不可写时，提交可能被拒绝或等待准入，草稿保留，须重选或处理阻塞，不自动改投。

保存想法不冻结代码：工作区从实际创建时父分支已提交代码创建，未提交修改不随输入带入。旧草稿没有父身份时须先明确选择并保存。

多标签编辑检查版本，冲突不覆盖另一处保存的内容；先复制保留本地修改，再刷新读取最新版本并整理。详情不提供单独重新读取按钮，列表刷新也不覆盖本地编辑。网络失败不要连续点击重复创建 Worker，可到「草稿」确认等待中的授权收据，或到「历史输入」确认实际发送的原文。

更多执行与验收规则见[一条指令输入如何交付](task-flow.md)。
