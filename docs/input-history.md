# 历史输入与草稿

「草稿」保存尚未授权执行的工作、追加与管理输入；「历史输入」检索已经发送的原话及时间。保存不创建 Worker、不投递消息、不调用 Agent。

## 三种输入方式

| 模式 | 去向 |
|---|---|
| 新建工作 | 基于明确选择的父 Worker 分支创建独立 Worker，默认 main |
| 追加输入 | 给原 Worker 补充要求，不创建新 Worker |
| 管理 Lush | 给当前项目新管家或原 V 管家提交管理需求 |

点击右下角圆形入口，选择类别或具体未完成条目。模式、目标分别保留编辑，不把原文改投给另一目标。冻结追加仍可可靠保存，须等待交付收口、整体解冻和 Agent 实际退出后投递；「已入箱」不代表 Agent 已收到。不可用目标明确说明，不能静默改投 main。

## 一个编辑器，两种位置

底部是浏览时的便携入口：正文、只读去向、条件／独占摘要、保存状态、撤销／重做和引用数量常显，提供「详细编辑」「写新的一条」「保存草稿」「提交」。不再提供底部高级设置菜单、父选择或删除操作。

「详细编辑」打开同一条编辑，不复制正文、不更换目标。详情使用同一个正文区、快捷键、文字历史、草稿 ID、版本和请求锁；同一条目不会同时有两个可提交编辑器。

- 详情默认可见、可编辑去向；工作／追加的执行条件默认展开。
- 静息／独占等高级条件按需展开，有值仍显示摘要。运行设置与引用完整信息默认收起；运行参数只在本次提交时使用，不写入服务器草稿。
- 删除在独立的「危险操作」中，经确认后删除未发送草稿、引用和对应浏览器恢复内容，不删除已发送输入或 Worker、不复用展示号。确认／请求期间的新编辑保留。
- 「到底部继续编辑」先保存，然后回到原阅读页面和位置；直接从草稿列表进入者返回可浏览的草稿列表，不留下另一份活跃编辑器。
- 「写新的一条」先保存原条目，再开启同去向的空白编辑；原草稿仍可从列表或未完成菜单继续。

底部可拖动正文上方横条调整高度，聚焦横条后 ↑／↓ 调整，Home 最小、End 最大。高度按项目和浏览器保存；软键盘或小窗口只临时限高。窄屏按钮换行，触控至少 44px。绿色实线新建、蓝色虚线追加、琥珀色双线管理同时配文字与图标；执行授权按钮始终为紫色 Agent 标识。

## 保存与快捷键

两处规则一致，触屏也有可见按钮：

| 操作 | 效果 |
|---|---|
| Enter / Shift+Enter | 换行 |
| Ctrl/⌘+S / 保存草稿 | 首次创建、之后更新同一项目草稿，保留内容，不执行 |
| Ctrl/⌘+Enter（含 Shift）/ 提交 | 先保存当前修改，再授权精确保存版本 |
| Ctrl/⌘+Z、Ctrl/⌘+Shift+Z、Ctrl+Y | 与撤销／重做按钮共用正文历史 |
| 空框 ↑／↓ | 按同项目、同模式、同目标查完整分页的可编辑草稿 |

输入法候选确认、重复按键不会提交。撤销只改变正文，不回退引用、目标、设置、服务器版本或已发送请求；保存后及两种位置互切仍保留本条正文历史。刷新不承诺恢复撤销栈。

自动保存发生在**离开整条编辑**：两种位置互切、收起、切换条目／去向、站内导航。点编辑器内引用、条件或运行设置不算离开，普通 textarea 失焦不触发服务器保存。自动保存和手动保存、提交共用同一串行队列，首次创建使用稳定去重身份，不会因重复点击创建多个草稿。

保存失败保留正文、引用及设置，并阻止本次站内离开；可重试。版本冲突不会自动覆盖：点击「读取服务器最新版」对照完整保存定义，再明确选择以最新版为基线保留本地整理，或使用所显示的服务器版本。服务器草稿已授权不可编辑时，可显式保留本地为新条目，旧收据不变；不要求先复制原文。

浏览器关闭、崩溃或断网不能保证异步服务器保存。浏览器恢复仅作兜底，保存状态会区别未保存、失败和项目已保存。黄点表示有未完成输入，不表示失败或尚未保存；菜单按类别列出原目标、摘要、状态及数量，仅查看不消点。浏览器恢复属于原项目、本浏览器，不跨设备，不包含密码或可复用授权。服务器草稿可跨设备读取。

## 提交与收据

成功授权后结束该条编辑并显示真实草稿收据；底部可「查看提交收据」。详情呈现只读收据，直到取得真实 Input／Message 才提供原文入口。不把 ACK 当作 Agent 已收到或执行成功。失败、冲突和请求期间新增的正文／引用保留；在途新编辑不会被旧成功回调清掉，也不会继续绑定已消费的草稿。

新建／追加的授权可能等待条件、安全准入或冻结解除；未创建 Worker 时不自动跳转到不存在的详情。普通暂停 Worker 的追加仍需显式开始／继续。首条工作指令提交才为手动创建的空 Worker 产生真实 Input/O 并授权执行；后续追加是 Message/A。空白创建、fork 与继承边界见[创建流程](task-flow.md)。

「撤销提交」只恢复尚未执行的草稿；已执行或 unknown 不盲目撤回／重发。旧预约 Hook 草稿仍走其受检取消入口。「释放独占」不取消 Worker、不删除成果，也不是合并授权。

## 查找草稿与历史

草稿页分「工作暂存」「追加输入暂存」「管理暂存」，单选分类，在全库分页之前筛选。列表常显去向、条件和等待／失败／未知状态，返回保留筛选、分页和阅读位置。成功源草稿从列表移除，原 ID 仍可读取收据。

历史输入默认全选新建、追加和管理，按实际发送时间倒序；Worker／合并筛选按需展开。全库搜索真实 Input、可信用户追加 Message 和主输入框的管理需求；不包含系统通信、定时管理或缺少来源证明的旧消息。正文只读，Worker 当前状态不证明某条消息已处理。关键词用 Enter／搜索提交，非文本筛选不偷偷应用未提交关键词；清空保留其它筛选。

Input 使用真实 O 编号，开发追加使用持久 A 编号，缺号显示真实消息 ID，不猜编号。管理追加仍是 Message，不造 O/A。主动保存的新草稿显示「草稿 #展示号」，旧无号记录显示「草稿记录 #内部ID」；删除、提交不复用展示号。原始记录、链接和 API 身份不改写。合并和 Worker 生命周期独立，「已合并」可以同时「待验收」。

## 条件与管理边界

条件必须全部满足。Worker 安全收尾不是一次 Agent 返回，child 合入直接父不等于已进入 main。「等当前所有Worker开发完」读取 main 的全部直接子开发 Worker，导入尚未走完合并的项，保留并去重已有条件；不含孙级或 Valet，后续新 Worker 不自动加入，超过 16 项（含独占隐含静息）整批不导入。

静息等待包含暂停、失败、待开始、未合并开发和在途交付；已安全交付的无代码成果不虚构合并。向空 Worker 提交首条指令前应取消等待自身静息的条件。独占先等待静息，再暂缓其它开发，直到本轮安全交付；自己的后代、管理、查询和交付仍可进行。失败、暂停、待决可能长期占用，需显式释放。

管理草稿支持新建和追加到原 V，忙碌时可以保存，提交必须真实可用且空闲，不持久排队。管理不支持条件、独占或引用附件；追加沿用原模型，新建可在详情选择本条模型。普通身份是默认值，模型不能自建管理员身份。

仅在详情明确选择「以管理员身份运行」，提交时核对完整原文、新建／原 V 目标、范围和保存版本，并重新验证当前 Web 登录密码。密码不进入草稿、浏览器快照或模型；恢复、回到底部及下一条默认普通。提权 unknown 只能通过精确原请求的只读收据核对，不能换 key 或改走普通入口补发。管理收据 succeeded 仅证明接受，不证明管理操作成功。权限与隔离见[项目内管家提权](engineering/administrator-valet.md)。
