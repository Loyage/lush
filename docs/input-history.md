# 历史输入与暂存

本文面向使用 Web 或桌面的用户：先把想法保存为草稿，准备好后再提交；也可从「历史输入」检索曾经提交的原始指令。

## 三种输入方式

| 模式 | 内容名称 | 去向与作用 |
|---|---|---|
| 新建工作 | 工作指令 | 基于所选父 Worker 的分支创建新 Worker，启动独立工作 |
| 追加输入 | 追加指令 | 给指定 Worker 补充要求或反馈，不创建新 Worker |
| 管理 Lush | 管理指令 | 交给当前项目管家（Valet），查询、调整和安排工作 |

三者统称「输入」。输入框上方常驻模式、去向与行为说明，打字或收起更多选项不会隐藏目标；正文提示只帮助组织内容，不承担目标提示。模式切换保留文字和引用，不立即提交或调用 Agent。当前只有工作指令与追加指令支持持久暂存，管理指令暂不支持暂存。

「暂存」保存尚未授权执行的草稿，不创建 Worker、不投递消息、不调用 Agent。「提交」保存执行授权，不保证立即开始；「按条件提交」也是现在提交授权，然后等待条件满足及安全准入。它们不是三个不同的执行引擎，内部 Input、Message、Draft、RPC 和历史编号不因此改名。

## 主输入框

| 操作 | 效果 |
|---|---|
| Enter | 新建模式暂存草稿；追加模式直接提交追加指令 |
| 「暂存」 | 新建与追加模式保存正文、引用和去向为草稿，不调用 Agent |
| 手机软键盘回车 / Shift+Enter | 换行；触屏客户端普通回车不暂存或提交 |
| Ctrl/⌘+Enter /「提交指令」「提交追加」「提交管理指令」 | 按当前去向提交；开发输入可靠保存授权，管理输入安排管家处理 |
| Ctrl/⌘+Shift+Enter | 与 Ctrl/⌘+Enter 相同，不打开条件设置 |

管理模式普通 Enter 换行，不提交。输入法确认候选文字也不触发暂存或提交。

新建工作默认父 Worker 为 main，也可展开「更多」明确选择其它父 Worker、查看或更改执行环境；执行环境信息和按钮默认隐藏，收起保留本条选择。后台在父真正空闲且安全可写时才创建并开始独立 Worker。冻结、实际调用未退出或独占开发都会延迟准入，不需要反复重发。工作区使用实际创建时的父提交，不在暂存或提交授权时锁死代码。

提交确认后留在当前页面，不自动跳到 Worker 详情。「已提交」只表示授权已可靠保存，不表示 Worker 已创建或 Agent 已开始。旧 API 的显式「仅创建」入口仍保留兼容，但不是提交授权流程。

暂存或提交成功后才清空本次确认的内容；失败与请求期间新编辑的正文、引用保留。暂存是项目级持久记录，不是当前浏览器内存中的便签，也不是自动执行队列。切换项目后，应回到原项目查看草稿。

手机端顶部常驻项目／页面身份与「导航菜单」，展开后以两列等高卡片跳转页面；菜单可独立滚动，跳转或按 Esc 后收起。输入框下方默认一行常用操作，不提供执行条件设置入口；历史输入与运行设置通过「更多」展开，桌面入口不变。触屏用户可点击「暂存」或当前模式的提交按钮；连接键盘后仍可用 Ctrl/⌘ 组合快捷键。

主输入的「撤销」「重做」默认隐藏，点击「更多」后显示；草稿详情正文旁直接显示。它们与 Ctrl/⌘+Z、Ctrl/⌘+Shift+Z、Ctrl+Y 共用本页文字编辑历史，不撤销引用、父 Worker、设置、保存或提交请求。主输入成功消费并清空后清除这条文字历史，失败或在途新编辑保留；草稿保存后仍可撤销文字编辑，再保存才更新服务器，不回退版本号。离开历史输入页后重开或刷新页面不保留撤销历史。

输入框聚焦时增高，失焦后缩回单行，长内容可在框内滚动，不因缩回丢失。窄屏按软键盘打开后的可视区域定位，尽量露出输入与操作区；极矮窗口优先正文，无可视区域接口时按窗口高度定位，缩放阅读时不强制滚动。输入区域沿用项目配色，不套外层框：实线「＋ 新建工作」表示默认创建，虚线「↳ 追加输入」表示临时追加；目标条常驻加粗，聚焦保留线型。浅色、深色和窄屏都不只靠颜色判断去向；不可输入时保留目标、原位显示原因。

## 给已有 Worker 追加

打开 Worker 详情不会自动切换输入模式，底部仍默认「新建工作」。点击具体指令／child 的「追加输入」，或工作树菜单中的同名动作，才切换到指定目标；父选择隐藏，暂存仍可用，不弹窗或立即提交。

桌面 Enter、Ctrl/⌘+Enter、Ctrl/⌘+Shift+Enter 或「提交追加」可靠保存执行授权，暂存追加只使用「暂存」按钮；手机回车与 Shift+Enter 换行。服务端确认后恢复新建工作模式，不等待 Agent 处理；失败保留追加目标与原文。如果确认期间编辑了正文／引用或主动切换目标，仍保留当前模式和未提交内容。下一次 Enter 按恢复后的模式暂存，不继续追加。

「回到新建工作」保留正文、引用与显式选择的父 Worker；追加模式中输入空白且无引用时也可按 Esc 返回。离开当前页面退出追加模式，树页提交后仍留在树页，不自动打开详情。暂停中的 Worker 仍需显式「开始 / 继续」后处理消息。

冻结期间合法追加可以可靠入箱，但不打断当前合并或源侧修复；交付收口、整体解冻且 Agent 实际退出后再交付。界面显示「已入箱 … 条追加指令，待交付给 Agent」和等待原因，不把入箱说成 Agent 已收到。未处理输入会阻止验收和归档；卡住、暂停或等待决策时保留输入，不要求反复重发。目标已结束、归档或不支持追加时保留目标、禁用并说明，不静默改投 main。

追加指令暂不支持引用附件；提交时明确拒绝并保留正文与引用，可移除引用后追加，或回到新建工作创建带引用的新 Worker。

## 找到与执行想法

打开工作分组的「历史输入」：

- 「新建工作」「追加输入」「管理 Lush」三种色块可独立勾选，勾选哪些就显示哪些模式的历史；多选取并集，全不选不显示记录。默认三种全选、Worker 状态与合并状态均为全部。
- 搜索针对本项目全库指令正文，包含原始 Input、草稿、可确认来源的追加指令及主输入框提交的管理指令，不限于当前页或最近 Worker。定时信号管理与系统消息不收录；旧缺少可信用户来源的追加消息保留在 Worker 中，不猜测归类。
- 模式与 Worker／合并状态筛选即时生效，不应用尚未提交的关键词；关键词用 Enter 或「搜索」提交。可继续加载更早记录，只找草稿时将 Worker 状态切换为「草稿」。
- 条目等高，显示两行正文摘要、编号、指令类型、时间与独立 Worker／合并状态。点击整条进入独立详情，不在列表内操作草稿。
- 「返回历史输入」或浏览器后退保留本次搜索、筛选、已加载记录及列表位置。返回不丢弃本地草稿编辑，再打开同一条可继续；切换条目先确认是否放弃未保存编辑。
- 可编辑草稿正文、父 Worker 或追加目标、条件、独占选项与引用，也可删除未提交草稿。不可用目标必须显式重选，不会改投其它 Worker。
- 「保存」在正文、去向、条件、独占或引用有变化时亮起；恢复原值或保存成功后变灰。运行设置仅在提交时写入，不单独启用保存按钮。
- 草稿详情支持 Ctrl/⌘+S 保存和正文撤销／重做；普通 Enter 换行，不设提交快捷键。快捷键和按钮共用单次请求保护，保存失败保留编辑。
- 「提交指令／提交追加」与「执行条件设置」相邻同组，保存、运行设置及删除位于次要操作组。点击「执行条件设置」才展开，默认收起，收起保留设置。已配置时标注条件数量／独占，按钮显示「按条件提交」。
- 宽屏左侧设置条件、右侧展示已有条件卡片；窄屏按设置区、已有条件区上下排列。快捷导入和手动添加常驻，静息／独占在「高级设置」中按需展开，启用状态仍在摘要和卡片显示。可逐项移除；移除显式静息条件不会关闭独占隐含的静息要求，独占需单独关闭。
- 提交先挂载当前版本的授权，实际新建会自动开始；追加复用目标的运行设置，新建可单独设置模型等运行参数。已提交草稿只读，不能编辑、删除或重复提交。
- 「撤销提交」仅恢复尚未执行的草稿；已经执行或结果未知不能撤回或盲目重发。原有预约 Hook 的草稿仍走其受检取消入口。
- 实际创建后可查看原始指令与真实 Worker；没有 Input 时展示草稿和提交收据，不虚构 O 编号。独占草稿保留「释放独占」，释放不取消 Worker、不删除成果。追加草稿保留真实 Message／A 编号收据，不创建另一条原始 Input。

每次只提交当前一条，不把其它草稿一起执行。新建成功关联 Input 后列表不重复显示源草稿；等待中的授权和追加草稿仍可查找，已发送追加草稿与其 Message 不重复显示。普通追加指令与管理指令也可查看只读原文，并跳转来源 Worker／Valet；页面归属仍未拆分。

## 条件与管理指令

条件必须全部满足：可添加 Worker「工作安全收尾」「本轮成果已合入 main」，或等待目标树彻底静息。工作收尾不是一次 Agent 返回；child 仅合入直接父 Worker 也不等于已进入 main。静息等待包括暂停、失败、待开始、未合并开发工作和在途交付；已合并且无新工作、静息待验收的 Worker 不阻塞。已安全交付的无代码结果不需要虚构合并；取消但有脏现场仍阻塞。

展开「执行条件设置」后，可点击「等当前所有Worker开发完」：读取 main 的全部直接子开发 Worker，把尚未走完合并环节的项追加为「本轮成果已合入 main」条件，不限于运行中，不包含孙级 Worker 或 Valet。已合并的项和已安全交付的无代码成果不会导入，与是否验收无关；新一轮尚未交付的开发仍会导入。已有条件保留并去重，之后新建的 Worker 不自动加入；该按钮不提交草稿、不授权或执行合并。读取失败或导入后超过 16 项上限（含独占隐含静息）时整批不导入，原条件保留。暂停、失败或取消等尚未合并的项也可能被导入；不再继续的工作可手动移除条件。

「独占开发」先等待项目静息，再暂缓其它开发创建和调用，直到本轮安全交付收口；自己的后代、管理、查询和交付仍可进行。它不是自动合并授权，失败、暂停或待决可能长期占用。「释放独占」只撤销后续独占意愿，保留成果与未知诊断。

「管理 Lush」把管理指令交给独立管家（Valet）：例如分析运行记录，或将“W123 合入 main 后进行 xxx”保存为条件草稿。提交会调用管家，但不会直接创建开发 Worker、Git 分支或 O 输入；管家后续受控操作可能创建开发工作，操作结果单独记录。可点击「查看最近管理记录」。当前管理模式不支持持久暂存、条件按钮或引用附件；普通 Enter 换行，Ctrl/⌘+Enter 或「提交管理指令」提交。

只有已审核的查询、草稿、提交等能力可自动执行；取消、合并、验收回收、删除、敏感设置等须用户在问卷中确认精确请求。管家没有任意文件／Shell 工具，不读取凭证、不跨项目，设备操作须明确提出。运行诊断读取安全调用摘要，不读取原始提示词或工具内容；不可用能力会说明需转至用户界面。

## 编号与状态

原始输入记录在界面称「原始指令」，使用 `O190` 等真实 Input 编号。Worker 头部、版本历史及正文中的 O 链接打开完整原文，不跳到关联 Worker，也不受历史列表当前筛选限制。草稿仍用 `草稿 #编号`，追加消息使用真实 A 编号，不另占 O 编号。

用户决定使用 `D454`，纯告知使用 `N455`（历史 plan 也用 D，未知类型保守用 N）。W／D／N／O 链接支持键盘及新标签；D／N 打开原事项与问卷／答案，不自动答复或标已读。全局链接保留来源项目，代码块、已有链接和编辑区不自动转换。历史原文、引用快照与整数身份不改写，旧数字书签仍可用。

| 主状态 | 含义 |
|---|---|
| 草稿 | 已暂存，尚未授权执行 |
| 已提交 · 等待条件／等待准入 | 已保存授权，尚未创建新 Worker 或投递追加消息 |
| 正在投递／已投递 | 正在执行投递或已有投递收据，不代表工作完成或 Agent 已处理 |
| 追加指令已入箱 | 已持久投递到目标收件箱，不保证 Agent 已收到或处理 |
| 提交后投递失败／投递结果待核验 | 明确投递失败或结果未知；未知不得自动重放 |
| 已创建·待开始 | 已创建 Worker，尚未调用 Agent |
| 排队中／执行中 | 等待执行槽或正在运行 |
| 等待中／待处理／已暂停 | 等待后续工作、用户决策或显式继续，不是失败 |
| 待验收 | 本轮交付后等待确认，不等于尚未合并 |
| 已完成 | Worker 已确认收口，不保证有代码改动 |
| 失败／已取消 | Worker 执行失败或明确放弃，原始指令仍保留 |
| 状态未知 | 历史关联缺失或无法确认，不假定成功 |

合并状态单独显示，例如「合并中」「合并受阻」「已合并」，可与「待验收」同时成立。归档不等于删除历史。

## 父 Worker 与并发编辑

暂存保存当时父 Worker 身份；主输入默认显式 main，不随项目检出分支或当前详情改变。在任意页面（含 main／owner 详情）都可展开输入区选择其它父 Worker。父已结束、归档或暂时不可写时，提交可能被拒绝或等待准入，草稿保留，须重选或处理阻塞，不自动改投。

保存想法不冻结代码：工作区从实际创建时父分支已提交代码创建，未提交修改不随输入带入。旧草稿没有父身份时须先明确选择并保存。

多标签编辑检查版本，冲突不覆盖另一处保存的内容；先复制保留本地修改，再刷新读取最新版本并整理。详情不提供单独重新读取按钮，列表刷新也不覆盖本地编辑。网络失败不要连续点击重复创建 Worker，可查历史确认提交收据。

更多执行与验收规则见[一条指令输入如何交付](task-flow.md)。
