# 快速对话

快速对话用于解释、整理、摘要和速记等纯文本交流，不创建 Worker、不执行工具。对话统一保存在后台设备用户的历史中，未打开项目或项目离线也能使用；每段多轮对话共用一个 C 编号。实现边界见[工程契约](engineering/quick-chat.md)。

## 配置模型和 Prompt

在全局工作台进入「快速对话」的设置，选择已有 API Key 模型来源和物理模型 ID。所有 Prompt 共用这份独立直连配置，不改变开发 Agent 的运行设置；来源支持范围与既有快捷解释相同，不支持 OAuth 套餐。保存只写配置，不调用模型；本地就绪不保证联网可用。

默认提供「快速解释」示例，可编辑 Prompt 或关闭它的右键注册。也可以保存自己的命名 Prompt，例如「整理会议要点」或「生成简洁笔记」。开启右键注册后，它会出现在有效文字选区的菜单中；未注册的 Prompt 仍可在输入框选择。

修改／删除 Prompt 不改写已有对话。来源和模型在新对话发起时固定，同段追问沿用原快照；原来源失效时会报错，不静默改用其他账号。

## 从文字开始

- 选中页面文字，右键选「快速解释」或已注册的 Prompt：直接调用模型，在新标签打开独立对话页，保留原页面。
- 先右键「引用」，再在项目主输入框打开「快速对话」模式（手机端先展开「更多」）：选择 Prompt，按需输入要求，点击发送。可以只带引用而不写正文；选择 Prompt 本身不调用模型。
- 全局快速对话页也能直接输入文字开始，之后在同一 C 对话中继续交流。

紫色模型调用按钮会消耗所选来源的 token，但不是 Agent 调用。仅发送用户输入和引用当时所见的快照，不读取引用目标的文件或最新状态。输入控件、菜单不作为选区来源；无选区不自动发送整块页面，超长选区明确提示缩短。

浏览器若阻止新标签，使用操作结果中的对话链接，不重复发送。请求失败或结果未确认时保留输入并检查历史，避免重复调用。

## 回看与继续

历史按新到旧分页，点击 C 编号进入完整对话。首轮、后续消息、结果、失败、引用和当时的 Prompt／模型来源都在同一记录中。每次仅允许一轮在途请求；失败轮保留，可明确发送新消息继续，但不会自动重试。

历史对话可在确认后永久删除，包括全部轮次；在途调用不能删除。删除后编号不复用。旧项目「解释历史」仍留在原项目，不自动合并到 C 历史，也不改写旧记录。

## 限制与风险

正文每轮最多8192字符；引用最多12项、单项8192字符、合计48KiB。最多4次并发调用、120秒截止、响应256KiB上限。多轮历史超过上下文预算时丢弃最早轮，并在本轮标明；完整历史仍保留。Host 停止会取消自己的在途请求，重启不自动重放。

模型输出不是执行事实，不能把生成笔记当成已写入项目文件。选中文字可能包含敏感资料，发送前确认允许传到配置的模型端点。新功能在 Host 中运行，合入部署后需由用户更新／重启 Host；不要重启正在工作的 daemon 来尝试刷新界面。
