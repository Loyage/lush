# 开发效率与效果优化待办

本文记录 W247 对近期 Worker 运行样本的复盘建议，供后续开发选择优先级；勾选项已由 W256 落实，未勾选项仍为待办；复盘建议本身不代表新增的强制规则。主要依据 W240～W243 的调用、交付及子 Worker 记录，以及 W242、W243 的分页执行步骤抽查。

## 优先级一：减少集成阶段才暴露的问题

### 可构建的中间交付

- [x] 派工前明确公共组件接口、生命周期及依赖；需要共享骨架时，先提交可运行的骨架再派工。
- [x] 父页面在相关模块合入后再接线，避免引用尚未交付的文件；不靠伪造兄弟模块或绕过构建使测试通过。
- [x] 派工目标区分子 Worker 可独立完成的验证与父 Worker 收齐成果后的集成验证，后者明确负责人。

依据：W243 父基线提前引用尚未交付的 `render-management.js`，两个子 Worker 在源侧修复时分别遇到 10 项、4 项 HTTP 测试构建失败，需收齐兄弟成果后补验。文件分工不重叠并不等于没有代码依赖。

验收方向：中间交付没有缺失模块引用；可独立验证的路径能运行，受依赖阻塞的验证有明确原因及最终补验记录。

### 全量前的快速集成检查

- [x] 为不同改动类型整理小范围检查组合，复用已有测试入口，不另造一套重复验证流程：
  - 页面重构：导航、深链接、资源构建及冷启动预算。
  - RPC 新增：注册表、权限、HTTP 转接及公共返回值。
  - 组件拆分：导出兼容、离页请求及返回后的状态恢复。
- [x] 在最终全量前跑适用组合，先处理容易由小范围检查发现的遗漏；组合不能替代最终全量，也不放宽性能或测试预算。

依据：W243 首轮全量约 8 分 53 秒，发现 11 项失败，涉及旧页面测试入口、RPC 清单及冷启动模块数超限；修复后最终全量约 8 分 39 秒。部分遗漏可由耗时约一两秒的资源构建专项等小范围检查提前发现。

验收方向：常见接口、导航及资源遗漏在快速检查阶段可被发现；最终全量仍覆盖收齐并修复后的代码树。

### 新能力的真实调用链验证

- [x] 新能力早期先验证一条“入口 → 注册 → 权限 → 执行 → 返回结果”的真实调用链，再扩大模块专项。
- [x] 工具集合、RPC 名称等尽量使用单一来源，并增加各层集合一致性测试。
- [x] 使用可控 Provider／CLI 和真实 bridge 验证，不要求调用付费模型，也不把 mock 通过当作真实链路通过。

依据：W240-2 多轮专项通过后，父 Worker 仍发现 Provider 只启用旧三项工具，新工具未完整进入实际可调用集合，随后追加修复与验证。

验收方向：新工具既在目录可见，也能经实际入口调用；缺注册、缺权限或缺 Provider 接线均有对应失败断言。

落实入口：可构建中间交付约定位于 `src/agent/skills/lush-delegation/guide.md`；快速检查用法见[贡献指南](contributing/README.md#全量前快速集成检查)；真实管理工具链与集合一致性回归位于 `test/project/management-tool-chain.test.js`。这些约定和回归不构成 runtime 构建／合并门禁，也不证明真实模型行为。

## 优先级二：降低协作成本与产品返工

### 精简协作消息

- [ ] 普通进度优先使用进度机制；追加消息优先用于决策、接口变化、阻塞及必须补做的验证。
- [ ] 集中表达接口确认，减少连续补充小字段；评估纯进度消息引起的唤醒，保留失败与安全问题的及时通知。
- [ ] 保留现有成功信号聚合，不为了减少调用数压制必要审查。

依据：W240 有 14 次调用，包含接口同步与短暂确认；W243-2 有一次仅核对消息、无需改动的调用。调用多本身不证明浪费，需结合实际工作判断。

验收方向：以仅核对消息、无新增工作的调用数作为观察指标，而非追求总调用数越少越好。

### UI 重构先确认信息层级

- [ ] 大型 UI 改动在决策问卷中附简短、安全的静态预览，确认默认内容、高级功能展开时机、高频操作步骤及窄屏表现。
- [ ] 区分“具备功能”和“默认突出功能”；浏览器布局检查不能替用户确认信息优先级。

依据：W240、W241、W243 连续调整输入与自动化界面，后续 W246 又提出条件发射应降低存在感。这不必然是前次实现错误，但说明信息层级值得更早确认。W246 的具体调整已落地，当前条件发射入口见[历史输入与暂存](input-history.md#找到与执行想法)；本待办针对今后 UI 重构的确认方式，不要求重复实现该调整。

验收方向：实施前明确哪些内容默认出现、哪些按需展开；交付按已确认交互及布局验证，不只检查功能是否存在。

## 优先级三：用工具减少记忆负担

### 常见失误转为工具支持

- [ ] CLI 提供可直接使用的参数／JSON 示例；按需增加只读预检，降低问卷外层格式等可机械检查错误。
- [ ] 先定位文件再读取，减少猜路径；用共享契约与测试入口降低重复记忆成本。
- [ ] 延续文档去重方向，不为每一种错误追加大段 Agent 必读提示。

依据：W242 交付报告称文档体积减少 26.7%；执行步骤中仍出现猜错路径及问卷 JSON 外层格式错误。此类问题更适合用工具反馈解决，而非继续堆长提示词。

验收方向：示例可直接使用，预检无副作用，失败说明能指导修正；不增加重复文档维护要求。

## 约束与复盘范围

优先推进可构建的中间交付、快速集成检查和真实调用链验证。现有最终全量、源侧语义审查及未验证范围报告继续保留，不通过省略安全或质量步骤换取速度；验证责任仍以[贡献指南](contributing/README.md#分层测试与交付)为准。

这是一份样本复盘，不是全项目统计；部分执行正文有截断，尚不足以量化 token、费用或预计节省比例。W247 分析时未修改产品代码，也未重新运行样本 Worker 的测试。实施具体待办前需核对届时现状，方案有实质歧义时另行确认。
