# 远程 Host：访问方式与安全取舍

本文面向希望从另一设备使用 Lush 的用户，解释后台部署位置、SSH 与 HTTPS 的选择，以及认证和项目白名单为什么必要。具体配置交给[远程 Host Agent 指导](remote-host-agent.md)，客户端使用另见[远程桌面](remote-desktop.md)与[Windows 客户端](windows-client.md)。

## 远程的是入口，不是项目事实

项目目录、Git、编码 Agent、模型认证与 lushd 都在后台机器。客户端只连接该机器的 Host 页面，不连接 daemon 的 Unix socket，也不需要同步 `.lush/` 或挂载远程文件系统。

Host 负责认证、项目登记和请求转发；每个项目仍有自己的 daemon 与状态。这个方案不会把 Host 变成跨项目调度器，也不会让客户端拥有另一份 Worker 数据库，详见[三层边界](../engineering/host-boundary.md)。

后台可以在 Linux/macOS 上按[本机部署方案](local-deployment.md)准备；远程访问是在它之上增加的入口配置，不代表需要另一套 Lush 核心实现。

## 选 SSH 隧道还是 HTTPS

| 方式 | 适合 | 代价与边界 |
|---|---|---|
| SSH 回环隧道 | 单人使用、已有 SSH、不希望公开 Web | 需保持隧道运行；本机转发端口也只供可信用户使用 |
| 认证 + HTTPS Host | 多设备方便访问、有域名和反向代理 | 需维护证书、认证、项目范围及端口隔离 |

SSH 方式可以保持 Host 只监听远端回环地址，无需创建公网配置。SSH-only Linux 首次部署可使用[桌面 SSH 入口](ssh-desktop.md)，免去手工安装 Host 和维护隧道；原有手工 / HTTPS 路线不变。隧道保护的是传输；若 Host 无登录认证，本机能访问转发端口的进程同样能访问项目，因此不是多用户隔离方案。

HTTPS 方式让浏览器和 Electron 直接使用可信的根地址。公网和局域网跨设备访问都不应退化为无认证的明文端口。配置 `web.json` 会让 Host 进入监听所有 IPv4 接口的认证模式，不能误认为“加了密码就仍只监听回环”；必须同时隔离后台 HTTP 端口，并在前面提供 HTTPS。

## 为什么要区分配置作用域

单项目入口只服务显式绑定的项目；多项目入口需要明确的 `projects` 白名单。白名单控制可见和可访问项目，不只是隐藏项目列表：不能让一个公开入口任意打开后台用户能读的目录。

认证配置的路径、字段和权限由[Agent 配置指导](remote-host-agent.md#3-配置认证与项目范围)统一维护。它与客户端的 Cookie、最近连接记录是不同数据，不得把登录密码或模型凭证同步到客户端配置中。

## 为什么会有登录和跨站限制

HTTPS 保护传输中的凭证；Host 登录控制访问；同源检查避免页面被其它站点借用来执行操作。这些机制不能互相替代。

反向代理可能改写 Host，因此必须保留正确的请求身份或明确登记对外 origin，而不是禁用跨站校验。应使用 Host 根地址，不把整个应用随意挂在 URL 子路径下。

登录会话在 Host 内存中，重启 Host 会要求重新登录。具体会话、锁定和 HTTP 规则见[HTTP 与认证](../reference/http.md)。

## 暴露入口不是建立不可信多用户服务

Lush 是可信用户开发工具。Agent 能以后台用户权限读写和执行代码，目录绑定与登录不构成操作系统沙箱；它不适合直接开放给互不信任的用户。

必须审阅代码改动，并控制可以访问后台的人员、项目和网络范围。备份或调整配置不应删除项目 `.lush/`，也不能自动把不同机器的项目状态互相复制覆盖。

## 断线和更新的影响

关闭客户端或 SSH 隧道不停止远端 daemon；Worker 可能继续运行。重新连接后先查看状态，不自动重发结果未知的输入或其它写操作。

Host 和各项目 daemon 需分别检查代码身份、分别升级。只更新客户端不能修复旧远端 API，重启入口也不意味着所有项目 daemon 都换了代码。

## 验收需要分别证明什么

1. 后台工具、项目与 daemon 可用，代码身份正确。
2. SSH 隧道或 HTTPS 连接实际可达；证书验证未绕过。
3. 认证保护正常，公开入口只能访问授权项目，后台 HTTP 端口没有被意外公开。
4. 客户端能读取项目状态；真实模型调用另获同意后验证。

Agent 应报告在哪台机器验证了什么、仍未验证什么、配置与日志位置，以及连接 / 关闭入口的方法。无目标机或客户端权限时，交给用户完成检查，不得把配置文件写好当作端到端验收。
