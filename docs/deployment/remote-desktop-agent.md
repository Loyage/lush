# Agent 指导：配置桌面远程连接

本文交给帮助用户从 Electron 连接远程项目的 AI coding agent。用户版的连接方式、设计原因、会话与故障边界见[桌面连接远程项目](remote-desktop.md)；后台入口配置按[远程 Host Agent 指导](remote-host-agent.md)执行，本文不重复认证模板。

## 1. 区分客户端与后台

确认客户端操作系统、安装来源、后台 Host 根地址、远端项目路径，以及是否已有可信 HTTPS 或 SSH 访问。不要把客户端目录填成后台项目，也不要复制 `.lush/` 或模型凭证到客户端。

- 远程模式不创建本地 Host / daemon。模型认证在后台用户环境配置。
- 使用已安装的客户端不要求本机 Bun；若从源码执行 `bun run desktop`，则必须有 Bun 和已安装的 Electron 依赖。
- 客户端安装、SSH、证书信任变更、服务重启和模型调用都需用户确认。不绕过 TLS 或 SSH 主机身份校验，不关系统保护。
- 用户只委托连接现有后台时，不顺带更改后台配置、停止服务或安装编码 Agent。

## 2. 准备客户端与入口

先检查已有客户端。Windows 安装包路径走[Windows 客户端 Agent 指导](windows-client-agent.md)；macOS / Linux 从用户提供的可信 Lush 检出启动源码桌面时，在源码目录执行：

```bash
bun --version
bun install --frozen-lockfile
bun run desktop
```

安装依赖会联网下载 Electron，已有安装不必重复下载。遵守目标机包管理约定；没有 GUI 权限时只能验证准备步骤，必须请用户完成桌面操作。

HTTPS 入口要求可信证书与正确认证，配置见[Host 指导](remote-host-agent.md)。用户选择 SSH 时，使用[用户版中的隧道命令与端口规则](remote-desktop.md#https-与-ssh-隧道)：只绑定回环、核对主机身份、不同远端使用不同本地端口，保持隧道运行。客户端不代管 SSH 或重连隧道，不在后台悄悄创建长期隧道进程。

## 3. 打开连接并验证

1. 在连接页输入 Host 根地址；HTTPS 或 SSH 回环 HTTP 均需使用实际入口。不得包含用户密码、`/p/<id>/`、查询参数或 URL 片段，不部署到任意 URL 子路径。
2. 打开远程窗口，由用户在远端登录页认证；不要读取或转存用户 Cookie。
3. 选择远端项目，核对项目显示与绝对路径，读取 Worker / 项目状态。不要用提交输入证明连接成功。
4. 如用户需要多个窗口，分别连接各 Host / 项目，检查窗口的项目身份不会因其它窗口切换而改变。
5. 退出后重启客户端，检查用户需要的登录与最近连接是否保留；是否退出远端账号由用户决定，不以删除记录代替注销。

相同 Host origin 的窗口共享登录，不同 origin 隔离。SSH 转发端口也是 origin 的一部分，因此切换远端不得复用原来的端口和登录语义。

系统通知默认关闭，仅按用户选择开启。验证通知点击前说明窗口关闭后不再提醒，不把它描述成远端持续后台推送。

## 4. 断线与排错

| 现象 | 检查与操作 |
|---|---|
| 连接失败 | Host 根地址、证书、SSH 隧道是否仍运行、实际端口，修复后显式重试 |
| 登录后操作被判跨站 | 在后台检查代理 Host / origin，按 Host 指导修复，不改客户端安全策略 |
| 页面 API 404 | 后台 Host 代码身份；客户端升级不能替代后台升级 |
| 运行中断线 | 重新加载或连接菜单重开，先读 Worker 状态，不自动重发写操作 |
| Windows 本地窗口禁用 | 这是产品边界；使用远程窗口，若需要本机后台则走 WSL2 |

关闭窗口不停止远端 daemon；桌面退出只会清理它自己创建的本地临时 Host。不要为了验证断线主动中断有活动工作的后台，也不要强杀无关进程。

## 5. 交付结果

记录客户端版本 / 来源、Host origin、远端项目身份、HTTPS 或 SSH 验证、登录 / 多窗口 / 断线 / 通知的实际验证与缺项。没有真实 Electron 或 GUI 权限时明确标为未验证，模拟测试不等价于桌面验收。

交付打开连接的步骤、隧道命令与关闭方式（如适用）、后台管理员的日志检查入口。报告不含密钥、Cookie 或密码。不自动移除最近连接、删除客户端偏好、停止后台或重放输入；用户要求退出账号时使用该 Host 的退出入口。
