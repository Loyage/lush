# 执行记录阅读器

本文描述执行过程的当前实现、数据边界和测试入口。修改前先读[设计理念](../design/agent-process.md)：目标是帮助用户理解 Agent 的运作，不是单纯堆放日志。

## 两条读路径

快速视图沿用 `worker.transcript`：从Worker的 Pi 兼容 JSONL 投影步骤，执行过程仅用户点击「打开执行详情」后全屏读取；打开后直接展示思考、回答、工具及结果的正文，仅运行时元数据默认折叠。刷新与新记录不会自动打开，返回Worker后停止正文续读。兼容读面保留单条 4,000 字符、每请求前 8 MiB 的限制与既有 token 口径，不重写会话或数据库。

完整阅读走 `core/transcript-reader.js`：

- 按Worker遍历所有会话文件，异步流式读取完成的 JSONL 行，不受快速视图的 8 MiB 范围限制。
- 搜索覆盖原步骤全文，不只搜预览或已加载 DOM；目前是大小写不敏感的连续子串匹配，不支持正则或语义搜索。
- 类型、工具名子串与失败筛选可以组合；失败指记录中的 `isError`，不猜测文本里的退出码。
- 返回按 `seq` 升序的有界摘要，`after` 为上一页最后一步；原文按 24,000 字符分页读取。
- 单行最多 16 MiB；超大行明确报“无法完整检索”，不会冒充无命中。坏 JSON 行跳过、未完成尾行等待后续写完；这与快速读面的步骤编号规则一致。
- 不持久化全文索引，也不缓存所有正文；每次查询从头流式扫描，因此超长历史的后页或原文查询可能较慢。当前能力是可完整翻找，不是恒定时间随机访问。

`seq` 在正常追加下稳定；会话清理或改写可能让旧编号失效。解释历史独立保存当时快照，不依赖源文件一直存在。

### 最新读取

需要优先看到尾部时走 `worker.transcript_latest`：它不复用快速视图的 8 MiB 头窗口，而是对Worker全部会话做一次完整的异步流式扫描，返回满足 `seq > after` 且（`before === 0` 或 `seq < before`）的最新 `limit` 步，按 `seq` 升序。`after` 是已读下界，`before` 是向回翻页的上界；两者默认 0 表示不设边界。

- 每步的字段、4,000 字符裁剪与 token 口径与 `worker.transcript` 完全一致：精确请求带 `exact/turn`，两次请求之间的批次带 `context_added/estimated/batch`，批首 `first` 只落在该批第一步；窗口从批次中间开始时不会误添 `first`，文件边界仍不跨文件推算。
- 返回 `next`（窗口最大 `seq`）/`oldest`（窗口最小 `seq`）/`has_older`（`(after, oldest)` 内是否还有步骤）供 `before` 连续往回翻页；空窗口的 `next` 回退到 `after`、`oldest` 回退到 `before`。
- 内存有界：只保留窗口与当前 token 批次，不缓存全部正文；不改写会话文件。全量扫描与全文搜索同级，超长历史不是恒定时间。单行超过 16 MiB 时置 `truncated` 并跳过该行，不冒充无数据；坏 JSON 行同快速读面一样跳过。
- 与快速读面的区别：快速读面从头读、受每请求前 8 MiB 预算限制，适合先看开始；最新读取为保证尾部可达会读完整个Worker记录，适合轮询最新步骤或从尾部向回翻找。

### 快速查看的阅读方向

全屏「执行过程」默认**最新在前**：初次展开走 `worker.transcript_latest?limit=100` 取尾部窗口，按 `seq` 降序渲染（最新步骤在最上），向上滚动回看更早，底部「加载更早」用 `before=oldest` 连续向前翻页。`state.steps` 始终按 `seq` 升序保存为规范态，方向只影响渲染与节点落位。阅读页工具栏或设置 → 界面 → 「执行过程排序」可切回「最早在前（正序）」，此时走 `worker.transcript` 从头部读取。两个方向都给两个有界翻页入口：`加载更早` 用 `before=oldest`、`加载更多` 用 `after=next`；asc 把更早的一页前插到顶部、desc 追加到底部。搜索定位出的居中窗口因此两侧都能继续读。切换偏好时已展开的过程按新方向重新加载，未展开不请求。

热Worker增量续读与终态补读也按方向取数：asc 用前向端点，desc 用 `transcript_latest?after=next`（`next` 恒为已知最大 `seq`），新步骤并入 `state.steps` 尾部、渲染到列表顶部，并在顶部提示「有新记录 · 跳到最新」（asc 仍跳到末尾）。desc 的 `has_older` 只由向旧翻页改变，增量不改动它；两种方向下按 `(file, call_id)` 的调用/结果配对跨翻页边界都不得重复或错配，已渲染节点的展开状态与阅读位置不被无谓重建吞掉。全屏阅读与设置共用同一排序偏好。

## 正文优先与因果配对

`transcript-body.js` 是执行正文渲染器，富文本与纯文本只差 `plain` 选项：工具参数按命令、文件、起始行、修改前后等标签直接展示；未知参数保留字段名；命令与输出使用保留真实换行的代码块，思考／回答按 Markdown 偏好渲染。富文本模式给命令（shell）与按文件扩展名识别出的文件正文着色，Markdown fence 也按语言着色（`code-highlight.js` 按需加载固定版本 highlight.js，受控 DOM 构建、不 innerHTML）。`plain` 模式只保留原始换行与扁平字段，不渲染 Markdown／JSON 树／着色，保留为纯文本渲染接缝，Web 不再提供终端模式。普通长内容默认显示前 10 行／1,000 字符，就地展开当前已加载内容；命令与失败文本不预折叠。参数最多预览 40 个字段、20 处修改，超限明确指向原文。

`transcript-model.js` 的摘要用于步骤收起态，不再挤占默认正文。全屏步骤以卡片分隔，主标题突出类型、工具名与调用状态；编号、上下文 token、工具耗时与相对时间按此顺序紧凑聚合在标题行，不另起一行平铺或为缺项预留列位；仅在窄屏或标题过长、空间不足时自然换行，失败状态及配对输出明确标红。搜索摘要只显示编号、类型、名称与失败标记，关键词摘录单独一行，不重复堆在标题里。会话文件与精确原文放在来源入口；加载计数、全部展开／收起及重新加载在正文上方，历史分页在底部。页面使用主滚动，不为过程／正文再嵌套定高滚动框。

投影保留 `call_id`、`tool_name` 与 `is_error`。界面按 `(file, call_id)` 将已加载的输入输出放在同一个调用下，结果可以增量追加而不重建输入节点；跨页加载后同样配对。重复调用身份不猜配，缺 ID 的旧记录各自保留。

步骤元信息只在工具指令上显示执行用时，统一使用秒（例如 `time≈1.3s`、`time≈65s`），有效耗时小于 1 秒（含零）时只显示 `time<1s`，不展示具体小数值，不显示模型回复用时或中文计时解释；缺失或无效时间不显示计时，不以相邻步骤间隔猜测。工具只在已加载步骤中按唯一 `(file, call_id)` 配对且只有一个有效结果时，用调用记录至结果记录的间隔估算；可能包含排队、同批其他工具等待及写入开销，不承诺纯执行时长，具体限制保留在帮助提示中。跨页／增量配对只更新用时元信息，缺结果、重复身份、逆序时间均不冒充零秒；搜索正文复用同一展示。不改写旧会话、不增加计时器、模型调用或持久化记录。投影可选字段 `model_duration_ms` 继续兼容保留，但不在界面显示。

未见结果显示“尚未见到结果”，不是“成功”或“仍在运行”的断言。原始步骤编号与各自来源引用保留。完整步骤接口另查同一会话内的配对记录，最多附带 8 条关联摘要；前后各两步只作为阅读上下文，不自动发给解释 Agent。

## 全文翻找与原文

全屏执行详情左侧提供固定的紧凑搜索框、类型、工具与失败筛选；关键词与工具名按 Enter 或「搜索」提交，输入草稿不自动请求；类型与失败筛选即时请求，但继续使用已提交文本，不偷用输入草稿。主搜索提交同时提交工具名草稿；清空某个文本条件保留其他筛选。Ctrl/⌘+Shift+F 聚焦搜索框，中文输入法确认候选不触发检索。搜索控件不随命中摘要滚动，命中摘要按页浏览，关键词高亮；右侧只展示本页命中正文，与左栏按步骤编号升序一一对应（不受全部记录的阅读方向影响）。点击左栏命中在右栏就地定位，不加载无关步骤窗口。每项通过既有 `transcript-step` 读取首段最多 24,000 字符及可靠配对内容，最多 4 个并发请求；配对内容和至多 8 条的截断边界显式标注，相邻上下文按需展开且标明非命中。长正文在步骤旁继续分段读取完整原文。读取失败留在对应卡片并可重试，不把失败当成没有命中。

搜索摘要为实际 `bash` 工具调用附带有界 `shell` 元数据：命令正文最多2048字符、其余参数预览最多1024字符，明确截断。`fingerprint` 使用完整参数（只规范 JSON 对象键序，保留命令空白、路径与所有参数）计算，不以截断正文归组；超过256 Ki字符／16000节点／32层的分析预算或参数无效时 `identity_complete:false`、指纹为空，不能猜配成同一命令。原始命令仍可按步骤分段读取。工具结果另带 `error_known`，区分明确的 `isError:false` 与旧记录根本没有错误标记；不从输出中的报错关键词猜测成功或失败。

「返回全部记录」清空关键词与筛选，恢复既有富文本过程及翻页，不重开Worker页。兼容的独立检索 / 引用定位仍可按 `seq` 读取前后各 100 步的窗口，展开并定位到步骤。

### 全屏富文本详情

Worker 工作详情的「打开执行详情／打开代码阅读器」使用保留来源项目的原生新标签链接，分别进入 `#worker-<内部ID>-execution`／`#worker-<内部ID>-execution-code`，可直接访问或刷新；原详情的输入与阅读位置不变。独立阅读页不提供返回 Worker 的按钮或备用链接，结束阅读时关闭浏览器标签页即可；Esc 保持阅读页，窄屏搜索展开时仍优先收起搜索。独立管理页与引用定位保留原有页内阅读接缝。

`transcript-view.js` 使用原生 dialog 顶层展示富文本执行过程：桌面左侧命中列表与右侧正文各自滚动，搜索框保持可见，正文及工具输出不再嵌套滚动框；两栏有独立命名的 Grid 区域，项目导航样式仅匹配 `#sidebar`，不得污染执行页的 `aside`。顶部以两行紧凑排布 Worker 编号／状态，以及平级页签／阅读排序，不重复占位标题；仅页内阅读器保留返回入口。

用户 W165 / 决定 #406 确认手机正文优先：宽度 ≤760px 时默认收起整块搜索区，仅保留「搜索」按钮；点击按钮或 Ctrl/⌘+Shift+F 展开搜索并聚焦关键词。检索区最多占阅读布局的 55%／340px，其余仍显示正文；很矮的横屏允许整个搜索区滚动，避免控件被裁掉。点击命中先收起搜索、聚焦正文，再就地定位对应卡片；再次展开保留关键词、筛选和命中页。Esc 在手机搜索展开时只收起搜索并归还按钮焦点，页内阅读器再按 Esc 返回原页面，独立阅读页则保持打开。桌面命中定位不收起左栏。代码路径搜索会显露搜索区；页签切换保留展开状态，不额外请求。检索时禁用排序（命中按步骤编号排列）。搜索、调用配对、步骤折叠和有界翻页复用原渲染器，不另建 Web 终端模式、不启动 Pi／PTY／模型、不执行记录中的命令。

页内阅读器可由引用定位或独立管理 Agent 页面直接打开；全屏打开时以阅读器的 Worker 身份而非后台详情选中项判断正文刷新、配对、分页及排序，不改后台选中项，关闭恢复原入口焦点和阅读位置。打开期间暂停Worker详情重画，全部记录模式下热Worker正文增量续读，保留节点与滚动位置；检索模式只提示新记录，不将非命中追加进正文，重新搜索才更新命中。搜索 / 翻页 / 返回全部记录 / 关闭会使旧检索与正文请求失效。返回／Esc 恢复Worker页位置与焦点；导航与 boot 关闭阅读页，迟到响应不写入已关闭的页面。排序切换重新加载对应头／尾窗口，过期方向请求不得覆盖新窗口。

「读取完整原文」通过既有 `worker.transcript_step` 按 24,000 字符分段，就地显示精确文字并提供继续读取／失败重试，不重复堆放配对与前后上下文。`worker.transcript_page` 保留为兼容只读 API：每页至多 50 段、96,000 字符正文、700,000 字节步骤 JSON，返回 `(next_seq,next_offset)`；不再有 Web 终端模式调用方。

### 平级的代码与改动视图

执行详情顶部增加键盘可切换的「执行记录 / 代码与改动」页签，默认仍是执行记录。代码页签首次点击才创建 `code-view.js` 并读取代码；切换保留两边的 DOM、选中文件、搜索与正文滚动，关闭释放代码计时器及请求。切到代码时暂停执行记录的增量正文读取、作废未完成的检索/正文队列；回到记录后已完成的搜索不重跑，未完成的搜索明确提示重新提交。

文件浏览器列出全部项目代码，未改文件可直接阅读；改动/未提交清单与目录共用选中状态。路径筛选按 Enter/按钮提交，目录按需读取，首层改动目录有界展开；用户显式折叠的目录在刷新/页签返回后保持折叠，不被自动展开规则覆盖。删除/重命名、暂存/未暂存、未跟踪、冲突各自可辨；缺少基线时明确净变化无法判断，不能把空列表报成无改动。数据和归档边界以[代码阅读器契约](code-reader.md)为准。

选中文件支持差异/文件内容、基线/当前版本、行号、按语言着色、上下差异块、增加上下文及分段读取。桌面默认并排，可切统一；窄屏强制统一并可收起文件栏。二进制/链接/子模块与模式变化保留元信息；正文按选中侧的类型/大小和读取原因识别不可展示内容，即使后端返回空 text，也不报空文件或已读到末尾。超限/不可用/不存在不冒充空文件或无差异。正文选区沿用文本引用，附路径、比较方向与采样出处，不新增代码语义目标或模型按钮。

仅前台代码页签按轮询偏好进行 single-flight 状态探测；状态变化只提示「加载最新」，不替换文件内容、选区或滚动位置。显式刷新才更新索引与选中文件；续读同时核对工作区 revision 和 file_revision，禁止把两个版本的文件片段拼接；`content.line_continued=true` 时核对字符偏移/行号并接入上一段的最后一行，不额外插入换行或重复行号，缺失该字段按 false 兼容。取消/切换后迟到响应作废。文件上的「在执行记录中搜索此路径」切回同级页签并清空旧类型/工具/失败过滤，只做路径文字搜索，不宣称修改因果定位。

### 性能分析（W308／D671、D672）

D672 修正首版的计划阶段视角：性能页签只分析当前 Worker 实际执行的 Bash／Shell 命令，默认突出「慢指令」与「重复失败指令（返工线索）」，不再列计划阶段排行，也不将 read／edit 等请求混入。慢指令默认按单次最长排序，可切累计尝试耗时；重复失败须同一完整身份至少两次明确失败，默认按失败尝试累计耗时排序，也可按失败次数。卡片展示命令、其余参数、已知耗时／未知数、失败／执行次数与最近结果；逐次尝试按需展开，直接定位对应指令及配对输出。窄屏两类排行纵向排列，命令换行、控件可换行。

性能页通过 `performance-data.js` 的 `commandsOnly` 路径读取 `transcript-search`，首次最多100条执行记录；只有点击「分析全部历史」才继续分页，总计最多5000条／8 MiB保留元数据。不请求独立计划、生命周期或后代读面，也不保留身份 inspect 附带的计划字段；不缓存工具输出正文，命令身份与有界预览采用上述服务端投影。不可核验完整身份的尝试逐次独立成组，不凭相同预览合并。取消、切页、关闭作废在途读取，错误／预算／缺证据明确局部或未知；切回保留排序、采样和滚动，刷新分析才重新采样，不后台轮询或调用模型。

`analyzeShellCommands` 复用同会话唯一调用与结果的配对及计时规则。配对结果须 `error_known:true` 才分类明确成功或失败，再按 `is_error` 布尔值区分；缺结果、重复身份或多结果保持未知。失败事实与计时独立：明确失败但缺时间仍计失败次数，不补零时长。完整命令／参数按精确指纹归组，命令空白、路径、timeout等变化均不自动视为同一问题。累计为已知单次记录间隔之和，不是并行墙钟时间，不包含尝试间隙中的思考／编辑／等待；失败累计只是返工线索，不宣称已证实全部返工时间。

性能排行只保留代表性主流程，不再保留完整模型／数据／DOM／API 独立组合；覆盖取舍见[贡献指南](../contributing/README.md#覆盖取舍)。`test/web/check-navigation-links-browser.js` 仍可验证新标签页及真实窄屏布局。

### Worker 详情渐进加载

`detail.js` 在 Worker 主体成功读取后立即显示原始目标、状态、最新结果与可用操作；仅仍属于当前项目/页面/请求并已成功渲染时返回 `true`，告知查看据此发出独立的已读 ACK。核心 inspect 是第一个请求，绘制后再补齐事件历史、必要用量与本地连接名称，不作为打开成功的前置条件；W185：改动概览不再套「查看改动概览」折叠层，主体绘制后自动渐进读取 diff，不阻塞打开成功或告知 ACK；同 Worker 刷新保留正文与文件明细展开状态。公开连接名称按项目/boot 内存缓存 30 秒、相关成功 action 后失效；导航/boot 取消旧 HTTP 只读请求，仍检查页面身份。加载中、读取失败和没有记录分别标明，不冒充零消耗或零改动。完整边界见 [Web 性能](web-performance.md#worker-详情)。

`renderDetail` 的可选渐进控制器按区补齐，不重画整页。目标/结果原文、手动折叠、表单与阅读位置保留；详情内焦点或选区期间暂缓补丁，失去焦点/取消选区后再应用。最多保留四类待补丁，新请求、导航、项目切换或 Worker 删除使旧补丁失效并释放监听。过往计划首屏随 Worker 主体展示，更早版本仍显式按需分页；补充数据不替换历史节点、已加载页面或展开版本，同 Worker 主体请求在途时也保留用户最新阅读位置及历史锚点。执行记录仍只在显式打开时读取，已打开记录的终态尾读独立运行，不拖住主体或告知 ACK。慢用量不阻塞正文；游标竞争响应不得标记尾读完成，仍有后页时继续读取。

渐进加载异常与迟到响应组合不再专用回归；`scripts/check-input-history-ui.js` 仍可用隔离 HTTP fixture 与 Firefox 验证真实应用输入/详情/告知的组合等待边界。

### Worker 详情模块预览

Worker 详情的输入输出（目标、各轮回复与简短决策问答）、时间线（调用与等待阶段，原始事件／通信按需展开）、计划（含折叠历史）、错误、Agent 信息、状态、代码与提交、Worker 关系（含双向依赖）和决策记录等阅读模块，由 `detail-preview.js` 选择阅读区、复用 `shared-module.js` 对**整个模块**提供高度预览：收起后的正文高度为 `min(400px,50dvh)`；只有自然正文高度超过该高度 **120px** 才默认收起，等于或处于余量内时完整显示，不裁剪也不显示多余按钮。明显超长的模块不因消息或历史条目数量增长而无限拉长，仅在标题右上角提供「展开完整内容 / 收起」，收起且实际被裁剪的正文在底部最多 96px（不超过预览高度的 35%）内逐渐淡出，直观提示下方仍有内容；预览说明仅供读屏，不再显示小字页脚或重复按钮。短模块与展开后的正文不加渐隐，遮罩随主题背景自然融合，不添加拦截点击或选区的覆盖层。展开后沿用页面主滚动，不为正文新增内层纵向滚动条。

详情顶层模块的标题行在本模块范围内吸顶：桌面贴详情滚动区顶部，手机贴固定导航条下方；进入下一模块时上一标题随模块离开，不堆叠、不复制按钮。展开后的「收起」始终留在这条标题行，继续使用原有键盘、帮助和折叠语义。

刷新不只保存 scrollTop：`detail-reading.js` 复用 `module-reading.js` 记录当前可见模块的正文锚点与屏幕坐标，主体重绘、渐进补丁和 ResizeObserver 检测到的上方模块高度变化都会补偿该坐标；桌面调整详情滚动，手机调整页面滚动。相同 Worker 再验证保留已成功读取的历史、用量、来源和 diff 正文，不先退回占位再膨胀。显式展开/收起、引用导航、用户滚动及窗口尺寸变化优先，不强行回到旧位置；模块/正文消失时尽量回退到模块位置或原滚动量，不承诺内容已被移除时仍逐像素固定。原生滚动锚定在 Worker 详情内关闭，避免双重补偿。离页释放几何观察器和滚动监听。

这是展示限高，不是数据截断：不删除 DOM、Markdown 或引用，不改变原有历史分页，也不影响全屏执行详情。相同 Worker 的刷新保留模块手动状态，已有目标、结果和消息节点照旧复用；切到另一 Worker 恢复预览。自然正文与高度上限分别由 ResizeObserver 观测（另观测模块外框保护阅读位置），涵盖按需历史加载、内容展开、窗口宽度以及仅高度变化。键盘聚焦正文内的控件、引用定位到正文时先自动展开，避免焦点或目标落在不可见区域；收起时把收起入口留在可见范围。操作栏、合并/验收控件、Hooks 与当前待决答复区不参与裁剪。

真实浏览器回归 `bun run test/web/check-detail-preview-browser.js` 使用隔离静态 fixture 与 Firefox；通过明确尺寸的 iframe 验证 1440／390／320px 和双主题下的模块预览、标题吸顶及模块末尾退场、吸顶收起、主体刷新、补充历史/用量和异步上方正文增长时的阅读位置，不启动用户 daemon 或模型。

决策记录的每条已回答／已忽略记录默认展开，用户仍可手动收起；同 Worker 刷新保留手动状态。整个模块仍遵循上述超长内容预览，不改变决策答复或历史只读边界。

### Valet 接口调用时间线

Valet 详情在「Valet 管理状态」旁新增独立的「接口调用时间线」，不改变其他模块层级。默认按开始 Event ID 正序，以单行摘要展示时间、真实 RPC method、目标和状态；Event ID 是持久身份，不是全历史调用序号。长字段省略，窄屏将时间与 Event 身份移入详情，保留接口、目标和状态；失败／未知保留不压缩的明确标识。每条默认收起，点击整行或聚焦后按 Enter／空格展开、收起，原生 disclosure 与 `aria-expanded` 表达状态。完整状态、脱敏参数、结果摘要、传输入口、Run 和耗时在展开区正常换行阅读，无任意原文入口。正序／逆序只重排已加载节点，不改变游标或记录，保留展开、焦点、选区与阅读锚点；「全部展开／全部收起」也作为随后更早分页和新增调用的默认模式，不自动展开或读取关联安全时间线。排序、逐条手动状态及全局模式在同一详情刷新时保留，切 Worker／项目／页面身份后重置。RPC 已返回与当时收据的待确认、等待安全点、拒绝、unknown 分开表达；只有当前 management 投影的精确 receipt ID（能力同时核对 method）可以更新已显示收据状态，缺少证据不推断。事件及安全覆盖契约以[管家接口调用事件流](hook-signals-management.md#管家接口调用事件流)为准。

每条失败或未知调用展开后显示最初失败阶段、受控分类原因／明确未知、副作用确定性、后续事项／停用／隔离／取消与下一步；后续处置不替换原失败。旧收据缺字段明确无法还原，不根据异常字符串猜根因。显示与「复制脱敏诊断」共用 `management-diagnostic-model.js` 的前端白名单投影：复制当前摘要、可信身份与**已读取**安全事件，不夹带任意 reason、参数、输出或凭证，也不宣称未读时间线完整。剪贴板不可用保留正文并明确失败；复制与关联导航不调用 Agent、不重放操作。能力提交与动作独立展示：同一调用可同时有 capability 的 applied 和关联 action 的 waiting／unknown；动作失败在展开区单独显示原错、确定性与下一步，不用提交成功覆盖。专用 start／retry 按真实 action 收据刷新，重复传输保留各自 call/request Event 关联；request_returned 只表示缺少完成证明，不伪装为旧数据或未开始。

「关联身份与安全时间线」显式展开后，经固定[HTTP 只读适配](../reference/web-routes.md)读取 `management.receipt`，一次30项、按实际事件游标继续；同一模块最多500关联事件／512 KiB，失败、缺页或预算不足保留已读内容并明示未完成。只接收当前 Worker 关联、受控 coverage 与递增实际游标，跨页面／项目／document 或取消后的迟到响应作废。只有持久事实才提供草稿、真实 O／Message、Worker 或单收据链接，未知挂载不生成输入链接；挂载确认不表示 Worker 已创建／开始。

已加载窗口含失败／未知时，整个接口调用模块保持逻辑展开且不允许高度预览把单行异常标识裁掉（健康窗口仍用共享预览）；不会自动展开任何调用详情，详细诊断、复制和关联入口统一放在该条展开区。窄屏摘要仍为单行，诊断按钮／链接／展开入口至少44px。

首屏仅取最新 50 个事件，向旧分页与向新续读分别保留边界；翻旧不回退最高已读 Event。完成事件独立自含开始信息，按 call_id 合并，不按相邻项配对，迟到的 started 不覆盖 finished。每次现有详情刷新最多读一页新增事件；has_more 保留「继续读取最新调用」，不自动扫描全历史。已显示的未完成调用通过精确开始 Event 的一条窗口重新读取服务端投影（每轮最多 50 项、余项显式继续且跨刷新保留核对队列），因此终态／Run 更换后即使 after 空页也能更新 unknown，不根据当前 Worker 状态伪造事件或完成结果。

同一详情保留分页、节点、展开、焦点、选区和阅读锚点，选择正文时延后补丁；项目、boot、document、页面和 AbortSignal 共同隔离迟到结果，离页取消读取和监听。不新增定时器、模型或进程。最多保留 5000 个事件／8 MiB 调用快照，预算触顶保留正文并明确部分范围。失败与旧服务不支持明确为不可用、可重试，不冒充无记录；空页不证明旧历史未调用。展开区在窄屏自然换行，整个模块复用共享超高预览与页面主滚动。

专项 `test/web/dom-management-calls.test.js` 覆盖配对、分页、迟到／取消、失败、精确收据与 unknown 更新；`test/web/dom-management-diagnostic.test.js` 以可控 Provider／真实 bridge 产生失败及真实 HTTP 读取，核对原失败与隔离、白名单摘要／复制一致性、旧数据、关联链接、缺页／失败／迟到响应；`bun run test/web/check-management-calls-browser.js` 使用隔离 HTTP fixture 和 Firefox，核对真实 HTTP 分页、1440／390／320px 单行省略与异常标识、键盘逐条展开、正逆序、跨页全局折叠模式、刷新节点／焦点／选区及终态投影，不启动用户服务或模型。

### 规划历史

Worker 详情先展示当前「Worker 计划」，其后「过往计划」按归档事件从新到旧排列；各版本默认折叠，可独立展开并比较步骤、冻结用时和当时完成度。摘要显示归档时间及「收到追加输入 / 调整计划」原因。实际计划变化保留旧版；追加用户输入后的新计划从未完成开始，其他页面的进度摘要只看当前计划。

首屏消费 `worker.inspect.progress_history` 的最新窗口，默认最多 10 条；「加载更早计划」以 Event ID 游标请求 `GET /api/worker/<内部ID>/progress-history?before=<cursor>&limit=10`，按需加载，失败保留原有正文并提供重试，耗尽明确显示「没有更早的计划了」。相同 Worker 刷新保留版本折叠、已加载分页、键盘焦点及阅读位置；切换 Worker 或离页不复用旧分页，也不接受迟到响应。整个历史区纳入详情模块高度预览，展开后仍使用页面主滚动。历史只展示冻结数值，即使记录残留 `active_since` / `started_at` 也不会实时增长或显示正在执行，不受当前 Worker 失败/取消状态影响；「进度汇报」关闭时历史一并隐藏，旧服务缺读面时不伪装成无历史。

### 输入输出与 Worker 生命周期时间线（W303／D666）

D666 取代 W232／D544 的统一时间线。`render-conversation.js` 保留 `renderConversation` 接缝和 `.conversation-panel`，标题为「输入输出」：默认用户输入、各轮回复及简短决策摘要，来源不明旧内容默认隐藏；提供「只看 Agent 回复／只看我的输入／全部内容」。普通生命周期、系统元数据和 Worker 通信既不混入正文，也不作为内容搜索命中；已知决策原文、类型与答复来源按精确证据保留。原始目标、追加输入及各轮结果仍使用真实投递时间、Run/Event/Message 去重、完整原文与逐条展开，不把独立调用的相同回复合并。

`render-worker-timeline.js` 独立渲染「时间线」，`worker-lifecycle-model.js` 从 Run 与既有历史读面投影调用、阶段和等待区间，默认显示当前状态、已知等待对象、起止与时长、所选输入批次来源、关键失败／受阻和交付节点。持久观察字段以 [invocation 契约](invocation.md#生命周期观察事件version-1) 为准；观察阶段不代替 Worker status 或交付事实。输入批次不表示唯一唤醒者，实际投递仍须同 Run 的确认事件。安全元数据受限时提示对象／来源可能未列全，可显式读取完整安全原文补齐。历史缺证据的调用间隔只标等待原因未知；不拿 updated_at、后来的子 Worker 状态或不连续页面猜起点／完整时长。

时间线的「完整事件与通信」默认收起，原记录按需展开和分段读取。输入输出／事件引用分别在所属模块定位；非内容引用由输入输出返回 null，再交给时间线定点补读，不为兼容引用把事件塞回对话。调用可一键定位对应回复。两个模块各自保留排序、分页、搜索、原文、节点和展开状态；离页取消读取，拒绝迟到响应，不自动遍历全历史、不调用 Agent。详情主模块依次为自动化、计划、输入输出、时间线、Agent、代码与提交、决策记录、Worker 关系（已有版本迭代等模块保留其接缝）；异常摘要和后置诊断沿用 D551。窄屏单列、控件换行、触控入口至少 44px，两个模块分别沿用共享超高预览与页面主滚动。

新增用户专属 `worker.reading_page`（HTTP `reading-page`）分别按 Event / Message 游标扫描默认每类50条、最多100条的窗口，覆盖孤立旧收件箱行，不依赖 inspect 最近100条或旧 `history_page` 的字节裁剪。正文预览至多24,000 UTF-16字符，明确标注 `text_truncated/total_chars`；`worker.reading_record`（HTTP `reading-record`）按相同字符位置分段读取正文或脱敏元数据，精确文本与安全边界见[完整历史协议](../reference/rpc/tasks.md#输入与结果完整历史读面)。输入输出每条记录在消息头提供「复制原文」，不再另设「查看完整原文」折叠入口；复制保留原始 Markdown／JSON 文本，正文中的代码块另提供「复制代码」。复制尚未读完的记录时显式分段读取，沿用单条 8 MiB（UTF-16）预算，可取消；读取失败、超限或离页时不复制部分正文，也不报告成功。时间线保留按需原文阅读。分页耗尽与正文完整是不同事实。

关键词按 Enter／「搜索」提交，键入草稿不重建列表。输入输出只匹配内容正文及已证实的决策摘要；时间线高级区匹配正文、事件类型与安全元数据。完整历史查找均须显式启动，分页检查完整解码后的正文；输入输出继续做内容资格校验，不把通信／元数据命中混入内容。无命中页仍推进事件与消息独立游标，显示扫描量、范围（不含执行过程）、失败与取消，不后台补扫。远端完整正文命中的长记录即使预览不含关键词仍展示，可继续读取原文。取消、导航、boot 或新读取使旧请求失效，迟到响应不发布；同 Worker 刷新保留关键词、排序、展开与未变化正文节点。每个面板分别采用 8 MiB（UTF-16）正文及 5000 条记录预算；触顶／不可读明确未完成、保留已有阅读，不把截断当完成或成功无命中。

身份依据真实 sender / typed signal / 持久追加编号／明确 message Event，不能根据正文 JSON 外观判断；Notice 答复由 `notice.answered.answer_source` 区分用户／Lush，缺证据标未知。没有可验证关联的旧 Notice 收件箱原文仍单独保留为来源不明，不凭相同正文强行合并。普通追加输入同时提供 message 与 history_event 引用；最新结果提供 result 引用。消息／事件引用定点请求对应ID前一条有界窗口，不扫描整段历史，先显露目标再按原有模块预览规则展开并闪烁。

以下 W182／W201 说明仅保留历史来源与身份规则；模块名称、分类开关、通信归属及分页按上述 D666 当前契约。

W182／用户决定 #440：`render-conversation.js` 将原始目标、明确来自用户的追加输入与各轮结果统一为「对话」。用户气泡靠右，Worker 气泡靠左，顶部一行有不同头像、发送方名称、输入／结果类型与时间；W185 增加分类筛选，W201／用户决定 #472 将其明确为「用户输入 / Worker 输出 / 系统与 Worker 通信」三个复选项，前两项默认勾选，通信默认不勾选；同 Worker 刷新保留选择，切 Worker 恢复默认。通信保持靠左，以独立的来源、通信类型、时间和边框区分当前 Worker 结果；左右表示发送方身份，不表示数据流的输入／输出。通信包含有来源证据的入站 Worker 消息与系统信号，按消息 ID 合并收件箱与历史事件，不冒充用户输入、Worker 结果或真实投递时间；发往其他 Worker 的消息不进入此分类。历史事件附带 `event.message` 本身不足以证明系统来源：只有非空发送方、显式 `signal_type` 或 `task.signal` 事件证据才能纳入通信；用户输入的路由、暂存与释放事件只留在历史，不新增气泡，跨页／刷新也不能重复显示。用户粘贴的 JSON 不因此改变身份。通信正文复用 `renderTaskMessageBody`：已知信号／历史结算／决策答复显示语义标题、正文和关键字段，未知对象／数组使用有界结构树，损坏 JSON 回退安全文本；每条保留惰性完整原文入口与原始消息／事件引用，刷新保留已展开节点。（历史独立消息模块已由 W214 输入与结果整合取代。）默认最新在前，标题行的正序／倒序按钮只重排已加载节点，不请求模型、不改变记录；同 Worker 刷新保留当前顺序与逐消息展开状态，切 Worker 恢复默认。

输入时间只用服务端投递证据，待投递显示「待输入」、历史缺证据显示「输入时间未知」；结果时间只用 run 的完成时间或完成事件，不以 Worker 更新时间或开始时间冒充。待输入的页面位置可借提交事件排序，但不将其显示成投递时间。没有完成记录的最新结果标明「结果时间未知」，放在最新一端；历史缺时间只能稳定排列，不能承诺精确时序。

初始合并 `worker.inspect.runs` 与已加载 `invocation.completed` 事件，按 run ID 去重，只把最新一次与 `Worker.result` 对应的结果合成一条，独立调用的重复文本仍保留。原始输入与各轮输入／结果按真实时间交错，更早内容经既有 `worker.history_page` 的单一游标逐页加载（包括没有对话内容的事件页）；不把首屏窗口当成完整历史。刷新保留已加载的旧页与最早游标，失败可重试，加载中／不可用与已读完明确区分。最新结果保留 `result` 引用，历史结果与追加输入引用不可变事件。

对话整体沿用模块预览与吸顶；每条明显超长的消息另提供「展开消息 / 收起消息」，正文预览为 `min(260px,35dvh)`，自然高度超过上限 60px 才裁剪。完整 Markdown／原文始终保留在 DOM，展开不增加纵向滚动条；消息头在展开的对话内贴模块标题下方，随自己的气泡离开。键盘聚焦或引用定位先显露消息及整个模块。

在真实终端里使用原生只读 `lush worker watch ID [--after N]`；Web「Agent」块提供复制入口，已知来源时固定并 Shell 引用 `--project`。原生观看器使用 Pi 公开渲染组件及 `worker.transcript_page` 连续分段读面；只读取已完成记录，不新增 RPC、AgentSession、Pi 子进程、模型调用或执行入口，不写会话、不加载用户扩展，具体边界与上限见[原生观看器](../native-viewer.md)。

纯文本持续跟随的 CLI、Web 入口与循环实现已删除，不保留兼容别名。`lush worker transcript ID [--after N]` 仍是用户单次查询；开发 Agent 使用 `lushw self transcript` 或 `lushw children transcript ID` 的关系入口，支持 JSON，不会轮询。原生观看仅用户可运行，agent token 会被拒绝，`--json` 不适用且须真实 TTY。`worker.transcript_latest` 继续服务 Web 阅读器，不因删除 CLI 跟随而移除后端读面。

## 专用解释 Agent（历史实现）

`explanation.*` / `intro.*` 已从 `src/rpc/registry.js` 移除，不再有公开 RPC / CLI / Web 入口；下面的实现与测试仍存在于源码中，只为读懂历史记录与后续清理，不能当作当前可操作的能力。当前执行记录由 `worker.transcript*` 及受限关系接口 `context.transcript` 提供，具体权限见[双入口契约](../reference/api.md#开发与管理双入口)。

选中执行记录中的 1–8,192 字文字，右键“介绍：目的、原理与结果含义”，直接创建 `explainer` 根 Worker；不创建 Input、开发分支或 worktree，也不附着在可能已终态的源 Worker 下。

- 来源快照写入现有 `explanation.requested` Event，包含选区、Worker目标、所属步骤首段、配对输入输出摘要、来源编号与时间，截断有标记。
- Worker.result 保存解释；Worker / Agent / Run 沿用现有生命周期、并发、取消、重试与恢复规则，不增加业务实体或 schema。
- 结果在独立旁侧面板显示，关闭面板只停止客户端读取，不取消解释Worker；完成后从源Worker的“解释历史”回看，支持更早历史分页。
- 模型须区分目的推断、机制背景和结果事实；资料不足时明确说明。原日志是资料，不是指令。

权限不仅依赖提示词：Pi 使用 `--no-tools --no-extensions --no-skills --no-context-files --no-approve`，不加载 profile 中的扩展和 Skills；启动消息直接附带运行时准备的资料文件，不需要模型用 read 工具读取。子进程不获 invocation token，runtime 也拒绝 explainer actor 的 RPC 和派工。

可以在 Agent 设置中为 explainer 配置 Pi 模型／思考等级／提示词与环境。Codex 尚没有在本实现中验证等价的无工具模式，因此选择 Codex 时明确拒绝，不以开发权限降级运行。Mock 可用于离线测试，但不会伪装为真实模型解释。

## 结构化渲染

通用工具输出与嵌套参数若为合法 JSON 对象／数组，显示根层默认展开、子层按需展开的键树并保留“查看原文”；字符串直接呈现换行，不用 `JSON.stringify` 把正文变成字面 `\\n`。最多 12 层、每分支 100 个子节点、每棵树 1,500 节点；到限提示查看原文。非法／截断 JSON 回退纯文本。所有内容经 DOM 文本节点写入，不解释 HTML。

结构视图是辅助预览；JavaScript JSON 数值显示可能涉及浮点精度，精确数值与原始空白以原文为准。Markdown 回答与思考仍走原有安全渲染；这里只为工具数据增加结构视图。

## 接口

以下新增 RPC 均为用户专属，不接受 Agent token；读取仍在认证后的 Web 边界内：

| RPC | 参数 | 返回 |
|---|---|---|
| `worker.transcript_search` | `id, query?, kind?, tool?, errors?, after?, limit?` | `steps, next, has_more, files, scope`；limit 默认 50，最大 100 |
| `worker.transcript_latest` | `id, after?, before?, limit?`（默认 0 / 0 / 100） | `steps, next, oldest, has_older, files, truncated`；最新优先窗口，limit 最大 200 |
| `worker.transcript_page` | `id, seq?, offset?`（默认 1 / 0） | `steps, next_seq, next_offset, has_more, files, scope` |
| `worker.transcript_step` | `id, seq, offset?` | `step, offset, next_offset, has_more, related, context` 与配对限制标记 |
| `explanation.start`（历史，无公开入口） | `id, seq, quote` | 新解释Worker的状态、来源快照 |
| `explanation.list`（历史，无公开入口） | 源Worker `id, before?` | `explanations, next, has_more`，每页 50 条 |
| `explanation.get`（历史，无公开入口） | 解释Worker `id` | `id, status, result, error, source` |

GET 路由：`/api/worker/<id>/transcript-latest`、`/api/worker/<id>/transcript-page`、`/api/worker/<id>/transcript-search`、`/api/worker/<id>/transcript-step`。`/api/worker/<id>/explanations` 与 `/api/explanation/<id>` 仍在源码里，但不在 `CORE_WORKER_READ` 白名单内，会被统一 404。
