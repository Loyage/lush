# 归并合并方案：异常、迭代与恢复

本篇覆盖 W205／D482 的边界场景，**均为拟议行为，尚未实现**。归并不放宽[消息](modules.md#冻结期间的-worker-追加输入w153--决定-376)、[验收](worker-acceptance.md)与[未知副作用](git-boundary.md)的安全原则；需要替换的现有假设列在[实施方案](merge-convergence-rollout.md)。

阅读路线：[产品与理念](../design/merge-convergence.md) → [算法与架构](merge-convergence-protocol.md) → **异常与迭代（本篇）** → [实施与验证](merge-convergence-rollout.md)。

## 1. 状态必须分层

源交付状态：`pending → queued → preparing → validating → ready → landing → integrated`；`withdrawn` 仅在发布未开始时可达。成员经历组合变化时关联新 generation，不通过旧消息倒退或结算。

节点状态：`planned → computing → ready`；需要 Agent 为 `resolving`，问用户为 `awaiting`，明确失败为 `failed`。来源变化为 `stale`，不能继续晋级。

发布状态：`prepared → applying → integrated`；现场未知为 `blocked`。节点失败不是父现场 blocked；父现场 blocked 也不能冒充只是重跑一遍组合。来源测试失败、组合测试失败与发布故障分开显示。

对当前协议须保留 version 隔离，不能把上述新枚举直接写进现有 v2 预约。恢复只根据持久状态与精确收据，不根据 UI 文字或 Agent 自称完成。

## 2. 典型场景与处理

| 场景 | 行为与保留边界 |
|---|---|
| 只有一项、奇数项 | 同一管线发布；不等伙伴、不等待二的幂 |
| 新成果持续到来 | 未封闭批次可继续配对；已验证成员不扩张，新成果形成下一批 |
| 无代码回答 | 交付结果，不制造空 Squash；仍有独立 Worker 结果与安全验收 |
| 组合最终树等于 B | 可作为有精确零变更收据的交付结算，但须说明重复贡献/抵消情况，不能据“相等”猜来源曾落地 |
| 两项改同一文件却无冲突 | 正常对象合成，运行受影响与最终验证；文件重叠不是必然阻塞 |
| 两项改不同文件却接口不兼容 | 由组合测试、风险审查或显式依赖识别，进入隔离整合；不把无文本冲突当质量证明 |
| 二进制、改名/删除、子模块等 | 先检测 Git 能力和项目支持，冲突不强制选边；不支持则明确暂停该组合 |
| 同一成果被两个组合领取 | 唯一成员归属与 CAS 拒绝第二次领取；多父进程不能靠内存 Set 去重 |
| 多个真实父目标 | 分别准备、晋级与发布；永不跨目标混成一个批次 |
| 子、孙成果尚活动 | 不准固定父向上交付；先进入直接父，再由父整合成果向上发布 |
| 父正在开发、同步或向上交付 | 可做基于固定历史的隔离准备；真实发布等父安全点，父向上已冻结则子不能落地 |
| 脏源 worktree | 不准固定交付，不自动提交或丢弃；已固定后外部变脏则阻止晋级/发布 |
| 脏父 worktree、外部 ref 前进 | 拒绝真实写入，保留用户现场；更新基线后重新验证，不覆盖旧 tip |
| 来源 ref 被外部改写或删除 | 标 stale/待核查，停止相关候选；不能只凭固定对象还在便忽略源身份漂移 |
| Agent/model 额度不足、并发槽不足 | 明确等待资源与费用来源；让无依赖就绪组合晋级，不切换付费账号、不循环唤醒 |
| 暂停项目或安全关闭 | 停止新领取，收口短写入；测试/Agent 按受控取消留状态，恢复不重放未知动作 |

零变更组合若存在相互取消的来源，必须揭示抵消与整合说明；预期行为存在歧义时问用户，不为了吞吐自动认可两项需求互相覆盖。项目测试成功也不能证明两条用户需求都已满足。

## 3. 一个阻塞，不能拖住全部

A+B 等待用户时，C+D 可以独立验证并发布；A/B 不设置 merged，也不占真实父写门。C+D 推进了父后，A+B 必须适配新基线，旧测试不能直接用于落地。

如果阻塞在更高节点 `(A+B)+(C+D)`，可把不依赖阻塞部分的已就绪子组合单独晋级；保留被阻塞节点与证据，原根标失效。**不能从修复后的最终树里直接减掉 A/B**：修复可能交织双方行为，必须从固定子成果重建新候选。

拆分必须检查显式上游与已知语义适配依赖；未知是否可拆时先问用户。没有记录的依赖可能遗漏，因此拆出的组合仍做对当前父的完整最终验证。依赖方不能因另一个组合 blocked 就偷偷越级。

组合测试失败可用已验证子组合和有界最小化诊断定位，不能把失败机械归咎于“最后一个 Worker”；测试可能非确定，跨模块错误也不单调。诊断不能自动撤销任何已落地批次，不能无限二分反复调用模型。

## 4. 追加输入、撤回与取消

源冻结期间新消息立即持久保存，按现有规则暂存；不混入整合尝试或修改已固定成员。详情显示“本轮交付后还有追加输入”，暂存输入不阻止这份固定交付收口，但阻止验收。

发布成功、整体解冻且 invocation 真正退出后，同一 Worker 接收下一轮输入。后续交付只取本轮新增变化；不创建替代 Worker，不重新交付已纳入批次的旧内容。

用户希望立刻改变本轮时可明确撤回：DB 原子使成员失效、使受影响祖先 stale，停止相关整合晋级；等待当前调用安全退出后再释放源冻结、投递追加输入。共享子组合不得一并取消；未知调用副作用保留诊断。

- 发布尚未开始：撤回成员保留原代码和入队审计，剩余成员重建候选。
- 发布已开始：不得当作撤回成功；返回“发布中，需先核查结果”，客户端保留操作意图，不后台盲重试。
- 已实际落地：即使 DB 尚未收口，按精确收据恢复；取消不能撤销 Git，改变代码需新的修复指令。
- 取消 Worker：沿用用户权限和真实后代边界；若它仍有待发布成员，先按上述阶段受检撤出。不得删除兄弟成果或直接丢掉未提交现场。

Agent 不获得取消、撤回或改变自动链的新权限。关闭未来自动合并仍不等于撤销已固定交付。

## 5. 发布与恢复的故障窗口

| 中断点 | 恢复规则 |
|---|---|
| 等待项已持久，尚未计算 | 重建调度、继续明确未执行的纯准备；不重复创建 Worker |
| 固定对象计算完成，节点结果未记 | 依据固定输入重算纯对象，或核验精确输出；不能推断 Agent 修复完成 |
| 整合 Agent 已开始、结果不明 | 标 unknown，保留会话与 worktree，显式检查/重试；旧 token 无效 |
| 最终测试中断 | 记未完成，无通过证据；可显式重跑固定候选测试，不冒充前次通过 |
| 已持久 L，尚未写父 | 仅证明 ref 与现场无变化后才重新准入；“未落地”与“落地未知”分开 |
| 父 index/worktree 部分更新、ref 未推进 | 同目标 blocked，保留现场与写门诊断，禁止下一批进入；不 reset/clean 自动修好 |
| Git 已发布 L，DB 未结算 | 精确核验 L/B/T、成员/generation、检出与目标祖先，再一个事务结算完整成员，绝不重发第二个提交 |
| DB 已结算，通知/HTTP ACK 丢失 | 返回已有收据，按事件身份去重；刷新不重发发布、验收或 Hook 命令 |

DB 事务把全部成员的 integrated、来源收据与父 head 一起结算，避免“Git 整批进入，部分 Worker 仍被再次排队”。成员清单和 digest 随落地记录持久保存，恢复不能只看当前可变的批次成员。

如果外部 Git 后来推进父，L 仍为祖先可证明这次交付曾落地；若精确 L 消失，不允许用类似标题或等价树修补历史。外部 revert 是新代码变化，不会抹掉原交付事实；后续输入从当前父重新整合，不能自动把已撤销需求再补回来。

## 6. 通知、Hook 与验收

成员各自生成一次 `delivery.integrated` 事实与来源报告，保持原编号；child 完成信号按父当前聚合规则唤醒，不因一个批次的多个通知并发启动同一个父 Agent。

父 `worker.merge_received` 应以**实际发布批次**为一次触发，带完整成员与本次精确提交；默认推送等命令执行一次，而非成员数次。只有待执行项自动沿安全门恢复，Shell 的未知副作用仍不重放。拟议变化须版本化触发 payload 与说明，历史逐 Worker 触发不迁移、不补发。

普通成功交付按现有最高自动级别告知；归并过程静默，一次失败/待决指向相关组合并列来源，不制造每层一条提醒。Notice 的问题仍用 D、告知用 N，编号来自真实记录，不构造新的“批次编号”替代 Worker 或原始 O 输入。

验收继续核对每个源 Worker 的消息、待决、清洁度、未交付新提交、调用退出、后代与来源收据。一个 main 提交共享多个成员，**不授权验收其他独立指令**；child 仍默认保留，尽量随其真实父的安全验收回收。

整合 Worker 是基础设施辅助身份，产物交付不走普通向上合并、不冒充用户验收。成功且已静息的辅助产物不得被普通后代等待门误判为仍在开发；失败/活动辅助调用必须阻止相关发布。辅助身份与归并缓存回收的细分规则见下节。

## 7. 私有资源与历史保留

纯计算只保留固定 Git 对象/私有 ref，需要测试或 Agent 时才建立登记过的独立检出，限制数量、字节与并发。对象跨节点共享时先查使用者，不能移除仍有活跃引用的资源。

纯计算/测试 scratch 可在精确发布收据、结果证据已持久且无使用者后受检回收。**整合 Worker 的 worktree、ref、会话现场不在这类自动缓存清理里**：成功辅助 Worker 保留待验收，直到其全部关联源交付所属 Worker 已安全验收、且没有活动调用/追加输入/新尝试/脏现场时，作为内部附属资源安全收口；或用户明确提前清理。不连带验收源 Worker，不继承任何源的自动验收级别。

失败/unknown 现场默认保留供检查；部分回收保留逐资源收据，可显式续办，不凭目录缺失猜成功。批次元数据、成员收据、测试摘要、整合历史与固定来源对象须在使用者存在时保留；删除源 Worker 需额外检查运行、节点、其他成员及共享证据，不能破坏活跃批次。
