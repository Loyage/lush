# 一次性整合：异常、迭代与恢复

本篇说明实际失败边界，不把旧两两树的子集绕行当作新能力。当前范围见[实施接缝](merge-convergence-implementation.md)，公共状态及操作参数见[接口参考](../reference/rpc/convergence.md)。[消息](../reference/rpc/tasks.md#追加消息的准入与失败处理)、[验收](worker-acceptance.md)与[Git 边界](git-boundary.md)不因整合放宽。

阅读路线：[产品理念](../design/merge-convergence.md) → [持久协议](merge-convergence-protocol.md) → **异常与恢复（本篇）** → [验证范围](merge-convergence-rollout.md)。

## 准入与固定集合

| 场景 | 当前行为 |
|---|---|
| 无可准入增量／无代码回答 | 预检列原因；不创建空整合 Worker。回答仍按原流程交付与验收 |
| 一项、奇数项、超过八项 | 一个自主 Worker 处理全部固定来源；不等伙伴、不切旧容量批次 |
| 来源脏、未读／暂存输入、待决或未收拢后代 | 预检排除并说明原因，开始前再次原子复核 |
| 普通请求 executing／resolving、已有尝试或未知落地 | 不抢占，不把固定普通请求转换成整合成员 |
| 来源 ref／真实父谱系漂移 | 停止准入或候选推进，保留诊断，不仅凭对象还在认定身份有效 |
| 新来源在开始后完成 | 不加入当前集合；下一次用户预检决定是否开始新操作 |
| 不同真实父目标 | 各自操作，不跨层收集，不重挂来源 |
| 父仍开发、脏或同步／向上冻结 | 私有准备不代替真实发布安全点；父门不通过就不能落地 |

## 失败、待决与目标前进

任一来源的冲突、组合失败或待决都阻挡本操作整体落地，不能将成功子集先合入又称一次性整合。无文本冲突也必须调用 Agent 做语义审查与组合验证；文件是否重叠不是兼容性证明。

整合 Agent 提问后释放调用，答复后复用同一身份和现场。调用失败／异常退出保留私有工作区；显式重试重新核验精确 revision、固定来源、待决与实际退出，并开启新 generation。目标前进同样使旧候选与测试失效，要求 Agent 审查 previous_baseline..baseline、保留已有适配并重新验证；自动刷新超限后等待检查／显式重试。

外部持续修改、模型额度或认证失败不能保证及时完成。runtime 不擅自换付费账号、不循环重放未知模型调用，不承诺固定提速。需求或架构有歧义时由 Agent 通过自身 Notice 问用户，不能丢掉一个成员来取得“成功”。

## 追加输入、撤回与取消

固定来源的合法普通追加先持久暂存，不混入本次组合。实际解冻且调用退出后，同一 Worker 接收下一轮；验收仍受未读／暂存输入约束。后续增量按精确来源映射计算，不重复引入本次已 Squash 的旧内容。

用户取消的是整组操作，不是从已适配树中减掉某成员。来源侧既有撤回接缝遇到 one_shot 时也取消整组。generation 先失效，停止准备／Agent，等真实退出后才释放成员；源代码、私有产物与历史保留。原普通请求恢复为 suspended，不能在取消后悄悄自动写目标；用户可显式恢复普通合并或重新预检开始新整合。

landing 已开始或已有发布收据时拒绝取消／盲重试，先核查精确结果。取消不撤销已落地提交；需要改变代码时用新修复指令，单次 Squash 不保证可独立撤销某成员。关闭来源未来自动 Hook 也不撤销已固定整合。

## 发布与恢复故障窗口

| 中断点 | 恢复边界 |
|---|---|
| 已登记但从未开始的私有 Worker | 可按固定尝试调度，不再创建第二身份 |
| Agent 已开始但缺少真实退出／完整产物事实 | 保留现场，标失败／未知诊断；不以旧返回或 token 推进，不自动重放 |
| 有未处理 Notice | 不部分发布，答复后在同一 Worker 继续 |
| 已接受候选但目标变化 | 新尝试重新适配与验证，旧测试失效 |
| 已固定候选／收据但尚未写父 | 重新核验固定 refs、检出、generation 与安全门；不猜已落地 |
| 父 index／worktree 部分更新，结果未知 | blocked，保留现场与发布门，禁止 reset／clean 或下一次写入掩盖问题 |
| Git 已落地，DB 未结算 | 核验精确 commit／baseline／tree、成员、evidence 与目标祖先，然后原子结算全部成员；不重发 |
| DB 已结算，ACK 丢失 | 查询原操作；相同开始 revision 返回同一操作，不创建第二次整合 |

精确落地随后仍为目标祖先可证明它曾进入父历史；相同标题、树或 patch-id 不能替代该证明。外部 revert 是新代码变化，不抹去历史成功，也不授权自动补回被撤销需求。旧 command 验证中断仍是未知，不能自动转免命令路径。

## Hook、验收与私有资源

整组实际落地只触发一次父 worker.merge_received，来源分别保存合并映射与收据，编号、报告和直接父不变。Shell Hook 的未知副作用仍不重放；整合成功不等于推送成功。

来源验收继续检查调用、消息、待决、后代、清洁度、新提交与成员收据。一个 Squash 共享多个来源不授权验收独立指令；已交付 child 默认保留供追加需求，尽量随真实父安全验收。整合 Worker 不是普通向上合并的 child，也不以自己的 awaiting_acceptance 冒充目标 integrated。

辅助 worktree／ref／会话保留至全部关联来源已安全验收、无活动调用／新尝试／输入／待决／脏现场，才按原内部资源门收口；不能当作普通缓存提前删掉。活跃成员及共享证据阻止破坏性回收／删除，部分失败保留逐资源诊断，显式续办。验收详细边界以[统一验收](worker-acceptance.md)为准。

旧 v1／v2／固定 v3 继续各自恢复协议；历史两两节点、验证与收据不迁移、不改写，也不能按本篇的新整组取消语义重释旧历史。
