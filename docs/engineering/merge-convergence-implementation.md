# 一次性整合实施接缝

本文记录 W287／D646 已实现的后端行为与历史兼容边界。产品取舍见[一次性整合](../design/merge-convergence.md)，模块见[Runtime 地图](merge-convergence-runtime.md)，公共参数、CLI／HTTP 与读面以[接口参考](../reference/rpc/convergence.md)为唯一来源。代码合入不代表运行中的 daemon／Host 已更新；部署由用户在安全点分别更新两者。

## 显式触发与普通串行路径

一次性整合由用户先只读预检，再按读取的 revision 开始；固定当时全部可准入的同一真实直接父来源，不设旧八成员上限，不动态吸收后来完成的来源，也不拆成多次落地。目标支持真实 main／owner／order／child 分支；没有可准入来源时拒绝开始，不创建空 Worker。

普通单项与已经授权的自动合并继续原 v2 serial 路径，无论目标保留何种旧归并配置。它们可能在集中整合开始前处理某个来源；开始时必须重新核验完整集合，不能抢走 executing／resolving、已有固定尝试或未知落地的普通请求。

新 main、order、child 不再安装持续归并策略或初始化标记。历史策略、默认与旧验证引用仅兼容读取，不批量改写；两个策略 setter 明确返回 retired 错误，即使同值或旧 revision 也不假成功。来源自动合并／验收授权与 child 锁定流程不变。

## 固定成果与发布

开始经项目写门与串行 Git 区预检，在 SQLite 事务中复核来源静息、消息／暂存、待决、后代、真实谱系及未落地增量后原子领取。来源 ref、编号、parent_id、target_branch 不变；普通追加输入冻结暂存，不混入固定尝试。准备与 Agent 验证不长期占父执行位。

每次操作创建一个私有 integration Worker 和一个自主节点。即使没有文本冲突也由这个 Agent 审查全部来源，决定顺序／分组／适配并验证最终组合；runtime 不生成必经的两两树。输入包含固定目标、来源提交、精确增量基点及来源目标／报告；报告不是测试证明。私有产物必须保留目标基线和全部来源祖先，ancestry-only 不证明内容正确。

目标变化后保留私有成果与同一 Worker 身份，追加不可变的新尝试上下文，增加 generation，使旧候选与验证证据失效，由 Agent 审查目标新增变化、适配并重新验证。自动刷新最多三次，超限须检查后显式重试；不机械拼接后沿用旧测试，也不覆盖初始创建事件或重放旧 invocation。

整合调用必须真实退出、私有工作区干净且无未处理消息／决定，才接收候选。runtime 固定精确单父 Squash 与完整成员映射，通过新旧队列共用的目标发布门复核 generation、refs、候选树、检出与清洁度后受检写入一次。未知落地保留现场与写门，仅凭精确收据恢复；Git 已落地而 DB 未结算不得重发。

多轮增量优先使用已核验落地映射中的上次源提交及安全父同步基点，不能重套完整源历史或靠树相等／patch-id 猜已合并。来源单源树通常不等于组合树；同步、版本图、验收及删除均继续核验成员映射。一次落地只触发一次父 worker.merge_received，来源分别结算，互不合并身份。

## 验证责任与在途兼容

新操作固定 operation_mode=one_shot、verification_mode=agent、validation=null。整合 Agent 对最终组合负责：进入 main／owner 前做项目规定的集成与全量；进入开发父目标做受影响集成与回归，影响广泛则扩大。来源各自通过、无文本冲突、Agent 返回和 Git 安全落地都不是组合测试通过证明；runtime 不运行新组合的最终快捷指令，不制造 passed 或 tested_commit/tree。

旧 v1／v2／v3 不转换。历史 v3 的固定成员／两两节点继续原协议；旧 command 模式仍用隔离检出、实际指令版本与精确候选证据门。缺失／损坏模式或验证引用不能转免命令路径，未知模型或命令副作用不自动重放。旧算法的兼容范围见[协议](merge-convergence-protocol.md#历史-v3-两两算法仅在途兼容)。

取消使 generation 先失效并停止调用，待真实退出才释放全部成员；保留来源与私有代码。原有普通请求恢复为需显式恢复的 suspended，不在用户背后继续写目标。取消不是部分发布或撤销已落地提交；失败／待决保留整组，不能偷偷发布可成功子集。故障窗口见[恢复契约](merge-convergence-cases.md)。

## 方法与安全读面

公开接口只暴露计划、开始、读取、取消、重试；无任意 ref／cwd／Shell／profile 参数。worker.inspect 与 worker.graph 的 merge_operation 是同源有界摘要，完整成员由操作读取；旧 delivery_summary 与历史查询继续兼容，不要求新 UI 依赖旧交付模型。精确字段、限制与权限见[接口参考](../reference/rpc/convergence.md)。

整合 Worker 不走普通 child 向上合并，不派工、不验收来源、不改自动级别，也不直接推进真实目标。RPC 窄权限来自单一注册表，Prompt 不是权限门或 OS 沙箱。来源验收仍独立，默认保留已交付 child；全部关联来源安全验收后，辅助资源才按原安全门收口，部分失败留诊断与续办入口。

## 限制与验证

本实现没有 runtime 动态扩批、阻塞子集拆分、自动语义正确性证明、细粒度模型预算或独立贡献撤销；不承诺固定加速。每个非空操作都会调用 Agent，可能增加无冲突场景的成本。旧两两对象路径仍要求相应 Git merge-tree 能力，不把它作为新操作的固定算法。

验证入口与责任见[验证范围](merge-convergence-rollout.md)。测试使用临时项目、真实 RPC／Git、受控 Provider 和 bridge，不证明真实模型质量、浏览器视觉或生产吞吐。顶层开发指令对最终代码树负责跨模块集成和完整 bun run test；runtime、自动合并与 CI 不代替验证。
