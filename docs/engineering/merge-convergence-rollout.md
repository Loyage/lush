# 归并合并方案：实施、验证与收益评估

本篇将 W205／D482 的设计拆成可验证的改造步骤。**首版代码已实现，但下面保留完整目标路线；测试清单与性能门槛不是自动通过的证据。** 下文最终命令验证性能门槛为旧command协议／历史方案；当前Agent模式不强制最终验证命令，挂载、默认与未实现项见[实施接缝](merge-convergence-implementation.md)，实际文件与导出见[Runtime 地图](merge-convergence-runtime.md)。

阅读路线：[产品与理念](../design/merge-convergence.md) → [算法与架构](merge-convergence-protocol.md) → [异常与迭代](merge-convergence-cases.md) → **实施与验证（本篇）**。

## 1. 哪些要重构，哪些不用推倒

| 保留 | 替换或新增 |
|---|---|
| canonical 项目绑定、每项目一个 daemon、Host 转发边界 | 父队列从逐源串行修复改为隔离归并调度 |
| 源 Worker 身份、父子关系、独立 worktree、消息与会话 | 批次/节点/成员技术记录、唯一领取与 generation |
| 来源交付授权、child 锁定、最高自动级别不继承 | `integration` 辅助 Worker 的内部创建、窄授权与产物交付 |
| 未知副作用不重放、精确 Git 收据与 CAS | 多源归并映射与单批发布收据 |
| Git 写串行、真实父 invocation/清洁度/冻结安全门 | 允许有界并行的固定对象计算与隔离验证边界 |
| 原始分支谱系不可变、代码沿真实直接父目标交付 | 中间 scratch 不属于源分支谱系、不改 source/parent refs |
| 源 Worker 安全验收、保留 child 供追加需求 | 对共享批次证据、辅助身份和资源引用的检查 |

现有禁止创建 merge Worker 的规则防止重挂源 Worker 与无谓调用父 Agent；新 `integration` 仅用于隔离产物修复，必须明文修订授权/提示词，不能利用旧 `task_kind='merge'` 冒充兼容实现。方案文档不授权当前 Agent 创建这种 Worker。

源修复保留父执行位、落地树必须等于单源树、v2 的入队/状态假设都需替换。不能只在 `driveTaskMerge` 前插入一个配对函数，其余原封不动。

## 2. 模块职责与并行分区（拟议）

纯规划、持久领取、隔离对象计算、整合调用、真实发布、生命周期兼容及用户读面须分离；当前职责从[Runtime 地图](merge-convergence-runtime.md)定位，精确导出查源码，不维护拟议文件名／临时派工表。

RPC 不开放“把 A 合入 B”的任意 ref 操作，也不开放 Agent 手工领取批次、推进父分支或修改归并资源所有者。只读接口返回有界成员摘要、完整计数与明确分页，不含 Prompt/env/凭证或任意 stderr；查询不能启动 Agent、daemon 或推动队列。

## 3. 兼容与上线顺序

1. **测量现状。** 加分阶段时间/次数与慢原因，区分源修复等待、真实冲突、无文本分歧、测试、Git 写门及资源瓶颈，建立当前队列基准。
2. **影子规划。** 只计算候选配对与成员映射，不写源/父，不发模型调用；与真实结果对照增量、归属、依赖和统计。此阶段仍走现有 v2。
3. **先隔离发布，再归并树。** 实现单成员新协议的归一化、多轮来源映射、最终验证与精确发布恢复；再接有界双项与多项树，先验证无模型路径。
4. **加入整合与异常。** 实现新辅助 Worker 的授权、冲突/语义适配、待决拆分、撤回、输入暂存、资源与模型预算。协议正确性优先于吞吐。
5. **打通现有语义。** 同步、迭代、child 聚合唤醒、Hook、自动验收、删除保护与 Web 读面联合回归，不能只验证 main 文件内容。
6. **受控启用。** 运行时先核验 Git 能力、测试环境与旧在途请求；版本切换只影响之后真实安全点新固定的交付。现有 requested/resolving/blocked 继续原协议收口，不中途迁移。
7. **统一入口。** 数据证明收益与安全后，新合并默认走一个新管线；用户不长期维护两套按钮。代码部署与 daemon/Host 重启由用户在安全空闲点完成，不由设计 Worker 操纵。

每父目标只有一个真实发布门，新旧协议不能各拿一个锁。影子与灰度开关是内部开发/部署机制，不扩展 Agent 操作自动级别的权限，也不增加设备级跨项目调度。

兼容期旧成功交付仍按旧收据读取。新协议可用显式 version 3，读取器认识 v1/v2/v3；不把多源收据塞进 v2 再期待旧程序识别。降级应拒绝含未识别在途新请求的状态库，不静默忽略它们；已有提交不撤销，未知现场不能自动回退旧队列重放。

Git 能力检测必须实际覆盖固定 merge-base、多基点、改名与对象生成；不满足时停用新管线并提示部署要求，未启动的新交付可走明确支持的兼容路径。已经进入新协议的组合不能失败后静默转旧路径。

## 4. 专项与跨模块测试清单

- **纯规划**：0/1/3/8/大量成员、稳定左右与拓扑、形成窗口、容量、依赖、阻塞跳过、无饥饿机会、重复领取、成员拆分；不把 Worker 编号当排序键。当前新式 child 没有公共依赖边写入口，历史 code 依赖单独覆盖。
- **真实 Git 对象**：共享/不同 fork、多 merge-base、Squash 后第二轮、父同步、改名/删除、二进制、重复增量、相互抵消、没有冲突但测试失败、归并拓扑改变；源/父 refs 始终不被准备阶段修改。
- **真实发布与注入故障**：固定成员、CAS 失败、外部 ref 漂移、dirty、取消各时点、index 半写、Git 成功 DB 未写、DB 成功 ACK 丢失，恢复不漏成员/重复发布。
- **并发与恢复**：1 槽和多槽、节点与来源复用、父普通输入、公平晋级、不断输入、不同父目标、旧协议共存、daemon 中断、旧消息/尝试被拒绝、辅助 token 到期。
- **生命周期**：父/子/孙收敛、多轮来源映射、冻结暂存、撤回后消息恰好投递、依赖不能越级、单批只触发一次父收到合并 Hook、命令未知不重放。
- **验收/资源/权限**：独立指令不连带验收、child 默认保留、脏现场/消息阻塞、辅助资源共享引用、批次删除保护、部分回收与显式恢复、Agent/用户能力隔离、私有字段不能出读 API。
- **UI/协议**：旧服务缺字段、不假造摘要、异常可见、迟到 ACK/失败保留输入、只读不调度、辅助 Worker 可查、Agent 紫色/帮助、键盘/触摸与窄屏。

测试用临时项目、可控 provider/进程与隔离设备根，不使用用户运行中的队列，不调用真实模型。整合模型业务质量与实际浏览器另外验收，mock 成功不能冒充真实语义解决能力。

专项／集成与最终全量责任统一遵循[分层测试与交付](../contributing/README.md#分层测试与交付)，不以自动合并或 CI 代替。

## 5. 怎么证明真的更快

在同一代码/测试环境与相同成果集上，对比当前逐源队列、仅自动无冲突合成、完整归并树。分别测无冲突、真实冲突、语义不兼容、混合待决与持续流入；采用 1/4/8/16/32 项，多次完整运行并报告分布，不能只比较最好的一次。

核心指标：

- 成果固定到真实发布的 p50/p95、最久等待与成功发布数量/分钟；准备就绪不计入吞吐。
- 父写执行位占用时间、无文本冲突产生的模型调用数、冲突关键路径和最终全量测试次数。
- 积压增长斜率、较早请求获得晋级机会、待决期间无依赖成果能否继续；总 CPU/内存/磁盘、测试与 Agent token/费用。
- 基线失效重建次数、节点/证据复用率、批次大小与被取消/拆分比例、各类错误及恢复结果。

发布安全硬门槛：零丢失成员、零重复发布、零未授权 ref 写入、未知现场不重放、最终树验证证据完整。功能门槛：一个组合待决时，无依赖组合能交付；源分支未污染；冻结输入不丢；单项也能交付。

初步性能评估目标是相同无冲突负载下 p95 等待明显下降、模型调用显著少于逐源修复、单项无明显退化、资源不随积压无界增长。**不预先承诺倍数或数值 SLA**；若只靠增大批次隐藏等待，或最终验证成为新瓶颈，应缩小窗口/容量、调整资源预算，不能降低安全校验换数据。

## 6. 本方案的明确限制

归并不能发现全部隐式需求依赖；不能让 Git 合并变成可交换/可结合操作；不能消除每目标最终验证与发布的串行边界；不能保证单 Worker 独立回退；不能抵挡外部持续修改；不能超出模型、测试与硬件容量。

因此优先实现“隔离自动合成＋精确发布”，用测量确认减少无谓串行修复的收益，再投入完整动态归并树。用户得到的是同一个简洁交付体验，不必承担内部算法的配置负担。准备资源饱和时只暂停新组合领取，交付意图仍持久排队并显示资源原因；摘要和调度使用索引、分页与事件增量，不每次扫描全部历史或把全部积压建成 worktree。

## 7. 历史方案验证（非首版运行证据）

历史概念验证和测试结果见 Worker／Git 记录，不是当前树证据。现行组合入口为 `test/web/branch-convergence-integration.test.js`，用真实 HTTP／RPC／SQLite／Git 与受控上游验证；mock 不证明实际模型语义质量、浏览器视觉或生产吞吐，不能承诺加速倍数。
