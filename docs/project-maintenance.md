# 全部中断、重启与全部继续

本文说明当前项目的维护暂停及父子 Worker 恢复规则。它与“放弃 Worker”、关闭页面和服务重启是不同动作；精确接口见[维护暂停契约](engineering/project-maintenance.md)。

## 一键安全重启

在全局工作台「全局总览」的「快捷操作」卡中点击「一键安全重启」，先保存未发送输入，再确认列出的在线项目范围。页面会自动中断、等待安全退出、逐个重启全部项目后台、继续本次暂停的项目，最后重启界面服务；可能需要重新登录，但不需再点「全部继续」。继续可能调用 Agent 并消耗 token。一键流程不生成内置「项目中断完成」告知，仍显示进度和失败结果；Worker 告知与用户自装 Hook 不受影响，手动「全部中断」保留完成提醒。

快捷操作卡默认显示；进入总览「编辑模式」后可移动、缩放、移除，也可从「添加卡片」加回。修改先进入草稿，支持撤销／重做，点击整页「保存更改」才共享到同设备浏览器，「取消编辑」丢弃草稿。编辑时不能开始维护操作或修改自动选择策略。进度／异常摘要可从卡片「详情」查看完整结果；缩放和信息刷新不切断在途流程，移除卡片会停止后续步骤，已经发出的请求仍可能生效。

卡片设置还可逐项勾选按钮，默认显示「一键安全重启」和「全局自动选择」，可另选「全部中断」「全部继续」「全部重启」，也可全不选。选择按钮只改变展示，不执行维护或修改设备策略。小卡片未容纳的已选按钮仍可在「详情」中原地执行。自动选择显示已确认开启／关闭或未知；开启须确认设备级持续授权并可能产生 Agent 费用，关闭不撤回已有答案或调用。卡片、全局自动化页与顶部提示共用一份策略；保存未确认时须先重新读取，不能重复提交。

原来已经处于项目级维护暂停的项目重启后仍保持暂停。离线和未登记项目不会启动；后来上线的项目不加入。等待最多 15 分钟，不强杀工具；任何失败、不可达、批次变化、超时或结果未知都会停止流程，保留已完成的动作和暂停现场，按页面报告用手动入口核对处理，不自动重试或恢复。保持此页打开；离页、关闭或刷新不会自动接着执行。精确边界见[一键安全重启契约](engineering/project-maintenance.md#一键安全重启w249d579)。

## 手动维护步骤

需要单独中断、切换模型或处理失败现场时，可展开全局工作台「项目管理」底部服务重启区域的「手动维护」，使用原三个批量操作；项目概览的中断／继续和项目行的独立重启仍保留。

1. 在当前项目的「项目概览」中点击「全部中断」并确认；也可在全局工作台「项目管理」底部的服务重启区域点击「全部中断」，确认此 Host 已登记在线项目的固定范围后统一提交。它持久关闭本项目的新 Agent 调用准入，向正在运行的 Agent 请求安全暂停；子 Worker、管理 Agent 和分歧修复也受准入门控制。
2. 等待各项目「项目概览」中的维护状态显示可重启；全局「全部中断」会观察本次固定范围的批次并在全部完成、当前空闲时提醒，也可查看来源项目的完成告知。单 Worker 的“中断完成信号”只证明自身安全停住，不能代替全局就绪。请求成功不等于调用已经退出：当前工具必须安全收尾，没有可验证安全点的后端需要等本次调用自然返回，已经开始的 Git／后台操作也需要结束。中断不会因等待过久强杀工具；调用自身的超时与显式放弃仍有效。
3. 打开全局工作台「项目管理」，在对应项目行点击「重启项目后台」，只重启该项目。底部还提供独立「重启界面服务」，「手动维护」中提供「全部重启」；后者会列出此 Host 已登记的所有在线项目，逐个安全重启，全部成功再重启界面。任一后台仍忙或失败就停止后续步骤，不回退到强制停止、不启动离线项目。就地报告已完成及未确认／未执行范围，不自动重试；界面重启前保存未发送输入，之后可能需要重新登录。
4. 后台重启后仍保持维护暂停；准备好后回到「项目概览」，显式点击「全部继续」，或在全局「项目管理」服务重启区域点击「全部继续」并确认在线项目范围。它允许本次暂停影响的调用及待执行工作重新通过调度门，可能启动 Agent 并消耗 token；请求成功不等于所有 Worker 立即运行。

全局中断／继续不包含界面服务、不启动离线或未登记项目；逐项提交，失败停止后续并显示已接受、未确认和未执行范围，不自动重试或撤销。请求接受不等于调用已经退出或立刻运行。手动模式下，中断、重启、继续需分别显式操作。

手动中断／继续不会替用户自动重启后台或界面，关闭页面也不会停止项目。界面不可达时不能根据旧页面状态断言后台已经静息。旧后台缺少维护接口时入口不可用；需在安全空闲点更新 daemon 和 Host，不能用失败的维护请求冒充暂停成功。

全局完成提醒只在页面仍打开时观察；离页、超出观察时限、来源不可达、批次撤销或结果未知均不承诺已经全部完成，需显式刷新核对。来源 info Notice 仍保留，重启按钮会再次检查安全门。新完成节点首版仅允许纯告知，维护期间不会因 Hook 启动 Agent 或快捷指令，详见[中断完成契约](engineering/interrupt-completion.md)。

## 有子 Worker 时

维护暂停覆盖项目的新调用，不把整棵树都改成同一个 Worker 状态。

- 父 Worker 原本等待子 Worker 时，继续保持等待；子级恢复并交付后，仍按既有通知与合并规则唤醒父级。多级后代同样遵循各自真实父子关系，不重复派工。
- 父 Worker 自己正在执行的开发工作被安全中断时，也可以恢复；不要求所有后代先完成才允许父级处理自己的工作、新用户消息或失败通知。
- 子 Worker 的待决问题、冻结交付、同步、代码依赖和实际退出等安全屏障仍有效。「全部继续」不会替用户回答问题、解除冻结、重试失败或验收成果。
- 原先单独暂停、待开始、失败、取消、已验收及待验收的 Worker 不因此批量启动。运行设置、消息、提交、工作区和会话保留。
- 暂停期间可保存新指令和追加消息，但新调用等维护解除后才能准入。个人暂停与维护门是两件事，单个 Worker 的「继续」不能越过项目维护门。

## 限制

维护暂停不是操作系统级进程暂停，也不是崩溃恢复授权。硬停止、调用超时或真正崩溃仍可能留下未知副作用；失败现场需要检查后显式重试，不能用「全部继续」自动重放。可重启只是当前观测，后台在真正停止前还会同步重检实际调用与后台操作。
