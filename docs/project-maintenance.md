# 全部中断、重启与全部继续

本文说明当前项目的维护暂停及父子 Worker 恢复规则。它与“放弃 Worker”、关闭页面和服务重启是不同动作；精确接口见[维护暂停契约](engineering/project-maintenance.md)。

## 维护步骤

1. 在当前项目的「项目概览」中点击「全部中断」并确认。它持久关闭本项目的新 Agent 调用准入，向正在运行的 Agent 请求安全暂停；子 Worker、管理 Agent 和分歧修复也受准入门控制。
2. 等待就地状态显示可重启。请求成功不等于调用已经退出：当前工具必须安全收尾，没有可验证安全点的后端需要等本次调用自然返回，已经开始的 Git／后台操作也需要结束。中断不会因等待过久强杀工具；调用自身的超时与显式放弃仍有效。
3. 打开全局工作台「后台总览」，在对应项目行点击「重启项目后台」，只重启该项目。页面旁边还提供独立「重启界面服务」和「全部重启」；后者会列出此 Host 已登记的所有在线项目，逐个安全重启，全部成功再重启界面。任一后台仍忙或失败就停止后续步骤，不回退到强制停止、不启动离线项目。就地报告已完成及未确认／未执行范围，不自动重试；界面重启前保存未发送输入，之后可能需要重新登录。
4. 后台重启后仍保持维护暂停；准备好后回到「项目概览」，显式点击「全部继续」。它允许本次暂停影响的调用及待执行工作重新通过调度门，可能启动 Agent 并消耗 token；请求成功不等于所有 Worker 立即运行。

按钮不会替用户自动重启后台或界面，关闭页面也不会停止项目。界面不可达时不能根据旧页面状态断言后台已经静息。旧后台缺少维护接口时入口不可用；需在安全空闲点更新 daemon 和 Host，不能用失败的维护请求冒充暂停成功。

## 有子 Worker 时

维护暂停覆盖项目的新调用，不把整棵树都改成同一个 Worker 状态。

- 父 Worker 原本等待子 Worker 时，继续保持等待；子级恢复并交付后，仍按既有通知与合并规则唤醒父级。多级后代同样遵循各自真实父子关系，不重复派工。
- 父 Worker 自己正在执行的开发工作被安全中断时，也可以恢复；不要求所有后代先完成才允许父级处理自己的工作、新用户消息或失败通知。
- 子 Worker 的待决问题、冻结交付、同步、代码依赖和并发上限仍有效。「全部继续」不会替用户回答问题、解除冻结、重试失败或验收成果。
- 原先单独暂停、待开始、失败、取消、已验收及待验收的 Worker 不因此批量启动。运行设置、消息、提交、工作区和会话保留。
- 暂停期间可保存新指令和追加消息，但新调用等维护解除后才能准入。个人暂停与维护门是两件事，单个 Worker 的「继续」不能越过项目维护门。

## 限制

维护暂停不是操作系统级进程暂停，也不是崩溃恢复授权。硬停止、调用超时或真正崩溃仍可能留下未知副作用；失败现场需要检查后显式重试，不能用「全部继续」自动重放。可重启只是当前观测，后台在真正停止前还会同步重检实际调用与后台操作。
