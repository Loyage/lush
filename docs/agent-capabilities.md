# Agent 能力开关与 Skills

在全局工作台打开 **设置 → 系统 → Agent 能力**，选择希望 Agent 主动使用的 Lush 功能。设置属于运行机器的同一系统用户，所有项目共用；没有项目在线时也可编辑，不会为此启动后台。

## 四项内置能力

| 开关 | 用途 | 指南 ID |
|---|---|---|
| 进度汇报 | 工作前列里程碑，完成后更新实际进度 | `progress` |
| 子 Worker 委派 | 拆分独立工作、创建 child 并按非阻塞协议协调 | `delegation` |
| 自动标题 | 当前 Agent 理解目标后生成自身一次性标题 | `auto-title` |
| 上下文检索 | 按需查看 Worker 摘要、历史与执行记录 | `context` |

默认开启。既有进度开关继续使用原值，不因升级重新开启。自动标题只适用于开发指令及 child，用户手动标题优先；只读分析不提供委派和自动标题。管理、管家及隔离解释角色不加载开发能力。

## 开关何时生效

保存后，**后续 Agent invocation** 读取新状态；当前调用不热切换。关闭的能力不再注入对应 Skill，Agent 收到不主动使用的指引。旧会话、自定义 Prompt、用户资源和已有记录不自动修改。

关闭不是权限隔离，也不会取消已有子 Worker、停止实际调度或阻止它们正常收尾。既有后代的成果检查、必要消息、合并修复及交付仍遵循必需核心协议。安全、权限、Git/worktree、等待与最低测试责任不能用这些开关关闭。

进度沿用原显示行为：关闭后进度及规划历史暂时隐藏，记录不删除，再开启可继续查看。关闭自动标题不会清除已生成标题；关闭上下文检索也不会隐藏用户可读历史。

## 薄 Skill 与详细指南

参考 Orca 的结构，Agent 启动时只得到已开启能力的简短入口与使用时机，详细流程按需读取，避免将整篇指南常驻上下文。进度和自动标题的每轮触发要求仍由短入口明确提示，不完全依赖模型自行发现 Skill。

内置指南随 Lush 代码发布，不需要安装第三方包：

```bash
bun run lushc skills list
bun run lushc skills get delegation
bun run lushc skills get progress --json
```

这些命令只读取当前 CLI 内置指南，无需 daemon 在线或选择项目，不读取账号、设备私密配置或实际开启状态，不调用 Agent。Agent 使用 runtime 在 PATH 固定的 `lushc`，指南与运行代码同版本。未知 ID 或文件路径被拒绝，不执行指南中的内容。

Pi 的 Lush 配置与 Pi 默认模式都获得已启用的内置 Skills；不会修改用户 Pi 的设置文件。Codex 使用同一短入口及 CLI 指南，不把 Pi 扩展当作 Codex 工具。

## 与第三方插件的区别

本页只控制 Lush 自带的工作能力。第三方扩展与 Skills 仍在 Agent 配置中显式选择，通过安装库管理，安装和启用分开；不会被本页自动安装、更新、删除或改写。第三方代码和 Skills 指令需要信任，独立配置不是操作系统沙箱。

开发接口与扩展新模块的边界见[工程契约](engineering/agent-capabilities.md)，取舍见[设计理念](design/agent-capabilities.md)。升级后应在安全空闲时更新项目 daemon 和 Host，两端都更新才会同时获得新注入机制和设置界面；设置保存本身不要求重启。
