# 改进待办

这里保存基于源码审查与测试得到的改进清单，供后续开发规划使用。条目描述待解决的问题与建议，不代表已经实现，也不替代现行架构和接口文档。

## 审查基线

本轮审查基于含未提交改动的工作区，Bun 为 1.4.2。结果不是对某个纯提交版本的认证，实施前应重新核对现状。

- `bun run test`：456 个测试，448 通过、8 失败，覆盖 93 个测试文件。
- `bun run docs:check`：通过，当时检查 46 个 Markdown 文件。
- `bun run doctor`：`code_match: false`，运行中的 daemon 与磁盘源码指纹不同。
- Candidate 的两项一致性问题在临时 Git 仓库中通过受控执行顺序复现；没有修改用户项目的分支或业务状态。
- 本目录只记录分析，不包含功能修复。优先级表示建议实施顺序，不表示已经批准产品或架构变更。

## 推荐顺序

| 优先级 | 待办 | 依据 |
|---|---|---|
| P0 | [Candidate 接受时固定被审阅提交](candidate-acceptance.md) | 隔离复现：实际落地提交与候选提交不同 |
| P0 | [防止迟到验收覆盖用户决定](candidate-state.md) | 隔离复现：rejected 被改回 ready |
| P1 | [恢复可靠测试基线与持续集成](testing.md) | 全量失败、部分单文件通过 |
| P1 | [结构化验收证据](verification-evidence.md) | 当前结果字段和候选状态判定的源码审查 |
| P2 | [控制快照与日志读取成本](read-performance.md) | 全量轮询与同步整文件读取的源码审查，尚无压力测试 |
| P2 | [集中状态转换与明确模块契约](architecture-contracts.md) | 维护性建议，需渐进实施 |
| P2 | [统一用户流程、文档与版本诊断](product-and-docs.md) | 文档口径冲突与运行版本不一致 |

先补复现测试再修一致性问题，同时恢复全量测试。后续优先改进验收证据，再处理性能和使用体验；不建议以大规模架构重写作为前置条件。

## 维护方式

- 修复后记录回归测试、验证命令与剩余限制，不能仅凭代码改动勾选完成。
- 区分已复现行为、源码推断和设计建议，不把建议写成现行规则。
- 涉及架构、产品行为、公共接口或数据模型的选择，应在实施前确认。
- 文件移动或接口变化继续遵循[模块地图](../engineering/modules.md)，文档修改遵循[文档约定](../contributing/documentation.md)。
