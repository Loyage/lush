# 多项目工作台改造规划

本文保留多项目工作台的原始规划与实施记录，区分已经确认并实现的范围与后续方案。目标是让一个全局 Web／桌面工作台同时打开多个项目，各项目继续独立运行开发；不把 Lush 改成跨项目调度器。现行行为以[模块地图](../../engineering/modules.md)及[三层边界](../../engineering/host-boundary.md)为准。

## 当前复核（2026-10-02）

相对 `81257d12e3001214e7f03bc4ee2398f834e35ee3`，第 0～2 阶段的核心身份隔离仍有效，无需重复实施或重新询问已确认的四项产品选择。`test/web/multi-project.test.js`、`project-route.test.js`、`launcher.test.js` 与桌面回归在本轮定向套件 **61 pass / 0 fail**（完整命令与日志见[安全复核](../03-security-boundaries.md#当前复核2026-10-02)）。

- 当前公开入口已从 `/api/launcher/*` 改为 `/api/host/*`，连接管理位于 `src/host/project-host.js`，注册表位于 `src/host/registry.js`；原入口已移除，不是兼容别名。
- 项目列表现会只读探测已登记目录的现存 socket（不启动未打开项目），不只读已连接项目；单个摘要 4 秒超时、失败 60 秒退避。尚无全局连接数／总摘要并发预算，不能把第 3 阶段所有性能目标标为完成。
- 项目相关偏好、异步读面与通知的精细边界仍由各自模块负责，不能因 URL 隔离就宣称全部前端缓存／问卷草稿或重复通知均已验收。真实双浏览器标签、真实 Electron 及外部 HTTPS 代理没有在本轮验收。
- 后续跨项目总待办、统一决策动作和资源预算仍是独立方案，不影响已完成的 S-01 身份隔离；本轮不扩大公共 API、代理信任或本地／公网路径边界。

## 实施状态（2026-09-26）

本规划已按用户确认的默认选项实施；S-01 的修复与验证证据见[安全边界 S-01](../03-security-boundaries.md#s-01--全局项目切换会把旧页面操作送到另一个项目)。已完成的范围：

- **项目身份路由**：全局工作台每项目一条稳定 `/p/<project-id>/` 路由；ID 由 canonical 路径派生，服务端只在已登记集合里反查。无前缀项目读写、未知／已移除身份都被拒绝，不再有可被别的标签页切换的「当前项目」。
- **宿主模型**：`createProjectHost` 用按 canonical 路径索引的连接集合 + single-flight；项目注册表（`launcher.json` v2）只存路径与上次打开，读 v1 时把 `last_project` 提升为登记项。历史 `/api/launcher/projects` 只对已连接项目读一次有界 `system.summary`（现行接口与探测范围见上面的当前复核）。
- **前端隔离**：`route.js` 从页面地址取项目，`api.js` 加前缀；折叠 / 筛选 / 排序与分支图折叠按项目隔离；左栏项目列表与切换用新标签打开，不丢当前标签输入。
- **产品语义**：打开项目 = 登记并按需启动 / 连接 daemon；从列表移除只删入口并断开 Web 连接，不停止 daemon；桌面窗口与标签各自独立保持项目，`last_project` 只决定新窗口首次落点；本地仍可选任意现存绝对目录，公网仍只认 `web.json.projects` canonical 白名单。

仍属后续方案：跨项目总待办 / 统一决策动作；本节不改变「不新增跨项目 Worker、全局事实库、全局调度」的边界。

## 想解决什么

改造前，不同项目可以各自运行 daemon，但全局 Web 的 `createProjectHost()` 只保存一份可变 `binding`；切换项目会影响同一 Web 进程下的所有标签页（历史问题，当前已修复）。旧页面随后发出的无项目身份请求甚至可能落到新项目的同号 Worker 上（见既有候选 [S-01](../03-security-boundaries.md#s-01--全局项目切换会把旧页面操作送到另一个项目)）。这次改造的最低安全目标是：**任何读写操作都明确归属于发起页面所打开的项目，不能由别的页面切换目标**。

参考 Codex 的“项目组织并行工作线程”模式：项目是导航与上下文边界，项目内部仍由 Lush 的 Worker、分支和 worktree 承载并行开发。参考：[Codex app 介绍](https://openai.com/index/introducing-the-codex-app/)；不照搬其数据模型或云服务。

## 不在本次范围

- 不新增跨项目 Worker、全局 SQLite 事实库、全局调度／并发配额或自动跨项目派工。
- 不修改项目目录绑定、Git 合并审批、agent token 与 invocation 生命周期；不将切换项目解释为停止 daemon。
- 不默认启动、停止、重启或迁移用户已有项目；实现和验证只用临时项目与 mock／可控子进程。
