# 多项目工作台改造规划

本文是供讨论的改动规划，**不是已批准的实现规范或已完成功能**。目标是让一个全局 Web／桌面工作台同时打开多个项目，各项目继续独立运行开发；不把 Lush 改成跨项目调度器。现行行为以[模块地图](../../engineering/modules.md)及[项目身份与恢复](../../engineering/identity-and-recovery.md)为准。

## 想解决什么

当前不同项目可以各自运行 daemon，但全局 Web 的 `createProjectHost()` 只保存一份可变 `binding`；切换项目会影响同一 Web 进程下的所有标签页。旧页面随后发出的无项目身份请求甚至可能落到新项目的同号 Task 上（见既有候选 [S-01](../03-security-boundaries.md#s-01--全局项目切换会把旧页面操作送到另一个项目)）。这次改造的最低安全目标是：**任何读写操作都明确归属于发起页面所打开的项目，不能由别的页面切换目标**。

参考 Codex 的“项目组织并行工作线程”模式：项目是导航与上下文边界，项目内部仍由 Lush 的 Task、分支和 worktree 承载并行开发。参考：[Codex app 介绍](https://openai.com/index/introducing-the-codex-app/)；不照搬其数据模型或云服务。

## 不在本次范围

- 不新增跨项目 Task、全局 SQLite 事实库、全局调度／并发配额或自动跨项目派工。
- 不修改项目目录绑定、Git 合并审批、agent token 与 invocation 生命周期；不将切换项目解释为停止 daemon。
- 不默认启动、停止、重启或迁移用户已有项目；实现和验证只用临时项目与 mock／可控子进程。
