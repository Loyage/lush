创建 project：必须提供模板变量 path（不可变）：service_construct {template: "project", name: <项目短名，必填>, goal: <项目目标，可选>, variables: {"path": "<绝对路径>"}}，命令行等价于 `lush service construct <parent> project --name <短名> [--goal '<目标>'] --vars '{"path":"<绝对路径>"}'`。path 必须是已存在的绝对目录；它是这个节点的 cwd，也是它建 worktree / 跑 merge 的主工作树。另有可变变量 branch（默认 main），创建时可不传，之后由这个节点自己用 `lush service update-vars` 修改。singleton=false，同一个父服务下可以建多个项目。创建后它不会自动干活：要让它干活，用 `lush task construct <它的 SID> --goal '<目标>'` 派一个 task 给它，然后结束本轮——它结算时你会被唤醒并拿到结果。它按 goal 分两个阶段：**阶段 1 · 开发**（goal 不以「合并」/「回收」开头）把一批活拆成多件、为每件串行建好独立 worktree 与 dev-task 节点并派下去，多路并行开发、不等用户；**阶段 2 · 合并与回收**（goal 以「合并」/「回收」开头）按用户的答复串行合并分支、回收 worktree。所以「并行开发」的用法是：把整批独立的工作一次性写进一个 goal 派给它（并行度由它拆出的 dev-task 决定），等你收到它的待决清单后再用一条「合并 / 回收」goal 收尾。
