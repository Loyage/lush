创建 dev-task：调用 service_construct，参数 template="dev-task"、name=<任务短名，必填>、goal=<目标，可选>、variables={"title": <一句话摘要，必填>, "detail": <详情正文，可选>}；命令行等价于 `lush service construct <parent> dev-task --name <短名> --goal '<目标>' --title '<一句话摘要>' [--detail '<正文>']`。三个字段的规矩：name 是不可留空的英文标识符 ^[A-Za-z][A-Za-z0-9_-]*$、不超过 64 字符、不含空格——它同时就是这个服务的服务名，用来命名相关的 worktree / 分支；title 是不可留空的单行摘要（≤200）；detail 是详情正文（可多行、可空、≤20000）。格式不合规、缺少 name 或 title 时创建直接失败（-32602）。dev-task 只允许创建一个子模板：worktree-service。默认规矩：除非 goal 或 detail 里明确说明例外（「不要开新 worktree」「就在当前分支 / 主工作树上改」「复用 <某个已有 worktree>」），它一律为这件工作新建一个独立的 git worktree，并把实际改动派给 worktree-service 在新 worktree 里用 agent 做；要它照别的方式做，就在这两处写明。创建后它不会自动干活：用 `lush task construct <它的 SID> --goal '<要改什么、怎么算完成>'` 派 task 给它。它管两个阶段：开发 task（新建 worktree 并把改动派给 worktree-service）与回收 task（goal 以「回收」开头：核对 worktree-service 的 state → 自检 → `lush service stop` 那个节点 → 删除 worktree 与分支）；用户同意回收时在同一个节点上再开一个回收 task 即可，不要自己删 worktree。
